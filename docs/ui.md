# 界面规范

依据 DEC-039：窗口由**图标栏、上下文侧栏、页面**组成，类似桌面聊天与素材库应用；视觉参考 Cindy 设计系统的细分隔线与 Inter 字体，底色是白色内容区加通透的中性浅灰侧栏（DEC-046 ③），强调色是一种清新的蓝（可预览绿色）。只借鉴布局、字体和配色方法，不复制任何站点或应用的标识、图标与品牌色。需求见[需求](requirements.md)，实现约束见[技术设计](design/architecture.md#frontend)。

## 1. 窗口布局（DEC-039）

| 宽度 | 图标栏 | 上下文侧栏 | 页面 |
| --- | --- | --- | --- |
| ≥ 1280 | 52px | 272px（有侧栏的页面） | 其余宽度 |
| 1000～1279 | 52px | 240px | 其余宽度 |
| 720～999 | 52px | 不显示（设置除外，只显示图标的 72px） | 其余宽度 |

- **沉浸式标题栏**（DEC-046 ④）：窗口不画系统标题栏，图标栏、侧栏和页面都延伸到窗口顶部；系统的最小化、最大化、关闭按钮保留在右上角，盖在页面上。页面顶部栏右侧给这些按钮让位（按 MyGo `TitleBar()` 的宽度），图标栏和侧栏顶部一条与按钮同高的区域、以及页面顶部栏的空白处都可以拖动窗口，双击最大化。看图层与播放层的面板上边距不小于按钮高度加 8px；全屏时没有这些让位。
- **图标栏**（最左，浅灰底 `#f7f7f7`）：只放图标，名称在悬停提示与无障碍名称里，见[第 2 节](#nav)。
- **上下文侧栏**（`#f7f7f7` 底，细分隔线）：当前页面里“看什么”的选择，像素材库的文件夹或聊天应用的会话列表。顶部是页面名（18px，600），下面是条目（图标或头像 + 名称，选中项浅强调色底、强调色文字），分组标题用 12px 灰字：
  - **主页**：“全部动态”、站点筛选，然后直接是订阅列表（DEC-053 ②，不加分节标题、不写状态文字）：正在直播的在最前（头像橙色直播圈），然后未读（头像右下角蓝色圆点），再是已读；点一行只看这个订阅的时间线，选中项高亮（[§3.1](#home)）。
  - **订阅**：“全部订阅”（头像网格）、“全部账号”（按站点列出全部订阅的账号，DEC-057 ⑥）和全部订阅的列表（虚拟滚动，直播中的头像带橙色圆环），点一项打开订阅详情。
  - **媒体库**（含媒体库本机详情 `/library/item`）：类型（全部 / 视频 / 图片 / 直播录像 / 转发；“图片”“视频”只列作者自己的内容，转发的动态与它带的图片、视频在“转发”里，DEC-056）；“来源”（全部来源、各订阅、不属于订阅的 UP 主）；底部一行“N 项 · 占用大小”。
  - **解析页、视频页与用户页**：“最近解析”，在解析过的对象之间切换，当前对象高亮（DEC-049 ②）。
  - **我的**：按站点折叠的四组功能（哔哩哔哩、抖音、微博、X），默认折叠，见[第 3.11 节](#mine)。
  - **任务**：“下载任务（N）”、“缓存队列（N）”（N 为未结束的队列数，DEC-057 ②）、“直播录制（N）”、“录制异常（N）”（N 为最近 7 天有异常的录制场数，为 0 时不带数字；DEC-050 ②、DEC-051 ③）、“检查计划”（DEC-059 ①）、“导入导出（N）”（N 为进行中与等待确认的导入导出数，为 0 时不带数字，DEC-062），见[第 3.6 节](#library)。
  - **设置**：设置分类（含“更新”与“关于”等），见[第 3.7 节](#settings)。
  - 登录页没有上下文侧栏。
- **页面**：白底。顶部栏（不随内容滚动）左边是返回箭头（需要时）与页面标题（18px，600），右边是该页的操作（不放快速解析框，链接与 UID 统一在解析页解析，DEC-069）。帖子、视频与用户详情及媒体库本机详情限宽 680px 居中；解析页主面板全宽居中承载一个最宽约 640px 的大输入框；媒体库网格、任务列表、订阅头像网格用满宽度；设置限宽 860px。
- **图标栏与上下文侧栏固定**：只有页面随内容滚动（NFR-UI-001）。窄窗（< 1000）没有侧栏时，主页的订阅列表退回为时间线上方的横向头像条（“全部动态”在最前），媒体库的类型与来源退回为页面里的标签与“作者筛选”，解析页的“最近解析”退回到大输入框下方，任务页的侧栏退回为页面顶部的分段选择。
- 不再有右栏：链接与 UID 解析集中在图标栏“解析”页（DEC-069）；排队与进行中的下载任务数量在图标栏“任务”的角标（DEC-049 ①）；正在直播的订阅排在主页侧栏订阅列表的最前。
- **更新提示**（FR-UPD-003）：正式版有更新时，任何页面的顶部栏下方出现一行浅蓝底的提示，不打断当前操作：“新版本 0.1.2 已就绪 · 更新内容 · 重启以更新”（自动下载关着时是“有新版本 0.1.2 · 更新内容 · 下载并安装”），右端一个关闭按钮（这次运行不再出现）。点“更新内容”在这一行下方展开这一版的说明（`CHANGELOG.md` 的那一节，按行显示），再点“收起更新内容”。点“重启以更新”：没有缓存与录制时直接重启；有时先弹确认框“重启以更新”，正文“重启会暂停 N 个缓存任务并结束 M 场录制，重启后可以继续缓存。”，按钮“重启以更新”“取消”。更新后第一次启动显示一次“已更新到 0.1.2 · 更新内容”，可以关掉。
- **数据来自更新的版本**：启动时发现数据文件来自更新的 TRACE（例如装回了旧版本），弹一个系统对话框“这些数据来自更新的 TRACE 版本，请安装新版”，确定后退出，不打开窗口、不改动任何数据。

## 2. 图标栏

- 顶部是 TRACE 字标“T”（DEC-046 ② 起不带点），只是标志，不是按钮，也不占导航项的位置；第一个导航项紧挨标志下方（DEC-057 ③）。
- 导航项（DEC-022、DEC-026）是 40px 圆角方块里的线性图标（描边 1.6，选中 2），悬停浅灰底，选中浅强调色底、强调色图标：
  1. **主页**：已缓存内容的信息流。
  2. **订阅**：被追踪的人（[第 3.9 节](#subscriptions)）；有订阅正在直播时图标右上角一个橙色小点（不做未读数字角标，DEC-033），悬停提示写“订阅 · 有订阅正在直播”，说明这个点不是未读（2026-11-15 反馈）。
  3. **我的**：登录账号在站点上的关注、收藏、稍后再看、历史等（[第 3.11 节](#mine)，DEC-047）。
  4. **解析**：粘贴链接或 UID。
  5. **媒体库**：已缓存的图片、视频和直播录像。
  6. **任务**：下载任务、缓存队列、直播录制、录制异常、检查计划与导入导出；只有存在排队或进行中的下载任务时，右上角显示强调色小数字（只数这两种下载任务，不数直播录制，也不数缓存队列里等待中的条目，DEC-049 ①、DEC-050 ②）。
- 底部固定当前账号的小头像（悬停显示昵称和 `UID`，点击进入账号设置，未登录时进入登录页）和**设置**（齿轮图标）。
- 不显示做不了的功能入口。

## 3. 页面

通用：

- **整洁原则**（DEC-037、DEC-038）：同类条目（帖子、投稿、最近解析、媒体库条目、录像）**点本体完成常用动作，其余操作收进一个“⋯”更多菜单；每个区域最多一个主按钮**，不堆砌文字按钮。
- **“⋯”菜单是浮在按钮旁边的弹出菜单**（白底圆角、阴影，在按钮下方右对齐，没有空间时翻到上方；点外面或按 Esc 关闭，键盘可用），菜单项不占页面空间、不推开下面的内容；危险操作（删除）用红字并与其他项用分隔线隔开。不要用在页面里展开一排胶囊按钮的方式代替菜单。
- **点开即跳转**（DEC-038）：从帖子、投稿、头像、最近解析打开视频或用户页时，立刻切换到目标页面，先显示卡片上已有的标题、作者和封面，并显示“正在打开…”；读取完成后填入完整内容。失败时在该页面显示原因和“重试”。后点的覆盖先点的，已经离开的页面不会被迟到的结果拉回。
- **顶部栏**：返回箭头、页面标题与页面操作（不含快速解析框，DEC-069），不随内容滚动；页面里的标签选中项下方是一条强调色粗短线。
- **帖子**（主页信息流、订阅详情、用户页动态共用 `PostCard`，DEC-037）：左边圆形头像（点击进入用户页），右边第一行“昵称 · 发布时间 · 类型”和右上角的[状态圆点](#status-dot)（主页不画，DEC-046 ⑦）；正文（超过 6 行折叠，可展开）；图片像站点上那样尽量完整显示（DEC-040）：1 张时按原比例完整显示（竖图高 360px、宽按比例，横图最宽 480px，比例限制在 1:2 到 2.4:1 之间），2 张或 4 张排两列、其他排三列的正方形格子（最多显示 9 张，多出的在最后一格写“+N”），实况照片左上角标“实况”，图片没加载出来时是浅灰底块，不写文字；点击图片打开[看图层](#viewer)。视频是一张横向卡片：左边 200px 宽的 16:9 封面（右下角时长），右边标题（最多两行）、简介（最多两行）和清晰度规格；不显示播放数、评论数这类会变的数字，也不缓存它们；点卡片任意位置播放（已缓存时在播放层播放本机文件）；转发在白底细线圆角框里显示原动态摘要；不支持的类型显示类型名说明。
  - **在主页信息流（含单个订阅视图）与订阅详情“内容”标签中**：帖子下方**不放任何文字按钮**（不显示“内置播放”“查看图片”“补存弹幕和字幕”“浏览器打开”“复制链接”“查看封面”等），直接点视频画面播放、点图片看图、点头像或昵称进用户页（DEC-037、DEC-051 ⑦）。订阅详情“内容”标签的每条帖子右上角另有一个“⋯”，菜单是“在资源管理器中显示”，分隔线后红字“删除”（打开与媒体库相同的删除确认，DEC-064）；主页帖子没有“⋯”。**主页**里作者已订阅时，点头像进入这个订阅的详情，没订阅的才进用户页（DEC-057 ④）；用户页（解析页）只在用户主动解析或从别处明确打开时出现。
  - **在用户页与动态详情中**：帖子同样**没有文字按钮**；右上角状态圆点旁一个“⋯”，菜单依次是“缓存”（仅未缓存时）、“在浏览器中打开”“复制链接”（DEC-038）。点未缓存视频的画面打开视频详情。条目之间用细线分隔，不用卡片阴影。

### 3.1 主页：信息流（DEC-023、DEC-037）

- 顶部栏标题“主页”；始终按从新到旧（最新在上）排列，不提供“最新在前 / 最早在前”切换（DEC-037）。顶部栏右侧提供一个纯图标的离线刷新按钮（34×34 圆形按钮，`refresh` 图标，不放文字，悬停提示“刷新”，无障碍名“主页刷新”；点击在后台协程调用无锁增量 `RefreshLibrary` 并一并预读刷新后的信息流、统计与订阅列表，完成后以单次快照切换更新界面，不卡住主线程、零网络请求、不弹窗；保留当前站点筛选或单订阅视图）。
- **订阅列表**（DEC-053 ②，替代 DEC-037 的“有更新”与 DEC-039 的“正在直播”分节）：主页侧栏自上而下是“全部动态”、站点筛选，然后直接是订阅列表，**不加任何分节标题**，每行只有头像与名称、不写状态说明。正在直播的头像一圈橙色直播圈；**未读**时头像右下角一个约 8px 的强调蓝色圆点（带一圈背景色描边，样式参考哔哩哔哩动态页的头像条）。分三组：正在直播的在最前（组内未读在前，再按最近更新），然后未读，然后已读；后两组各按该订阅在当前站点筛选下最新一条已缓存内容的发布时间从新到旧。没有已缓存内容的订阅不列出（正在直播的除外）；只列订阅，没订阅的作者与直播间不进列表。订阅很多时列表虚拟化。窄窗没有侧栏时，变成时间线上方可横向滚动的头像条：圆形头像（约 52px）、下面一行名称，“全部动态”在最前，同样有直播圈与未读圆点。
  - **未读**：该订阅全部关联账号在当前站点筛选下最新的已缓存发布时间晚于 `homeSeen["sub:<id>"]`；没有这一项时与启动时读到的 `anchor`（看过的最新一条）比；两者都没有（第一次使用）算已读，不会满屏圆点。在主时间线上往下翻不改变某个订阅的已读状态，只有点开它才算看过。
  - **顺序在进入主页时定下**：本次停留期间（含点开、返回“全部动态”、切换站点筛选）只更新圆点与直播圈，不挪动行；新缓存的内容只让圆点出现，开播或下播只改直播圈，新出现的订阅加在末尾。下次进入主页（从别的页面切回来，或重新启动）重新排序，看过的移到已读组。
  - 点击某一行（包括正在直播的），进入**只含该订阅（全部关联账号）已缓存内容的信息流视图**：顶部栏显示返回箭头、头像与订阅名称，下方从新到旧列出该订阅的已缓存帖子（同样使用无底部按钮的主页 `PostCard`）；点击返回箭头回到主时间线原来的位置。
  - 成功打开后把该订阅的 `homeSeen` 记为原值与其最新缓存内容时间戳中较大的一个，圆点立即消失、行不挪动，直到该订阅又有更新的缓存内容；只按订阅记一个时间戳，不按单条记已读。读取失败保留主时间线，保存失败显示原因；返回主时间线时回到原来那条与行内偏移。
- 内容是所有已缓存的动态、直接缓存的视频和直播录像，不分作者，按发布时间（录像按开播时间）从新到旧排列，每条是一个帖子；录像帖子显示“直播录像”与清晰度编码规格。已缓存的视频卡片点击后在播放层播放本机文件；图片点击打开看图层看本机原图。
- **回到上次阅读的位置**（DEC-053 ①，替代 DEC-040 的“每次从最新处开始”）：“全部 / B 站 / 抖音 / 微博 / X”分别记下主时间线可见区最上面那条与它顶边的偏移（滚动停下约 1 秒后、离开主页、切换筛选与关闭窗口或退出时保存）。每次启动后第一次显示某个筛选时停在那条与偏移，往上滑载入之后缓存的内容，当前看到的条目不跳动；那条被删掉时停在不晚于它的最近一条；没有记录时从最新处开始。同一次运行内切到别的页面或别的筛选再回来，回到当时的位置。单个订阅的信息流不记位置。不提示“N 条更新的内容”，往上翻过的就是看过了（DEC-040）；看过的最新一条仍记为 `anchor`，作为没有 `homeSeen` 的订阅的初始已读基准。
- 抖音、微博与 X 的作品同样是帖子（DEC-043、DEC-065、DEC-066）：抖音视频作品按视频卡片（竖版封面在左、文案在右），抖音图文作品按图文帖子显示图片并在下方显示配乐条（[§3.4](#douyin-pages)）；微博单条按图文、混排、视频与转发帖子显示（[§3.4](#weibo-pages)）；X 单帖按长帖、作者线程、多图/GIF/视频混排与转帖/引用框显示（[§3.4](#x-pages)）；作者行均带站点小字。主页上下文侧栏“全部动态”下面有站点筛选“全部 / B 站 / 抖音 / 微博 / X”（窄窗时是时间线上方的五段式切换，720 宽无横向溢出），默认“全部”，记在 `ui-state.json`（FR-SITE-002）。
- **作者行的订阅名与共创头像**（DEC-063 ②）：帖子的账号名后面用小一号（13px）的强调色文字显示它所属订阅的名称，不加“订阅”二字；订阅名与账号名相同时不重复显示；点账号名或订阅名打开这个订阅。为订阅账号缓存的共创或合作作品（`via.reason = "collab"`）在主页与订阅详情“内容”中按这个 `via` 账号归属订阅，并优先显示该 `via` 账号的本机头像（不再显示共创发布者头像；`via` 账号无本机头像时回退到其所属订阅主账号的本机头像）。
- 底部到头时显示“已经到最早的缓存了”。
- 分页读取失败保留帖子并显示“重试”，等待用户重试；查看时间保存失败显示原因，“看最新”失败仍停在原位置。主页缺少本机图片时使用占位图，不自动补发远程图片请求。
- 空状态：“还没有缓存的内容。到‘解析’里打开一位 UP 主、抖音作者、微博博主或 X 用户，在动态、作品、微博或帖子上点‘缓存’”，带一个去解析页的按钮。

### 3.2 解析页（DEC-022、DEC-033、DEC-037、DEC-049 ②）

- **上下文侧栏**（≥ 1000 宽）：与视频页、用户页共用同一份“最近解析”列表。窄窗没有侧栏时，同一份列表（含“⋯”与行内确认）显示在大输入框下方，输入框靠上放置。
  - 侧栏顶部标题“最近解析”，右侧只放一个“⋯”按钮，展开“全部清空”（点击后在行内确认再执行，同时清理无引用缩略图；失败显示原因并保留确认，缩略图清理的恢复契约见[数据设计](design/data-and-cache.md#storage)）。
  - 解析成功后，封面与头像缩略图缓存到本机数据目录 `<DataDir>/thumbs/`（不进媒体库，不带 Cookie、不带外站 Referer，地址过白名单，大小有上限，文件名不含签名参数；未缓存到媒体库的条目也能显示封面与头像，失败时显示占位图而不是空白）。
  - 每行显示本机小封面或圆形头像、单行标题、一行“类型 · 站点”（如“视频 · B 站”“作品 · 抖音”“微博 · 微博”“帖子 · X”“X 用户 · X”），**点击整行直接打开详情**，当前正在查看的条目高亮；悬停或聚焦时右侧出现一个“⋯”按钮，展开“在浏览器中打开”与“删除”（删除单条时一并删除对应本机缩略图）。
- **主面板**：顶部栏标题“解析”（不显示“正在加载”“正在重建索引”等与解析无关的后台状态，DEC-033；所有页面顶部栏均无快速解析框，解析统一在本页进行，DEC-069）。主面板**不再列出最近解析**，只在页面竖直方向略偏上居中的位置放一个**大输入框**（最宽约 640px，高约 52px，全圆角胶囊形，类似搜索引擎首页）：左侧是当前登录账号头像，中间输入区提示可粘贴哔哩哔哩、抖音、微博或 X 的视频/图文/微博/帖子/直播链接、分享文本（含 `t.cn`、`t.co` 短链与镜像链接）、用户主页或 UID/`sec_uid`，右侧是强调色按钮“立即解析”。按回车解析；中文输入法正在组合输入时按回车不提交；解析中按钮显示“解析中…”并禁用。识别或解析失败在输入框正下方用一句话说明；微博直播链接给出提示“微博直播暂不支持录制，可以在浏览器中打开”且不发请求，X 直播与 Spaces 链接给出提示“X 直播与 Spaces 暂不支持录制，可以在浏览器中打开”且不发请求，未登录微博或 X 时分别提示“请先登录微博”“请先登录 X”且不发请求。

<a id="status-dot"></a>
### 3.3 状态圆点（DEC-024）

帖子、投稿条目和视频详情页显示一个直径 8px 的纯色小圆点（DEC-039；媒体库和主页不显示，主页只列已缓存的内容，DEC-046 ⑦）。**一条帖子只有一个圆点**，表示动态和其中的图片、视频合起来的状态：都缓存完整才是绿色，其中有缺的（例如视频只缓存了一部分）就是黄色，图片和视频卡片上不再各自显示圆点；视频详情页的圆点在“缓存视频”按钮旁，封面上不显示，配合“缓存”操作（帖子与投稿在“⋯”菜单里，视频详情页是“缓存视频”按钮）：

| 状态 | 圆点 | 按钮 |
| --- | --- | --- |
| 未缓存 | 不显示 | “缓存”（下载线性图标） |
| 排队 / 缓存中 | 蓝色进度圆环 + 悬停显示百分比 | 禁用，悬停显示“正在缓存” |
| 已缓存（最高档） | 绿色小圆点 | “已缓存”，点击进入媒体库对应条目 |
| 部分缓存 / 已暂停 / 可升级 | 黄色小圆点 | 部分：“补全”；暂停：“继续”；可升级：“升级缓存”。悬停列出缺什么、为什么，或“可升级到 4K（当前 1080P）” |
| 失败 / 文件缺失 / 清单损坏 | 红色小圆点 | “重试”或“删除记录”；悬停显示原因 |

圆点里不画对勾、短横等符号；含义靠悬停提示和无障碍名称（如“已缓存，1080P 高码率，最高档”“部分缓存”）给出，不只靠颜色。

<a id="detail"></a>
### 3.4 视频详情与用户页

- **视频详情页**（解析路由）：顶部返回箭头与“视频”；UP 主行（头像与昵称，点击进入空间；右侧“缓存视频”主按钮与状态圆点）；标题（大号）；大封面（已缓存时点击播放本机文件）；简介（超过 6 行折叠）；发布时间、分区；统计行（图标加数字）；多 P 列表（已缓存时每 P 显示实际清晰度，如“1080P 高码率 · AV1 · 杜比全景声”）。在解析路由打开已缓存视频时集中提供缓存维护操作（DEC-037）：探测到更高档时，标题上方显示黄色横幅与“升级缓存”按钮；同时在详情操作行提供“补存弹幕和字幕”按钮。
- **站点标记**（FR-SITE-002，DEC-043、DEC-065、DEC-066）：用次要文字色、12px、无底色的小字“B 站”“抖音”“微博”“X”，紧跟在作者名或元信息后面（中间一个“ · ”）。出现在用户页头部、订阅详情“账号”列表、主页帖子作者行、媒体库卡片的元信息行、任务行、最近解析条目六处；订阅网格的头像不加。不使用站点的图标与品牌色。
- **本机内容详情**（`/library/item`，DEC-049 ③）：从媒体库条目右下角“⋯ → 详情”进入媒体库自己的本机详情路由，图标栏仍高亮“媒体库”，上下文侧栏仍保持媒体库侧栏，返回箭头回到媒体库原来的筛选与滚动位置。只读本机清单和媒体，不发任何站点请求，缺图用占位图；不显示互动数据（播放数等会变，不缓存，DEC-040），未知时长不冒充 0；动态详情保留本机图片和引用视频卡片，直播录像显示“直播录像详情”、直播间、清晰度与分段原地播放，详情里的图片、视频、多 P、实况、配乐与录像分段点击都原地打开看图层或播放层。隐藏所有需要联网的操作（缓存、补存弹幕和字幕、升级缓存、刷新元数据），只在右上角“⋯”菜单保留一项“在解析页打开”供用户明确选择联网查看。
- **用户页**：横幅（带头像、昵称、`UID`、等级）；下面一行“关注 N · 粉丝 N · 投稿 N”，右侧只有一个订阅按钮（未订阅时强调色“订阅”，点击打开[加入订阅对话框](#subscribe-picker)；已订阅时“已订阅”，点击进入所属订阅）和一个“⋯”（“全部缓存”或“在缓存队列中查看”，“在浏览器中打开空间”，直播中另有“在浏览器中观看直播”）；签名；标签栏为“动态”（默认）和“投稿”，标签不带数字，标签栏右侧是筛选“全部 / 未缓存”。动态是帖子；投稿是缩略图在左、标题和时长/播放数在右的紧凑行，点行打开视频，“缓存”“在浏览器中打开”在行右侧的“⋯”里。**整个头部是列表的第一行，随内容一起滚走**，窗口矮时也能看到内容（DEC-038）。两种列表都滚动到底自动加载。
  - **只看未缓存**（DEC-046 ⑧）：筛选只作用于已加载的页，切换不请求站点；之后加载的页同样按筛选显示。已加载的都缓存了时显示“已加载的内容都缓存了”和“加载下一页”按钮，不自动连翻。
  - **全部缓存**（DEC-050 ①，替代原按 10 / 20 / 50 条一次入队的做法）：用户页“⋯”提供一项“全部缓存”（哔哩哔哩按当前标签是“动态”还是“投稿”决定列表，抖音为“作品”，微博为“微博”且只补原创微博，X 为“帖子”且只补原创帖子，看不到作品的私密/受保护账号不提供）；当该账号的这一列表已在缓存队列中且未结束时，菜单项变为“在缓存队列中查看”（点击跳到任务页并选中该队列任务）。点“全部缓存”不弹确认框，直接建立后台缓存队列任务并在顶部提示“已加入缓存队列，会在后台慢慢缓存”。队列在后台按慢速、不规律的节奏逐条缓存（Q-017 默认值：每个站点同时只跑一个队列任务，每次只把 1 条未缓存条目排进下载队列、等它下载结束再随机等 40～150 秒，每缓存 15～25 条长歇 10～25 分钟；已加载的页不重发请求，后续翻页计入站点的每小时额度并遵守退避，遇风控、限流或额度用完进入“等待退避结束”、退避过后再随机等 10～30 分钟继续，登录失效暂停并在重新登录后继续，重启后接着做；微博到博主可见范围边界、X 到时间线可见上限时正常结束并把提示写入队列摘要）。缓存规则开了“全部缓存”时，后台按同样的队列定期补齐，任务页里这类队列的名称写“<账号> · 定期全部缓存 · 投稿/作品/微博/帖子”（DEC-061 ①）。从用户页点开的视频，在视频页点“缓存视频”也按这个用户存放合作视频（DEC-061 ③）。
  - 正在直播时，签名下方出现一条直播横幅：橙色“直播中”标记、直播标题（悬停显示房间号）与清晰度编码（如“原画 · AVC”），右侧只有一个按钮“录制”（录制中变为“停止录制”，DEC-033、DEC-038）。

<a id="douyin-pages"></a>
- **抖音用户页**（FR-DY-004，DEC-043）：结构同上，差别只有内容：横幅位置用中性色块（抖音没有横幅），头部是头像、昵称、小字“抖音”、抖音号；“关注 N · 粉丝 N · 获赞 N · 作品 N”；签名；**只有一个“作品”列表**（不显示标签栏）。作品是网格：竖版 3:4 封面卡片（视频右下角时长，图文左上角“图文”、置顶的左上角“置顶”角标），每行按宽度 3～5 个，点卡片打开作品详情，“缓存”“复制链接”“在浏览器中打开”在卡片右下角的“⋯”里，卡片右上角是状态圆点。私密账号先照常请求作品：当前登录的抖音账号看得到（例如已关注且被通过）时照常列出，列表底部一行小字“私密账号：当前登录的抖音账号可以看到这些作品”，也能“全部缓存”；看不到时写“这个账号是私密账号，当前登录的抖音账号看不到作品”（DEC-057 ⑦）。资料显示 0 条公开作品且首屏正常返回空列表（含 `[]` 或 `null` 且 `has_more: 0`）时，直接显示“还没有发布公开作品”，**不误判为“登录已失效”**；首屏不确定空结果提示可重试错误而不标记登录失效，第 2 页及以后空壳才按登录失效处理。“作品”标题右侧有同样的“全部 / 未缓存”筛选，“⋯”里有同样的“全部缓存”（已在队列中未结束时为“在缓存队列中查看”；看不到作品的私密账号没有）。直播横幅同上。
- **抖音作品详情**（FR-DY-003）：版式同视频详情。视频作品：作者行（头像、昵称、小字“抖音”，右侧“缓存视频”主按钮与圆点）；文案首行作标题，其余作正文（话题用强调色文字）；竖版封面按原比例、最大高度为页面可见高度的 70%，已缓存时点击播放；发布时间、时长；统计行只有点赞、评论、收藏、分享（没有播放数）；配乐一行“♪ 标题 · 作者”。图文作品：同样的作者行与文案，各页按帖子规则显示（一张按原比例，多张为正方形格子；实况照片标“实况”；视频页显示封面，中间一个半透明圆形播放标记，右下角时长），点任何一页打开看图层；图片下方是**配乐条**：圆形播放/暂停、“♪ 标题 · 作者”、进度与时长；没缓存时播放在线配乐，已缓存时播放本机文件，取不到时配乐条显示原因并禁用。已缓存的作品详情集中提供本机信息（实际清晰度与编码，如“1080P · HEVC”）；没有升级、补存弹幕字幕的操作。

<a id="weibo-pages"></a>
- **微博用户页**（FR-WB-004，DEC-065）：头部结构同哔哩哔哩用户页，包含头像、昵称、小字“微博”、UID、简介与认证说明、统计行（含“微博 N”）、“订阅 / 已订阅”按钮（打开[加入订阅对话框](#subscribe-picker)）与“⋯”（“全部缓存”或“在缓存队列中查看”、“在浏览器中打开”），不显示直播横幅。只有一个“微博”列表（不显示标签栏），右侧提供“全部 / 未缓存”筛选；置顶微博排前并标“置顶”，滚到底加载下一页、两页无重复；博主设了可见范围（如只展示最近半年）时底部如实显示站点的提示文案而不是错误；严格区分“登录已失效或被拦截”的空壳错误、真正 0 条的“还没有微博”与正常到底，遇到风控停在原处可重试。
- **单条微博详情**（FR-WB-003，DEC-065，含独立视频页与媒体库离线 `/library/item`）：作者行（头像、昵称、小字“微博”，点击进入用户页；右上角状态圆点与“⋯”菜单：缓存、复制链接、在浏览器中打开）、发布时间、完整正文（长微博自动补全全文，短链按站点标题显示）、可见范围提示；转发在主页、订阅详情、博主主页、我的 › 微博 › 收藏与联网/离线详情均展示完整嵌套原博引用框（可展开原博全文、原博图片/GIF/实况网格、可播放视频卡片与富媒体卡片；原博已删或不可见时保留外层转发正文并显示不可见说明；联网详情在引用框提供“打开原微博”按钮以独立打开原博，未缓存视频支持经 `StagePreviewMedia` 预览或提示缓存后本机播放；离线详情以“转发微博”标记及在 `Via.UID != Author.UID` 时显示“由 <Via.Name> 转发”）；从博主主页、带转发者路径的链接或订阅上下文进入/缓存转发微博时传递转发者/订阅归属上下文（`weiboCacheFor`、`ForwarderHintUID`），使快转与普通转发均存入该转发者或订阅账号的 `forwards/` 目录；超过 9 张图按原顺序全部展示，GIF 显示动图，实况照片标“实况”并在看图层内联播（`InlineSite="weibo"`），图片与视频混排按原顺序；单视频显示封面、时长、清晰度与编码；头条文章、投票、音乐、外链与直播卡片仅显示摘要与“在浏览器中打开”，**不出现缓存视频入口**；转发、评论、点赞数只在联网详情显示，离线详情不显示。

<a id="x-pages"></a>
- **X 用户页**（FR-X-004，DEC-066）：头部结构同微博用户页，包含头像、昵称、`@handle`、小字“X”、简介与认证说明、统计行（含“帖子 N”）、“订阅 / 已订阅”按钮（打开[加入订阅对话框](#subscribe-picker)）与“⋯”（“全部缓存”或“在缓存队列中查看”、“在浏览器中打开”），不显示直播横幅。只有一个“帖子”列表（不显示标签栏），右侧提供“全部 / 未缓存”筛选；置顶帖排前并标“置顶”，滚到底加载下一页且两页无重复；到达时间线可见上限时底部显示“已到达 X 时间线可见上限”；受保护账号明确说明原因；严格区分限流/风控造成的假空壳错误（停在原处可重试）、真正 0 帖的“还没有帖子”与正常到底。
- **单条 X 帖子详情**（FR-X-003，DEC-066，含媒体库离线 `/library/item`）：作者行显示头像、昵称、`@handle` 与小字“X”（点击进入用户页；右上角状态圆点与“⋯”菜单：缓存、复制链接、在浏览器中打开）；发布时间、编辑标记与可见范围提示；完整正文（自动展开 `note_tweet` 长帖全文并还原 `t.co` 原链接）、作者自回复线程按顺序展示；转帖与引用帖显示嵌套原帖框（支持长帖全文与媒体，原帖已删除、受保护或地区不可见时保留外层并说明原因）；最多 4 项图片、GIF 与视频按原顺序混排（GIF 静音循环播放；视频显示封面与时长；仅有 HLS 分段流时提示“这条视频只有分段流，暂不支持缓存”而不提供无效视频缓存入口）；投票、外链卡片、X Articles、直播与 Spaces 卡片仅显示摘要与“在浏览器中打开”，**不出现缓存视频入口**；回复、转帖、喜欢等数字只在联网详情显示，离线详情不显示。

<a id="viewer"></a>
### 3.5 看图层（DEC-033）

- 点击任何图片打开看图层：一个浮在应用上方的深色圆角面板（四周留边，背后的应用变暗，点面板外面关闭；DEC-040），默认按面板适应显示**原图**（已缓存的用本机文件，否则用去掉尺寸后缀的原图地址）。
- 滚轮、快捷键（`+` / `-` / `0`）或双击缩放，按住拖动平移；只保留少量半透明圆形悬浮按钮：右上角**关闭**，左右两侧**上一张 / 下一张**，底部居中**适应窗口 / 原始大小（1:1）**，左上角轻量胶囊显示“当前 / 总数 · 缩放百分比”。
- 鼠标静止约 2 秒后悬浮控件自动隐藏，鼠标移动或按键时重新出现；左右键切换同一条动态里的图片，Esc 关闭。
- 实况照片与 X GIF（MP4 静音循环）翻到这一页就在看图层里原地自动播放动态片段（DEC-040、DEC-046 ①、DEC-049），底部圆形“播放”按钮用来重播：已缓存的播放本机片段，没缓存的先从站点取到临时文件再播放（哔哩哔哩、抖音、微博与 X 均一致，按 `InlineSite` 区分站点通道），不跳到播放层。
- 抖音图文的视频页在看图层里直接播放（点画面暂停/继续，底部一条细进度条与时长，没缓存时播放在线地址）；切到别的页时停止。视频页或实况片段播放时，配乐条暂停，停止后不自动恢复。

### 3.6 媒体库与任务

- **媒体库**（图标栏“媒体库”，DEC-037、DEC-039、DEC-049 ③）：独立的离线浏览页面。顶部栏标题“媒体库”（“重建索引”在设置“存储”）；搜索框右侧一个“刷新”按钮（DEC-055）：在后台重新检查保存位置里的文件（只看文件在不在、大小对不对，不算哈希、不联网，进行中显示“正在刷新…”），完成后弹窗列出这次发现的变化——“文件夹已删除，已从媒体库移除（N）”（标题与文件夹路径）和“缺少文件（N）”（标题与缺少的文件名，最多列 6 个），没有变化时写“检查了 N 个条目，没有发现被删除的文件。”，底部“知道了”；类型与来源在上下文侧栏（窄窗时退回为页面里的标签“全部 / 图片 / 视频 / 直播录像 / 转发”和“作者筛选”）；页面里一行搜索框，**固定按发布时间从新到旧排序**（直播录像按开播时间；不再提供“发布时间 / 缓存时间”切换，已保存的旧缓存时间排序偏好静默忽略）。来源分组里加站点筛选“全部 / B 站 / 抖音 / 微博 / X”（720 宽无横向溢出），与类型、作者筛选叠加（FR-SITE-002）。顶部栏右侧一个“⋯”（菜单“导入…”“导出…”，DEC-062）。
  - **导入页**（“⋯ → 导入…”，[远程 §6.3](design/remote.md#import)）：在媒体库里打开，标题“导入”，左上角返回箭头回到媒体库，上下文侧栏仍是媒体库侧栏，内容宽度最多约 760px。上方“选择要导入的文件夹”、一行说明（网盘下载的文件夹、另一台 TRACE 的缓存或导出文件夹都可以；先只读扫描，确认后才写入）、路径输入框与强调色“扫描”（扫描中“正在扫描…”，下面一行“正在扫描：已检查 N 个条目”与“取消”）。扫描完成后：一行摘要“扫描到 N 个条目：M 个会导入（约 X），K 个冲突等你决定”；一排可点的分类胶囊“全部 N · 新条目 · 可补充 · 相同 · 冲突 · 未传完 · 无法识别”（各带条数，点了只看这一类）；有冲突时一行“全部冲突都：[暂不处理 / 保留本地 / 用导入的 / 合并]”与小字“逐条选的优先”；下面每个条目一张细边框卡片：分类小标签、标题，冲突条目右侧一个同样的下拉框，一行小字（作者、“来自 <节点名>”、要复制的文件数与大小、缺失或不一致的文件数、内容不同的文件名、“本地在另一个作者文件夹”、无法识别的原因），一行来源文件夹路径；最多列 200 条，超出时说明“只显示前 200 条；导入会处理全部条目”。底部固定一条操作栏：开关“导入后删除来源里已导入的文件”（说明只删校验通过并已导入的文件和变空的文件夹，默认关），右侧“放弃”与强调色“开始导入”；开始后跳到任务页“导入导出”。扫描失败、取消时在原处说明。
  - **导出**（“⋯ → 导出…”，[远程 §6.4](design/remote.md#export-local)）：对话框，标题“导出媒体库”、一行说明、“范围”下拉（“全部”；媒体库当前有类型、站点、来源或搜索筛选时另有“当前筛选”）、目标文件夹输入框，“取消”与强调色“开始导出”；目标为空、范围内没有内容时在框下说明原因；开始后跳到任务页“导入导出”。
  - 网格：卡片约 240px 宽，按页面宽度每行 2～6 个；**16:9 圆角缩略图**（圆角 14px），视频右下角显示时长、正中播放图标；**不显示状态圆点**（媒体库里都是已缓存的内容，DEC-039）；缩略图下方是**最多两行的标题**（14px，600）、一行元信息（作者名，直播录像附清晰度与编码如“原画 · AVC”）和右侧一个“⋯”按钮。虚拟滚动，滚到底继续加载。
  - 点击缩略图或标题直接在原地打开对应文件的看图层或**播放层**（DEC-033、DEC-037、DEC-049 ③），不按网格位置猜测分 P、不跳转到解析路由、不发任何站点网络请求；点击右下角“⋯”展开菜单：**详情**（在媒体库自己的本机详情路由 `/library/item` 打开所属动态、视频、作品或直播录像，保持“媒体库”图标高亮与媒体库侧栏，返回时保留原筛选与滚动位置，只读本机数据，仅在详情“⋯”里留“在解析页打开”作为明确联网入口）、**在资源管理器中显示**、**删除**。播放层和看图层一样是浮在应用上方的深色圆角面板（点面板外关闭；全屏时铺满窗口），**打开即自动播放**（DEC-040），底部悬浮条只保留圆形**播放/暂停**、**进度条**、**音量**、**全屏**，右上角保留圆形**“⋯”更多菜单**与**关闭**。音量按钮展开 0～100% 滑块与静音开关；全屏作用于原生窗口，切分段保持全屏，关闭播放或登录失效时恢复。**弹幕**（开关、透明度滑块 20%～100%、显示区域上方 1/4 / 上半屏 / 全屏、密度低/中/高/不限）、**字幕**（语言选择与关闭）、**分段切换**（多 P 或多段直播录像的“上一段 / 下一段”）、**在文件夹中显示**、**用系统播放器打开**统一收进“⋯”菜单。鼠标静止约 2 秒后悬浮控件自动隐藏，鼠标移动或任意按键时重新出现；菜单打开时保持控件可见。音量、静音、弹幕与字幕偏好记住并沿用，保存失败显示原因。
  - 每个条目的“删除”打开确认弹窗：写明预计清理的已登记缓存文件数与大小；标题行写“类型：标题”（动态没有标题时用正文第一行）；删除动态时说明一并删除的引用视频数，以及“这条动态引用的 N 个视频单独缓存过或还被别的动态引用，将保留”；删除后文件夹里还有非 TRACE 文件时提示“已保留 N 个不是 TRACE 创建的文件”。
  - 空状态：“还没有符合筛选的媒体。缓存图片、视频或直播录像后，它们会出现在这里”。
- **任务**（图标栏“任务”，DEC-049 ①、DEC-050 ②、DEC-051 ③）：通过上下文侧栏（≥ 1000 宽；窄窗 `< 1000` 时退回为页面顶部的分段选择）组织六部分内容，点哪一项主面板显示哪一项：
  1. **下载任务（N）**（N 为排队与进行中的下载任务数，与图标栏“任务”角标一致）：顶部栏右侧提供“检查画质更新”按钮（执行时显示“检查 M / N · 取消”），列表上方固定批量操作栏——存在可重试任务（失败、部分完成或非用户手动暂停的暂停任务，按 `IsRetryableTask` 计数，不含用户手动暂停）时提供强调色“批量重试（N）”按钮（点击调用 `RetryAllTasks` 并按已登录站点隔离批量重新入队、在顶部横幅反馈重试/缺登录跳过/重复跳过结果），存在已结束（已完成 / 已取消）的任务时并排提供“清除已结束（N）”按钮。任务列表使用 `ui.List` 虚拟化滚动（仅渲染可见卡片，配合轻量摘要查询 `ListTasksSummary`、256px 缩略图与按 `libraryRev` 缓存的封面，不随每秒下载进度清空重查，单条操作只刷新任务列表），任务增多时仍流畅滚动。每行是对象缩略图、标题、站点小字、进度条与“已下载 / 总大小”、状态文字和操作（进行中/排队可暂停或取消；已暂停可继续；失败/部分完成可重试或移除；已完成/已取消可移除，不能取消；DEC-033）。失败原因（`LastError`）直接显示在任务行内；移除失败或部分完成的任务前，行内弹出确认提示“确认移除该任务？会删除未完成的临时文件，已缓存完成的文件会保留”。点“展开详情”（FR-CACHE-009）按需读取逐文件进度清单与脱敏后的分段重试记录。
  2. **缓存队列（N）**（DEC-057 ②，替代每个队列占侧栏一行；N 为未结束的队列数）：主面板顶部一行小字“取消或移除队列不会删除已缓存到媒体库的内容”，有结束的队列时右侧“清除已结束（N）”；下面每个队列一张卡片：头像、“账号名称 · 列表类型”、站点小字、状态（或下次时间）与“已缓存 x · 跳过 y”，右侧展开箭头与操作（进行中“暂停”“取消”，已暂停“继续”“取消”，已结束“移除”）。点卡片展开：当前正在缓存的条目、暂停或等待的原因、“最近缓存的内容”（本机封面——动态没有图片时用它引用的视频封面——、标题与缓存时间，点击直接打开本机内容）。从用户页“在缓存队列中查看”进入时展开对应的卡片。
  3. **直播录制（N）**（N 为正在录制的场数）：列出正在录制的直播行与最近结束的录制行（主播头像、直播标题、站点小字、橙色“录制中”标记、已录时长、大小、速度、段数与清晰度编码如“原画 · AVC”，进行中右侧“停止录制”）；有录制异常的场次在行上显示“⚠ N 处异常”小字（可点开查看异常）；没有录制在进行时显示“现在没有直播在录制”。
     - 最近结束的录制每行右侧“移除”，标题行右侧“全部移除（N）”：只从这个列表隐藏（8 天内不再出现），录像留在媒体库（DEC-057 ①）。
     - **页内实时预览**（DEC-049 ①）：在“直播录制”里点击一场正在录制的直播，在页面内直接实时播放正在写入的 `.part` 分片 MP4 画面（边写边读本机录制文件并等待新分片，**不另开任何站点连接**；画面落后直播约 10 秒以内；预览区不渲染弹幕、也不显示弹幕开关，实时弹幕待实现 FR-LIVE-003）。离开“直播录制”视图（含切到“录制异常”等其他组）或任务页、切换预览对象或停止录制时立即停止预览并同步释放文件句柄，换段时跟随新段或平滑结束，不影响 `.part` 的收尾转换与改名；若某条录制路径不支持实时预览，页面如实说明“这场录制暂不支持实时预览”。
  4. **录制异常（N）**（DEC-051 ③；N 为最近 7 天含进行中有异常的录制场数，为 0 时显示“录制异常”不带数字）：按录制场次列出（主播/直播间、站点小字、开始时间，以及该场的异常列表：发生时间、类型的中文说明——断流重连、因网速跟不上丢失片段及估算秒数或重连空档秒数、连续 30 秒速度低于码率及持续时长、空间不足、收尾转换失败——与影响时长或段数）；已结束的场次点击可打开本机离线录像详情（`/library/item`，同媒体库，不发网络请求），右侧红色描边按钮“删除记录”删除这一场的异常记录（录像不删，正在录制的场次没有这个按钮，DEC-057 ①）；没有异常记录时显示空状态说明。
  5. **检查计划**（DEC-059 ①）：顶部一行“下一轮定时检查：今天 21:07”（定时检查关闭时说明），下面两行小字：更新检查每轮每个站点最多检查的账号数（B 站 30、抖音 20、微博 20、X 15）、上次查得早的先查、额度不足或退避时顺延；开播检查的规则摘要（B 站每轮查全部，抖音两次至少隔 6 秒、一轮最多几个、超过后轮流查、不占每小时额度，微博与 X 不查开播，完整规则见设置 › 订阅与直播，DEC-060 ⑤）。每个订阅账号（含微博与 X 账号）一张卡片：头像、昵称、站点小字、所属订阅名；“更新检查：上次 今天 20:07 · 正常”（从未检查时“还没有检查过”，失败时红字写原因，如“本小时额度用完，已顺延”）；开了“开播录制”的订阅，哔哩哔哩与抖音账号再加一行“开播检查：上次 今天 20:51 · 约每 3 分钟”，微博账号显示“微博直播暂不支持录制”、X 账号显示“X 直播与 Spaces 暂不支持录制”（`LiveNote`）而不显示开播频率；右侧“下次 今天 21:07”（退避时“退避后 …”），或“只手动检查”“定时检查已关闭”“未登录，不检查”。按下次检查时间排列，不发站点请求，每 20 秒重读一次本机状态。顶部右侧“检查全部”，检查进行中换成“正在检查 x / y”与“取消”；每张卡片最右“检查”只查这一个账号，查的时候显示“检查中…”，其他卡片的按钮暂不可用，未登录站点的账号按钮不可用（DEC-060 ③）。
  6. **导入导出（N）**（DEC-062）：本次运行里的导入与导出，新的在上。每个一张卡片：上传图标、“导入 · <来源文件夹>”或“导出 · <目标文件夹>”、右侧状态（正在扫描 / 等待确认 / 正在导入 / 正在导出 / 已完成 / 失败 / 已取消）；进行中有进度条、“已复制 / 总大小 · 速度”（扫描时“已检查 / 总数”）、“取消”与当前条目名；扫描完等待确认的写各分类条数，右侧“放弃”与强调色“查看预览”（回到导入页）；结束后一行摘要（导入：“新增 · 补充 · 跳过 · 处理冲突 · 未传完 · 复制 N 个文件（大小）”，勾了删除来源时附删除的文件数；导出：“导出 N 个条目 · M 个文件（大小）”及本地已缺失的文件数），失败原因与没完成的条目红字列出。没有任务时空状态“还没有导入或导出”，说明从媒体库右上角“⋯”开始。

### 3.7 设置页（DEC-019）

打开设置时，**上下文侧栏是设置的分类**（DEC-038、DEC-039），图标栏不变：

- 侧栏最上面是返回箭头加“设置”（回到进入设置前的页面），下面是分类，只有**图标 + 名称**，不带说明小字；选中项浅强调色胶囊底、图标和文字强调色。宽度 ≥ 1000 时侧栏约 232px 显示名称，更窄时 72px 只显示图标（悬停有提示，带无障碍名称）。
- 内容区顶部栏标题就是分类名，下面直接是设置项，不再重复分类标题。
- 路径 `/settings/<分类>`，默认“账号”；分类列表以后可以加搜索框，现在不做。
- 设置内容不套卡片：分组和设置项之间只用细线分隔，不出现白、灰、白层层嵌套的框；侧栏条目文字 14px（DEC-040）。
- 每个设置项一行：名称 + 当前值 + 操作，用细线分隔。**设置项默认没有说明小字**；只有需要提醒后果或限制的具体设置才有一行说明（如“关闭窗口时”“定时检查更新”“缓存保存位置”）。下拉框显示中文选项名（如“能拿到的最高（推荐）”“最小化到托盘（推荐）”），不显示内部值。改动立即保存，保存失败在该行下方显示原因。
- 分类：

### 3.8 登录页

一个站点都没登录时唯一可进入的内容页（设置页除外）；已登录任一站点后也可以从设置或“请先登录”提示进入，来登录其他站点。居中一张卡片，最上面是站点切换（四段式切换“哔哩哔哩 / 抖音 / 微博 / X”，从提示进入时预选对应站点），标题“登录哔哩哔哩”“登录抖音”“登录微博”或“登录 X（原 Twitter）”，说明“TRACE 需要登录后才能解析和缓存”。

**抖音**只有“粘贴凭证”一种方式（FR-DY-001）：说明怎样在浏览器打开抖音网页、登录后从开发者工具复制请求里的 Cookie（只写步骤，不放截图）；单行密码型输入框，占位“粘贴 Cookie（至少包含 sessionid）”；“验证并登录”；结果一句话：成功显示头像、昵称、抖音号后进入应用，失败写原因（“缺少 sessionid”“抖音认为这个 Cookie 没有登录或已过期”“抖音要求验证，请先在浏览器里正常打开一次抖音再复制”）。提交后输入框立即清空。

**微博**只有“粘贴凭证”一种方式（FR-WB-001）：说明怎样在桌面浏览器打开 `weibo.com`、登录后从开发者工具复制请求头里的整段 Cookie；单行密码型输入框，占位“粘贴 Cookie（至少包含 SUB）”；“验证并登录”；结果一句话：成功显示头像、昵称、UID 后进入应用，失败分别说明缺 `SUB`、未登录或访客 Cookie、验证或风控且不保存、不改变已有凭证。提交后输入框立即清空。

**X（原 Twitter）**只有“粘贴凭证”一种方式（FR-X-001）：说明怎样在桌面浏览器打开 `x.com`、登录后从开发者工具复制发往 `x.com` 请求头里的整段 Cookie；单行密码型输入框，占位“粘贴 Cookie（至少包含 auth_token 与 ct0）”；**提交按钮上方**固定显示中立事实风险提示框（说明 X 网页端接口不是官方开放 API、X 条款限制自动化访问、存在触发限流/验证/临时锁号甚至封号风险、建议使用专门账号或小号但不阻止粘贴自有账号、TRACE 只读不写不存密码不自动续期、遇验证或锁号立即停止 X 全部自动请求）；“验证并登录”；结果一句话：成功显示头像、昵称、`@handle` 与 ID 后进入应用，失败分别说明缺 `auth_token`/`ct0`、未登录或访客态、账号不一致、限流（带预计恢复时间）或验证/锁定（“X 要求验证或账号被临时锁定，TRACE 已停止 X 的全部自动请求，请先在浏览器里处理”）且不保存、不改变已有凭证。提交后输入框立即清空。

**哔哩哔哩**下面两个标签：

- **扫码**：二维码、状态文字（未扫码 → 已扫码，请在手机上确认 → 登录成功 / 已过期）、取消与刷新。
- **粘贴凭证**：说明怎样从浏览器复制 Cookie（只写步骤，不放截图）；单行密码型输入框，占位“粘贴 Cookie（至少包含 SESSDATA）”；强调色胶囊按钮“验证并登录”；验证中按钮显示加载状态；结果用一句话说明（成功后进入主页；失败写原因，如“缺少 SESSDATA”“凭证已失效”）。提交后输入框立即清空。下方一行浅色提示：“凭证只保存在这台电脑上，并按当前 Windows 用户加密”。
- 登录已失效时卡片上方多一行：“登录已失效，请重新登录”。

### 3.9 订阅（DEC-026、DEC-033、DEC-051 ⑦）

每个界面区域最多只放一个强调色主按钮。

**订阅列表** `/subscriptions`：

- 顶部栏标题“订阅”，右侧只放一个强调色主按钮“添加订阅”和一个“⋯”（菜单“检查全部”“从关注列表导入”“导出订阅…”“导入订阅…”；检查进行中时顶部显示“正在检查 M / N”和“取消”按钮）。
- **导出订阅 / 导入订阅**（DEC-062，[远程 §6.4](design/remote.md#export-local)）：都是对话框。导出：标题“导出订阅”、一行说明（订阅、关联账号、缓存规则和部分设置，不含 Cookie；填文件夹时自动补上文件名）、路径输入框、“取消”与强调色“导出”，成功后顶部提示“订阅已导出到 <文件>”。导入：标题“导入订阅”、路径输入框（文件或它所在的文件夹）与“预览”；预览一行摘要“新订阅 N 个 · 已订阅的账号 N 个 · 新规则 N 个 · 规则不同 N 个 · 已全部订阅 N 个”，下面分节列出新订阅（名称、账号数、规则名）、已在订阅里的账号（昵称、站点、本地在哪个订阅）与开关“把导入订阅里的新账号合并进这些已有订阅”（默认关：跳过已订阅的账号，其余账号建成新订阅）、内容不同的规则（每条一个开关“用导入的“<规则名>””，说明两边的摘要，默认保留本地）；底部“取消”与强调色“确认导入”（有预览后才出现），成功后关闭并提示新增的订阅数，失败在框内说明、什么都不改。
- 顶部栏下面一个搜索框（按订阅名、备注和账号昵称过滤，只在本机过滤）。
- 主体是**较大的圆形头像网格**（头像约 92px，下方一行订阅名称，过长自动省略），按可用宽度自动排列列数（3～5 列），按行虚拟化滚动（NFR-UI-002）。
- 正在直播的订阅头像外有橙色直播圆环，头像下沿带橙色胶囊小标“直播”（正在录制时带红点与“录制中”）；点击该直播/录制小标即可一键开始或停止录制，点击头像或名称进入订阅详情 `/subscriptions/:id`。
- **全部账号**（DEC-057 ⑥）：侧栏“全部账号”（窄窗在搜索框旁的“全部账号”按钮）打开按站点列出全部订阅账号的页面：顶部“全部 / B 站 / 抖音 / 微博 / X”与“N 个账号”，下面每个账号一行：头像、名称与站点小字、“UID …”“抖音号 …”或“`@handle`”及作品数（B 站与抖音写“作品 N · 已缓存 M · <统计时间> 统计”，微博写“微博 N · 已缓存 M · <统计时间> 统计”，X 写“帖子 N · 已缓存 M · <统计时间> 统计”；还没解析过这个账号时写“已缓存 M · 作品总数在打开主页后统计”，DEC-061 ②），右侧胶囊“订阅 <所属订阅名>”和行尾“⋯”菜单（“更改关联订阅”“打开订阅”“打开主页”）；按站点、再按名称排序，虚拟滚动；点一行进入所属订阅的详情。
- 空状态：“还没有订阅。把你关心的人建成订阅，一个人可以关联他的多个账号”，搭配顶部“添加订阅”主按钮和空状态“从关注列表导入”按钮。

**添加订阅**（对话框）：名称输入框（必填，≤ 64 字）；“关联账号”输入框（可选，粘贴哔哩哔哩主页链接或 UID、抖音主页链接/分享文本/`sec_uid`、微博主页链接/分享文本，或 X 主页链接/分享文本，可预览显示头像、昵称、站点小字与 UID/抖音号/`@handle` 确认卡片；账号已属于别的订阅时卡片里写“该账号已属于订阅 X”并提供“创建并移到新订阅”；不属于任何订阅、且已有订阅时，卡片里另有“加入现有订阅…”，关闭这个对话框并以预览的账号打开加入订阅对话框）；强调色主按钮“确认添加”。

<a id="subscribe-picker"></a>**加入订阅**（对话框，DEC-058，FR-USER-003）：用户页“订阅”（哔哩哔哩、抖音、微博与 X）、“我的”里关注的人“⋯ → 加入订阅”、添加订阅里的“加入现有订阅…”都打开它。顶部是账号头像、“订阅 <昵称>”与站点小字，一行说明“加入一个现有订阅（同一个人的多个账号放在一起），或者新建一个订阅。”；下面是唯一的强调色主按钮“新建订阅“<昵称>””（用默认规则新建，名称即昵称）；再下面“或加入现有订阅”、搜索框（按订阅名称、备注与账号昵称过滤，输入法组合输入时不过滤）与订阅列表（头像、名称、一行“B 站 N · 抖音 N · 微博 N · X N · 备注”，右侧“加入”，虚拟滚动；没有订阅时写“还没有订阅，可以新建一个”，没有匹配时写“没有匹配的订阅”）。点一行把账号加入那个订阅并关闭，顶部提示“已把 X 加入订阅“Y””；失败（例如账号已属于别的订阅）在列表下方说明原因、对话框不关。底部“取消”；Esc 与点空白处也关闭。

**更改关联订阅**（对话框）：从订阅详情 › 账号行尾“⋯ → 更改关联订阅”或订阅 › 全部账号行尾“⋯ → 更改关联订阅”打开，与“加入订阅”共用搜索选择框；标题为“更改关联：<昵称>”加站点小字，副标题写明当前所属订阅并说明保留已缓存内容与检查起点；主按钮“移到新建订阅“<昵称>””原子新建并移入该账号，下方搜索列表排除当前所属订阅（无其他订阅时显示“还没有其他订阅，可以移到新建订阅”），点选任一目标订阅即原子转移并刷新界面，不发站点请求。

**订阅详情** `/subscriptions/:id`：

- 顶部返回箭头与订阅名。详情头部（不套卡片）只有大头像、订阅名（及备注说明）、一个**规则按钮**“规则：<规则名> ▾”和一个“⋯”（菜单“检查更新”“改名”“备注”“更换头像”，分隔线后红字“删除订阅”；检查中头部附“取消检查”）。规则按钮弹出全部缓存规则（名称与摘要，当前规则打勾），选一条立即生效，最后一项“管理缓存规则”进入设置的“缓存规则”（DEC-040）。
- 标签栏只有两个：**内容**（默认，`tab=content`）、**账号**（`tab=accounts`；旧保存状态或路由里的 `live` 读入时自动归到“账号”，DEC-051 ⑦，替代 DEC-040 的“直播 / 账号”标签；不再有“更新”“已缓存”“规则”标签）；从任一标签点开哔哩哔哩、抖音、微博或 X 账号主页（及从该主页再进入单条详情）后，按顶部返回箭头逐级回到这个 `/subscriptions/:id` 并**保留原激活标签**（不退回订阅列表或重置标签）：
  - **内容**（默认）：这个订阅**全部关联账号**（含同时关联的哔哩哔哩、抖音、微博与 X 账号）已缓存内容的信息流（动态、视频、作品、微博、X 帖子与已录制的直播录像帖子），与主页时间线（及主页点进单订阅视图）共用同一套帖子渲染、虚拟化列表与滚到底自动加载更早内容，固定按发布时间（录像按开播时间）从新到旧排列，全程只读本机索引与清单、零站点网络请求；每条帖子右上角的“⋯”可“在资源管理器中显示”与“删除”，用来清理异常的缓存（含只有文字或图片的动态，DEC-064），删除后列表从最新处重新载入；没有已缓存内容时显示“还没有缓存这个订阅的内容”，并提示可在右上角“⋯”菜单点“检查更新”，不加额外强调色主按钮。
  - **账号**（合并原“直播”）：每个关联账号一行——第一行显示头像（优先使用本机头像副本，DEC-051 ⑥）、昵称、站点小字（“B 站”/“抖音”/“微博”/“X”）、UID、抖音号或 `@handle`；第三行是与“全部账号”相同的作品数（DEC-061 ②，微博显示“微博 N · 已缓存 M”，X 显示“帖子 N · 已缓存 M”，打开页面不发请求）；哔哩哔哩与抖音账号的第二行显示直播状态（未开通直播间 / 未开播 / 直播中“标题 · 清晰度与编码，如 原画 · AVC” / 录制中“已录 时长 · 大小”及清晰度编码），直播中或录制中时右侧放置“录制”（强调色主按钮）或“停止录制”按钮；**微博与 X 账号不显示直播状态、不出现录制按钮**。其余操作收进该行的“⋯”菜单（“打开主页”、“在浏览器中观看”（微博与 X 不含直播观看）、“用作头像”、“更改关联订阅”、“解除关联”、“刷新直播状态”（仅 B 站/抖音））。已录制的录像不再在这里重复列出（在“内容”标签里作为直播录像帖子出现）。底部保留“关联另一个账号：粘贴主页链接或 UID”输入框与预览确认卡片（未直播时确认按钮为该标签页唯一的强调色主按钮）。
- 删除订阅确认框：“删除订阅‘X’？只删除这个订阅和它的账号关联，不删除已缓存的内容，也不会在站点上取消关注。”按钮“确认删除订阅”与“取消”。

**从关注列表导入** `/subscriptions/import`：

- 顶部返回箭头与“从关注列表导入”；下面一行：站点切换（“哔哩哔哩 / 微博 / X”，未登录所选站点时提示先登录）、分组下拉（哔哩哔哩为全部关注、特别关注、各分组带人数；微博仅在服务端返回分组时显示分组下拉；X 无分组）和本页搜索框。
- 列表每行：复选框、头像、昵称、签名首行；已经属于订阅的账号复选框禁用，写“已在订阅‘X’中”。滚到底加载下一页，失败时底部显示原因和“重试”，已加载的保留。
- 底部固定一条操作栏：“已选 N 个”、“全选本页”、强调色“导入 N 个订阅”；导入完成后提示“已建立 N 个订阅，跳过 M 个”，并回到订阅列表。

### 3.10 托盘与退出（DEC-030）

- 托盘图标与应用图标用同一套图形画（`internal/brandicon`）：深灰底白色“T”，开发版与测试身份右下角带同样的琥珀色“DEV”角标、正式版没有；有任务或录制时右上角加一个琥珀色圆点（2026-11-22 用户反馈：原来右下角的琥珀色小块和开发版角标在托盘里看起来一样，开发版图标像是时有时无 DEV）；悬停提示“TRACE · 正在缓存 3 项 · 录制 1 场”或“TRACE”。
- 单击图标打开窗口（已打开就置前）；右键菜单只有“打开 TRACE”和“退出”两项（DEC-050），是在指针处打开的系统原生菜单（系统菜单字体，与图标之间没有空隙）；任务与录制的数量看悬停提示。有任务或录制时点“退出”先弹确认框（同下一条）。
- 窗口里退出（托盘菜单之外，例如设置“常规”里关闭行为为“退出”时点关闭按钮）：有任务或录制时弹确认框，写明会暂停几个任务、结束几场录制，按钮“退出”与“取消”。
- 第一次关到托盘时的系统通知：标题“TRACE 仍在后台运行”，正文“缓存、定时检查和录制会继续。可以从托盘图标打开或退出”。

### 3.11 我的（DEC-047）

登录账号自己在站点上的关注、收藏、稍后再看、历史等列表（FR-ACCT-001～005），在线浏览、只读。

**上下文侧栏**（≥ 1000 宽）：

- 顶部页名“我的”。下面四组，组头是站点名“哔哩哔哩”“抖音”“微博”“X”（14px，600），左边一个展开箭头（折叠向右、展开向下），右边是该站点登录账号的小头像（24px；未登录时是灰色“未登录”小字）。

- 展开后列出功能条目（图标 + 名称，选中项浅强调色底、强调色文字）：

  - 抖音：**关注**、**喜欢**、**收藏**，以及真实检查确认可用后才出现的**观看历史**（[Q-015](https://github.com/chialecode/trace/issues/22) 第 3 条）；
  - 微博：**关注**、**收藏**，以及真实检查确认可用后才出现的**赞过**与关注分组筛选（[Q-023](https://github.com/chialecode/trace/issues/22) 第 3 条，默认隐藏）；
  - X：**关注**、**书签**、**喜欢**，以及真实检查确认可用后才出现的**书签文件夹**与**列表**（[Q-024](https://github.com/chialecode/trace/issues/21) 第 9 条，默认隐藏）。

**页面**：

- 没有选中功能时（刚进入）：页面中间一句“在左侧选择一个站点和功能”，不发请求。窄窗（< 1000，没有侧栏）时页面本身列出与侧栏相同的四组与功能条目（同样默认折叠），选中后进入列表页，顶部栏左侧出现返回箭头回到这个列表。
- 顶部栏标题是“<功能名>”加站点小字（如“收藏夹 · B 站”），右侧是一个“⋯”（“刷新”“在浏览器中打开”——打开站点上对应的页面）。

## 5. 视觉（DEC-039）

参考 Cindy 设计系统的做法：靠底色深浅与 1px 细线分区，基本不用阴影（只有浮动菜单和弹窗有）；一种强调色。DEC-046 ③：内容区是白色，图标栏与侧栏是更通透的中性浅灰（不偏暖、不偏黄）；输入框、卡片、对话框尽量白底加细线，不出现白、灰、白层层嵌套，也不用大面积灰卡片；浅灰底只留给图片占位、小提示与选中的分段按钮。色值是 TRACE 自己的，不用任何站点或应用的品牌色。

| 用途 | 值 |
| --- | --- |
| 页面（也用于输入框、卡片、控件） / 侧栏与图标栏 / 占位与小提示 | `#ffffff` / `#f7f7f7` / `#f4f4f4` |
| 主文字 / 次要文字 / 更淡 | `#262626` / `#6b6b6b`（白底 5.3:1，侧栏灰底 4.9:1） / `#a3a3a3` |
| 分隔线 / 控件描边 | `#ececec` / `#dcdcdc` |
| 悬停底 | `rgba(38, 38, 38, 0.06)` |
| 强调色（默认蓝） | `#1a73e8`，悬停 `#1765cc`，按下 `#1557b0`，浅底 `#e8f0fe`；白字对比度 4.5:1。用于主按钮（解析、检查更新、录制、验证并登录等）、选中的图标栏与侧栏条目、标签下划线、焦点环、“N 条更新的内容”提示、任务角标 |
| 强调色（绿色预览，[Q-011](https://github.com/chialecode/trace/issues/23)） | `#0a8754`，悬停 `#08744a`，按下 `#066340`，浅底 `#e6f4ec`；白字对比度 4.6:1。环境变量 `TRACE_UI_ACCENT=green` 启动或截图场景 `home-green-accent` 预览 |
| 直播 | `#c2410c`（白字对比度 5.2:1），浅底 `#fff1e8`：“直播中”标记、直播横幅描边、头像外的直播圆环、图标栏订阅上的小点。不用强调色，免得和主操作混淆 |
| 状态圆点 | 直径 8px 纯色：绿 `#2aae5b`、黄 `#f3a115`、红 `#d91f37`；缓存中是蓝色进度圆环 |
| 主按钮 | 强调色底、白字、胶囊形；次按钮白底灰描边；禁用时 50% 透明；每个区域最多一个主按钮 |
| 错误 | `#c4182e`，浅底 `#fdf0f1`，同时配图标和文字，不只靠颜色 |
| 头像占位色 | 蓝、青绿、靛、琥珀、绿、青、紫、石板灰八色按 UID 或名称固定选取，不用粉色 |

- 字体：**Inter**（4.1 可变字体，随程序打包，`internal/ui/fonts/`，SIL OFL 1.1）；中文等 Inter 没有的字由系统字体补上（Windows 为微软雅黑）。系统无法加载字体时用系统字体。字重：正文 400，导航与条目 500，标题与强调 600，只有字标用 700。字号：正文 14px，次要 12～13px，页面标题 18px，侧栏标题 18px。多行文本行高集中定义于 `internal/ui/theme.go`：`LineHeightBody = 1.6`（帖子/动态/转发/详情多行正文，提升中英文混排可读性）、`LineHeightCompact = 1.45`（多行标题、简介、卡片摘要与提示文案）、`LineHeightHeading = 1.35`（18～20px 详情主标题及紧凑双行网格标题）；单行标签、胶囊按钮与工具栏控件不加行高倍增以保持高度一致。日志与诊断代码框使用等宽字体。
- 圆角：按钮和输入框为胶囊形，卡片与浮动菜单 12～16px，媒体库缩略图 14px，帖子封面 12px，侧栏条目 8px，图标栏按钮 12px。
- 图标统一使用 `internal/ui/theme.go` 的 `DrawIcon` 线性图标绘制，描边粗细一致，不绘制任何同心圆靶子形图标（DEC-033）：

<a id="states"></a>
## 6. 状态

每个页面都要覆盖：加载中（骨架屏，不用整页转圈）、空状态（告诉用户下一步做什么）、错误（按错误类别给一句说明和下一步按钮，[错误分类](research/bilibili.md#errors)；X 未登录写“请先登录 X”，限流写明预计恢复时间，验证或临时锁定写“X 要求验证或账号被临时锁定，TRACE 已停止 X 的全部自动请求，请先在浏览器里处理”）、部分成功（列表已加载的部分保留，底部显示错误和“重试”）、到底（明确说明没有更多）。

<a id="accessibility"></a>
## 7. 可用性

- 键盘：Tab 顺序合理，焦点环可见；Esc 关闭弹层；输入框按回车提交（组合输入时除外）；看图层左右键切换、`+`/`-` 缩放、`0` 适应窗口。
- 图片有替代文字；只显示图标的按钮有无障碍名称和悬停提示；状态圆点有文字名称。
- 长中文标题按行截断，不撑破布局；数字用“万”“亿”缩写（如 12.3万），悬停显示精确值。
- 界面截图只证明看到的状态；后台行为、键盘和输入法要分别验证。
