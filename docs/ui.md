# 界面规范

依据 DEC-039：窗口由**图标栏、上下文侧栏、页面**组成，类似桌面聊天与素材库应用；视觉参考 Cindy 设计系统的细分隔线与 Inter 字体，底色是白色内容区加通透的中性浅灰侧栏（DEC-046 ③），强调色是一种清新的蓝（可预览绿色）。只借鉴布局、字体和配色方法，不复制任何站点或应用的标识、图标与品牌色。需求见[需求](requirements.md)，实现约束见[技术设计](design/architecture.md#frontend)。

## 1. 窗口布局（DEC-039）

| 宽度 | 图标栏 | 上下文侧栏 | 页面 |
| --- | --- | --- | --- |
| ≥ 1280 | 52px | 272px（有侧栏的页面） | 其余宽度 |
| 1000～1279 | 52px | 240px | 其余宽度 |
| 720～999 | 52px | 不显示（设置除外，只显示图标的 72px） | 其余宽度 |

- **沉浸式标题栏**（DEC-046 ④）：窗口不画系统标题栏，图标栏、侧栏和页面都延伸到窗口顶部；系统的最小化、最大化、关闭按钮保留在右上角，盖在页面上。页面顶部栏右侧给这些按钮让位（按 MyGo `TitleBar()` 的宽度），图标栏和侧栏顶部一条与按钮同高的区域、以及页面顶部栏的空白处都可以拖动窗口，双击最大化。看图层与播放层的面板上边距不小于按钮高度加 8px；全屏时没有这些让位。
- **图标栏**（最左，浅灰底 `#f7f7f7`）：只放图标，名称在悬停提示与无障碍名称里，见[第 2 节](#nav)。
- **上下文侧栏**（`#f7f7f7` 底，细分隔线）：当前页面里“看什么”的选择，像素材库的文件夹或聊天应用的会话列表。顶部是页面名（18px，600），下面是条目（图标或头像 + 名称，选中项浅强调色底、强调色文字），分组标题用 12px 灰字：
  - **主页**：“全部动态”；“有更新”（有新内容的订阅与 UP 主，点进只看此人的时间线，选中项高亮）；“正在直播”（最多 8 行，头像橙色圆环、名称、直播标题或“录制中 · 标题”，点击进入用户页，在直播横幅上录制）。
  - **订阅**：“全部订阅”（头像网格）和全部订阅的列表（虚拟滚动，直播中的头像带橙色圆环），点一项打开订阅详情。
  - **媒体库**：类型（全部 / 视频 / 图片 / 直播录像）；“来源”（全部来源、各订阅、不属于订阅的 UP 主）；底部一行“N 项 · 占用大小”。
  - **视频页与用户页**：“最近解析”，在解析过的对象之间切换，当前对象高亮。
  - **设置**：设置分类，见[第 3.7 节](#settings)。
  - 解析页、任务页与登录页没有上下文侧栏。
- **页面**：白底。顶部栏（不随内容滚动）左边是返回箭头（需要时）与页面标题（18px，600），右边是**快速解析框**（链接图标 + “粘贴链接或 UID 解析”，在任何页面都能用，结果在页面里打开）和该页的操作；页面较窄时快速解析框换到标题下一行。解析页、设置页、登录页不显示快速解析框。帖子、视频与用户详情、解析页限宽 680px 居中；媒体库网格、任务列表、订阅头像网格用满宽度；设置限宽 860px。
- **图标栏与上下文侧栏固定**：只有页面随内容滚动（NFR-UI-001）。窄窗没有侧栏时，主页的“有更新”退回为时间线上方一行头像，媒体库的类型与来源退回为页面里的标签与“作者筛选”。
- 不再有右栏：快速解析框在顶部栏；缓存与录制的数量在图标栏“任务”的角标；正在直播在主页侧栏。
- **更新提示**（FR-UPD-003）：正式版有更新时，任何页面的顶部栏下方出现一行浅蓝底的提示，不打断当前操作：“新版本 0.1.2 已就绪 · 更新内容 · 重启以更新”（自动下载关着时是“有新版本 0.1.2 · 更新内容 · 下载并安装”），右端一个关闭按钮（这次运行不再出现）。点“更新内容”在这一行下方展开这一版的说明（`CHANGELOG.md` 的那一节，按行显示），再点“收起更新内容”。点“重启以更新”：没有缓存与录制时直接重启；有时先弹确认框“重启以更新”，正文“重启会暂停 N 个缓存任务并结束 M 场录制，重启后可以继续缓存。”，按钮“重启以更新”“取消”。更新后第一次启动显示一次“已更新到 0.1.2 · 更新内容”，可以关掉。
- **数据来自更新的版本**：启动时发现数据文件来自更新的 TRACE（例如装回了旧版本），弹一个系统对话框“这些数据来自更新的 TRACE 版本，请安装新版”，确定后退出，不打开窗口、不改动任何数据。

## 2. 图标栏

- 顶部是 TRACE 字标“T”（DEC-046 ② 起不带点），点击回到主页。
- 导航项（DEC-022、DEC-026）是 40px 圆角方块里的线性图标（描边 1.6，选中 2），悬停浅灰底，选中浅强调色底、强调色图标：
  1. **主页**：已缓存内容的信息流。
  2. **订阅**：被追踪的人（[第 3.9 节](#subscriptions)）；有订阅正在直播时图标右上角一个橙色小点（不做未读数字角标，DEC-033）。
  3. **解析**：粘贴链接或 UID。
  4. **媒体库**：已缓存的图片、视频和直播录像。
  5. **任务**：缓存任务与直播录制；有排队、进行中或录制中的任务时，右上角显示强调色小数字（只数这三种）。
- 底部固定当前账号的小头像（悬停显示昵称和 `UID`，点击进入账号设置，未登录时进入登录页）和**设置**（齿轮图标）。
- 不显示做不了的功能入口。

## 3. 页面

通用：

- **整洁原则**（DEC-037、DEC-038）：同类条目（帖子、投稿、最近解析、媒体库条目、录像）**点本体完成常用动作，其余操作收进一个“⋯”更多菜单；每个区域最多一个主按钮**，不堆砌文字按钮。
- **“⋯”菜单是浮在按钮旁边的弹出菜单**（白底圆角、阴影，在按钮下方右对齐，没有空间时翻到上方；点外面或按 Esc 关闭，键盘可用），菜单项不占页面空间、不推开下面的内容；危险操作（删除）用红字并与其他项用分隔线隔开。不要用在页面里展开一排胶囊按钮的方式代替菜单。
- **点开即跳转**（DEC-038）：从帖子、投稿、头像、最近解析打开视频或用户页时，立刻切换到目标页面，先显示卡片上已有的标题、作者和封面，并显示“正在打开…”；读取完成后填入完整内容。失败时在该页面显示原因和“重试”。后点的覆盖先点的，已经离开的页面不会被迟到的结果拉回。
- **顶部栏**：返回箭头、页面标题、快速解析框与页面操作，不随内容滚动；页面里的标签选中项下方是一条强调色粗短线。
- **帖子**（主页信息流、订阅详情、用户页动态共用 `PostCard`，DEC-037）：左边圆形头像（点击进入用户页），右边第一行“昵称 · 发布时间 · 类型”和右上角的[状态圆点](#status-dot)（主页不画，DEC-046 ⑦）；正文（超过 6 行折叠，可展开）；图片像站点上那样尽量完整显示（DEC-040）：1 张时按原比例完整显示（竖图高 360px、宽按比例，横图最宽 480px，比例限制在 1:2 到 2.4:1 之间），2 张或 4 张排两列、其他排三列的正方形格子（最多显示 9 张，多出的在最后一格写“+N”），实况照片左上角标“实况”，图片没加载出来时是浅灰底块，不写文字；点击图片打开[看图层](#viewer)。视频是一张横向卡片：左边 200px 宽的 16:9 封面（右下角时长），右边标题（最多两行）、简介（最多两行）和清晰度规格；不显示播放数、评论数这类会变的数字，也不缓存它们；点卡片任意位置播放（已缓存时在播放层播放本机文件）；转发在白底细线圆角框里显示原动态摘要；不支持的类型显示类型名说明。
  - **在主页信息流（含单个订阅视图）中**：帖子下方**不放任何文字按钮**（不显示“内置播放”“查看图片”“补存弹幕和字幕”“浏览器打开”“复制链接”“查看封面”等），直接点视频画面播放、点图片看图、点头像或昵称进用户页。
  - **在订阅详情、用户页与动态详情中**：帖子同样**没有文字按钮**；右上角状态圆点旁一个“⋯”，菜单依次是“缓存”（仅未缓存时）、“在浏览器中打开”“复制链接”（DEC-038）。点未缓存视频的画面打开视频详情。条目之间用细线分隔，不用卡片阴影。

### 3.1 主页：信息流（DEC-023、DEC-037）

- 顶部栏标题“主页”；始终按从新到旧（最新在上）排列，不提供“最新在前 / 最早在前”切换（DEC-037）。
- **有更新**（DEC-037、Q-009、DEC-039）：主页上下文侧栏的“有更新”分组（窄窗没有侧栏时是“主页”标题下方一行可横向滚动的圆形头像，直径约 56px，下方一行名称，过长省略；没有任何更新时整组隐藏），列出在上次使用时看过的最新内容之后又有新缓存内容的订阅（不属于任何订阅的创作者按 UP 主单独列出），按最新缓存内容的发布时间从近到远排列。
  - 点击某个头像，进入**只含该订阅（全部关联账号）已缓存内容的信息流视图**：顶部栏显示返回箭头、头像与订阅名称，下方从新到旧列出该订阅的已缓存帖子（同样使用无底部按钮的主页 `PostCard`）；点击返回箭头回到主时间线原来的位置。
  - 按 [Q-009](../USER-ACTIONS.md#q-009) 默认口径：成功打开后把该订阅的“已看到”时间记为其最新缓存内容的时间戳，头像从该行消失，直到该订阅又有更新的缓存内容；只按订阅/创作者记一个时间戳，不按单条记已读。读取失败保留主时间线，保存失败显示原因；返回主时间线时保留条目和行内偏移。
- 内容是所有已缓存的动态、直接缓存的视频和直播录像，不分作者，按发布时间（录像按开播时间）从新到旧排列，每条是一个帖子；录像帖子显示“直播录像”与清晰度编码规格。已缓存的视频卡片点击后在播放层播放本机文件；图片点击打开看图层看本机原图。
- 主页每次打开都从最新处开始，不恢复上次的位置，也不提示“N 条更新的内容”；往上翻过的就是看过了，不会因为往下滑又被当成未读（DEC-040）。看过的最新一条的发布时间会被记下，只作为下次启动时“有更新”的比较基准。有新缓存的内容时，回到列表顶部会载入它们，当前看到的条目不跳动。
- 抖音的作品同样是帖子（DEC-043）：视频作品按视频卡片（竖版封面在左、文案在右），图文作品按图文帖子显示图片，并在图片下方显示配乐条（[§3.4](#douyin-pages)）；作者行带站点小字。主页上下文侧栏“全部动态”下面有站点筛选“全部 / B 站 / 抖音”（窄窗时是时间线上方的三段式切换），默认“全部”，记在 `ui-state.json`（FR-SITE-002）。
- 底部到头时显示“已经到最早的缓存了”。
- 分页读取失败保留帖子并显示“重试”，等待用户重试；查看时间保存失败显示原因，“看最新”失败仍停在原位置。主页缺少本机图片时使用占位图，不自动补发远程图片请求。
- 空状态：“还没有缓存的内容。到‘解析’里打开一位 UP 主或抖音作者，在动态或作品上点‘缓存’”，带一个去解析页的按钮。

<a id="parse"></a>
### 3.2 解析页（DEC-022、DEC-033、DEC-037）

- 顶部栏标题“解析”；解析页只显示与解析有关的内容，不显示“正在加载”“正在重建索引”等与解析无关的后台状态（DEC-033）。
- 输入框（类似“有什么新鲜事？”）：左边是当前账号头像，占位文字提示可粘贴哔哩哔哩或抖音的视频/图文/直播链接、分享文本、用户主页或 UID/`sec_uid`，右下是强调色胶囊按钮“立即解析”。按回车解析；输入法正在组合输入时按回车不提交。解析中按钮显示“解析中…”并禁用。识别失败在输入框下面用一句话说明。
- 输入框下面是“最近解析”列表（DEC-037）：
  - 解析成功后，封面与头像缩略图缓存到本机数据目录 `<DataDir>/thumbs/`（不进媒体库，不带 Cookie、不带外站 Referer，地址过白名单，大小有上限，文件名不含签名参数；未缓存到媒体库的条目也能显示封面与头像，失败时显示占位图而不是空白）。
  - 列表标题“最近解析（N）”右侧只放一个“⋯”按钮，展开“全部清空”（点击后在行内确认再执行，同时清理无引用缩略图）。失败显示原因并保留确认，缩略图清理的恢复契约见[数据设计](design/data-and-cache.md#storage)。
  - 每条条目（头像、“昵称 · 类型 · ID”、标题；视频条目带 16:9 封面与时长）**点击条目本体直接打开**，去掉独立的“打开”“复制链接”等文字按钮；右侧只放一个“⋯”按钮，展开“在浏览器中打开”与“删除”（删除单条时一并删除对应本机缩略图）。
- 空状态：“粘贴一个链接开始”。

<a id="status-dot"></a>
### 3.3 状态圆点（DEC-024）

帖子、投稿条目和视频详情页显示一个直径 8px 的纯色小圆点（DEC-039；媒体库和主页不显示，主页只列已缓存的内容，DEC-046 ⑦）。**一条帖子只有一个圆点**，表示动态和其中的图片、视频合起来的状态：都缓存完整才是绿色，其中有缺的（例如视频只缓存了一部分）就是黄色，图片和视频卡片上不再各自显示圆点；视频详情页的圆点在“缓存视频”按钮旁，封面上不显示，配合“缓存”操作（帖子与投稿在“⋯”菜单里，视频详情页是“缓存视频”按钮）：

| 状态 | 圆点 | 按钮 |
| --- | --- | --- |
| 未缓存 | 不显示 | “缓存”（下载线性图标） |
| 排队 / 缓存中 | 蓝色进度圆环 + 悬停显示百分比 | 禁用，悬停显示“正在缓存” |
| 已缓存（最高档） | 绿色小圆点 | “已缓存”，点击进入媒体库对应条目 |
| 部分缓存 / 已暂停 / 可升级 | 黄色小圆点 | 部分：“补全”；暂停：“继续”；可升级：“升级缓存”。悬停列出缺什么、为什么，或“可升级到 4K（当前 1080P）” |
| 失败 / 文件缺失 / 清单损坏 | 红色小圆点 | “重试”或“删除记录”；悬停显示原因 |

圆点里不画对勾、短横等符号；含义靠悬停提示和无障碍名称（如“已缓存，1080P 高码率，最高档”“部分缓存”）给出，不只靠颜色。

<a id="detail"></a>
### 3.4 视频详情与用户页

- **视频详情页**：顶部返回箭头与“视频”；UP 主行（头像与昵称，点击进入空间；右侧“缓存视频”主按钮与状态圆点）；标题（大号）；大封面（已缓存时点击播放本机文件）；简介（超过 6 行折叠）；发布时间、分区；统计行（图标加数字）；多 P 列表（已缓存时每 P 显示实际清晰度，如“1080P 高码率 · AV1 · 杜比全景声”）。已缓存的视频在详情页集中提供缓存维护操作（DEC-037，可从媒体库条目右下角“⋯ → 详情”进入）：探测到更高档时，标题上方显示黄色横幅与“升级缓存”按钮；同时在详情操作行提供“补存弹幕和字幕”按钮。
- **站点标记**（FR-SITE-002，DEC-043）：用次要文字色、12px、无底色的小字“B 站”“抖音”，紧跟在作者名或元信息后面（中间一个“ · ”）。出现在用户页头部、订阅详情“账号”列表、主页帖子作者行、媒体库卡片的元信息行、任务行、最近解析条目；订阅网格的头像不加。不使用站点的图标与品牌色。
- **本机内容详情**：从媒体库进入时只读本机清单和媒体，缺图用占位图。视频保留已知未完成分 P 的选择，不显示互动数据（播放数等会变，不缓存，DEC-040），未知时长不冒充 0；用户点“缓存视频”时重新获取站点元数据。动态详情保留本机图片和引用视频卡片；直播录像显示“直播录像详情”、直播间、清晰度与片段播放，浏览器入口指向直播间，不提供点播视频的缓存、补存或分 P 勾选。
- **用户页**：横幅（带头像、昵称、`UID`、等级）；下面一行“关注 N · 粉丝 N · 投稿 N”，右侧只有一个订阅按钮（未订阅时强调色“订阅”，已订阅时“已订阅”，点击进入所属订阅）和一个“⋯”（“缓存更早的内容”，“在浏览器中打开空间”，直播中另有“在浏览器中观看直播”）；签名；标签栏为“动态”（默认）和“投稿”，标签不带数字，标签栏右侧是筛选“全部 / 未缓存”。动态是帖子；投稿是缩略图在左、标题和时长/播放数在右的紧凑行，点行打开视频，“缓存”“在浏览器中打开”在行右侧的“⋯”里。**整个头部是列表的第一行，随内容一起滚走**，窗口矮时也能看到内容（DEC-038）。两种列表都滚动到底自动加载。
  - **只看未缓存**（DEC-046 ⑧）：筛选只作用于已加载的页，切换不请求站点；之后加载的页同样按筛选显示。已加载的都缓存了时显示“已加载的内容都缓存了”和“加载下一页”按钮，不自动连翻。
  - **缓存更早的内容**（DEC-046 ⑥）：“⋯ → 缓存更早的内容”里选一次的条数“10 条 / 20 条（推荐）/ 50 条”。从当前列表（动态或投稿）的最新一条往更早的方向，只把未缓存、也不在缓存中的条目排进现有下载队列；已加载的页不再请求，之后的页按需翻（一次最多翻 8 页）。翻页与入队按自动请求处理，计入站点的每小时额度、遵守退避；遇到风控、限流、额度用完或退避就停止剩余入队。结束后顶部提示“已把 N 条更早的内容加入缓存队列，跳过 M 条已缓存或不能缓存的”，停止时附原因，到底时写“已到列表末尾”。
  - 正在直播时，签名下方出现一条直播横幅：橙色“直播中”标记、直播标题（悬停显示房间号）与清晰度编码（如“原画 · AVC”），右侧只有一个按钮“录制”（录制中变为“停止录制”，DEC-033、DEC-038）。

<a id="douyin-pages"></a>
- **抖音用户页**（FR-DY-004，DEC-043）：结构同上，差别只有内容：横幅位置用中性色块（抖音没有横幅），头部是头像、昵称、小字“抖音”、抖音号；“关注 N · 粉丝 N · 获赞 N · 作品 N”；签名；**只有一个“作品”列表**（不显示标签栏）。作品是网格：竖版 3:4 封面卡片（视频右下角时长，图文左上角“图文”、置顶的左上角“置顶”角标），每行按宽度 3～5 个，点卡片打开作品详情，“缓存”“复制链接”“在浏览器中打开”在卡片右下角的“⋯”里，卡片右上角是状态圆点。私密账号写“这个账号是私密账号，不能浏览作品”。“作品”标题右侧有同样的“全部 / 未缓存”筛选，“⋯”里有同样的“缓存更早的内容”（私密账号没有）。直播横幅同上。
- **抖音作品详情**（FR-DY-003）：版式同视频详情。视频作品：作者行（头像、昵称、小字“抖音”，右侧“缓存视频”主按钮与圆点）；文案首行作标题，其余作正文（话题用强调色文字）；竖版封面按原比例、最大高度为页面可见高度的 70%，已缓存时点击播放；发布时间、时长；统计行只有点赞、评论、收藏、分享（没有播放数）；配乐一行“♪ 标题 · 作者”。图文作品：同样的作者行与文案，各页按帖子规则显示（一张按原比例，多张为正方形格子；实况照片标“实况”；视频页显示封面，中间一个半透明圆形播放标记，右下角时长），点任何一页打开看图层；图片下方是**配乐条**：圆形播放/暂停、“♪ 标题 · 作者”、进度与时长；没缓存时播放在线配乐，已缓存时播放本机文件，取不到时配乐条显示原因并禁用。已缓存的作品详情集中提供本机信息（实际清晰度与编码，如“1080P · HEVC”）；没有升级、补存弹幕字幕的操作。

<a id="viewer"></a>
### 3.5 看图层（DEC-033）

- 点击任何图片打开看图层：一个浮在应用上方的深色圆角面板（四周留边，背后的应用变暗，点面板外面关闭；DEC-040），默认按面板适应显示**原图**（已缓存的用本机文件，否则用去掉尺寸后缀的原图地址）。
- 滚轮、快捷键（`+` / `-` / `0`）或双击缩放，按住拖动平移；只保留少量半透明圆形悬浮按钮：右上角**关闭**，左右两侧**上一张 / 下一张**，底部居中**适应窗口 / 原始大小（1:1）**，左上角轻量胶囊显示“当前 / 总数 · 缩放百分比”。
- 鼠标静止约 2 秒后悬浮控件自动隐藏，鼠标移动或按键时重新出现；左右键切换同一条动态里的图片，Esc 关闭。
- 实况照片在底部多一个圆形“播放”按钮，在看图层里原地播放它的动态片段（DEC-040、DEC-046 ①）：已缓存的播放本机片段，没缓存的先从站点取到临时文件再播放（哔哩哔哩与抖音都一样），不跳到播放层。
- 抖音图文的视频页在看图层里直接播放（点画面暂停/继续，底部一条细进度条与时长，没缓存时播放在线地址）；切到别的页时停止。视频页或实况片段播放时，配乐条暂停，停止后不自动恢复。

<a id="library"></a>
### 3.6 媒体库与任务

- **媒体库**（图标栏“媒体库”，DEC-037、DEC-039）：顶部栏标题“媒体库”（“重建索引”在设置“存储”）；类型与来源在上下文侧栏（窄窗时退回为页面里的标签“全部 / 图片 / 视频 / 直播录像”和“作者筛选”）；页面里一行搜索框与排序（发布时间 / 缓存时间）。来源分组里加站点筛选“全部 / B 站 / 抖音”，与类型、作者筛选叠加（FR-SITE-002）。
  - 网格：卡片约 240px 宽，按页面宽度每行 2～6 个；**16:9 圆角缩略图**（圆角 14px），视频右下角显示时长、正中播放图标；**不显示状态圆点**（媒体库里都是已缓存的内容，DEC-039）；缩略图下方是**最多两行的标题**（14px，600）、一行元信息（作者名，直播录像附清晰度与编码如“原画 · AVC”）和右侧一个“⋯”按钮。虚拟滚动，滚到底继续加载。
  - 点击缩略图或标题直接打开对应文件的看图层或**播放层**（DEC-033、DEC-037），不按网格位置猜测分 P；点击右下角“⋯”展开菜单：**详情**（所属动态、视频或直播录像的本机详情）、**在资源管理器中显示**、**删除**。播放层和看图层一样是浮在应用上方的深色圆角面板（点面板外关闭；全屏时铺满窗口），**打开即自动播放**（DEC-040），底部悬浮条只保留圆形**播放/暂停**、**进度条**、**音量**、**全屏**，右上角保留圆形**“⋯”更多菜单**与**关闭**。音量按钮展开 0～100% 滑块与静音开关；全屏作用于原生窗口，切分段保持全屏，关闭播放或登录失效时恢复。**弹幕**（开关、透明度滑块 20%～100%、显示区域上方 1/4 / 上半屏 / 全屏、密度低/中/高/不限）、**字幕**（语言选择与关闭）、**分段切换**（多 P 或多段直播录像的“上一段 / 下一段”）、**在文件夹中显示**、**用系统播放器打开**统一收进“⋯”菜单。鼠标静止约 2 秒后悬浮控件自动隐藏，鼠标移动或任意按键时重新出现；菜单打开时保持控件可见。音量、静音、弹幕与字幕偏好记住并沿用，保存失败显示原因。
  - 每个条目的“删除”打开确认弹窗：写明预计清理的已登记缓存文件数与大小；共用视频时说明“这个视频还被 N 条动态引用，将保留视频文件”；删除后文件夹里还有非 TRACE 文件时提示“已保留 N 个不是 TRACE 创建的文件”。
  - 空状态：“还没有符合筛选的媒体。缓存图片、视频或直播录像后，它们会出现在这里”。
- **任务**（图标栏“任务”）：顶部栏标题“任务”，右侧“检查画质更新”按钮（执行时显示“检查 M / N · 取消”）；存在已结束（已完成 / 已取消）的任务时，列表右上角提供“清除已结束（N）”按钮。每行是对象缩略图、标题、进度条与“已下载 / 总大小”、状态文字和操作（进行中/排队可暂停或取消；已暂停可继续；失败/部分完成可重试或移除；已完成/已取消可移除，不能取消；DEC-033）。失败原因（`LastError`）直接显示在任务行内；移除失败或部分完成的任务前，行内弹出确认提示“确认移除该任务？会删除未完成的临时文件，已缓存完成的文件会保留”。点“展开详情”（FR-CACHE-009）显示逐文件进度清单与脱敏后的分段重试记录。
  - **直播录制**排在任务页最上面：主播头像、直播标题、橙色“录制中”标记、已录时长、大小、速度、段数与清晰度编码（如“原画 · AVC”），右侧“停止录制”。

<a id="settings"></a>
### 3.7 设置页（DEC-019）

打开设置时，**上下文侧栏是设置的分类**（DEC-038、DEC-039），图标栏不变：

- 侧栏最上面是返回箭头加“设置”（回到进入设置前的页面），下面是分类，只有**图标 + 名称**，不带说明小字；选中项浅强调色胶囊底、图标和文字强调色。宽度 ≥ 1000 时侧栏约 232px 显示名称，更窄时 72px 只显示图标（悬停有提示，带无障碍名称）。
- 内容区顶部栏标题就是分类名，下面直接是设置项，不再重复分类标题。
- 路径 `/settings/<分类>`，默认“账号”；分类列表以后可以加搜索框，现在不做。
- 设置内容不套卡片：分组和设置项之间只用细线分隔，不出现白、灰、白层层嵌套的框；侧栏条目文字 14px（DEC-040）。
- 每个设置项一行：名称 + 当前值 + 操作，用细线分隔。**设置项默认没有说明小字**；只有需要提醒后果或限制的具体设置才有一行说明（如“关闭窗口时”“定时检查更新”“缓存保存位置”）。下拉框显示中文选项名（如“能拿到的最高（推荐）”“最小化到托盘（推荐）”），不显示内部值。改动立即保存，保存失败在该行下方显示原因。
- 分类：
  - **账号**（FR-AUTH-007）：按站点分成两组，组标题“哔哩哔哩”“抖音”，组之间细线分隔。抖音一组：已登录时头像、昵称、抖音号、“登录方式：粘贴 Cookie”、“自动续期：不可用，粘贴的 Cookie 与浏览器共用会话；过期后请重新粘贴”、“重新粘贴”“退出登录”（确认里说明会暂停抖音的缓存任务和录制，哔哩哔哩不受影响）；未登录时一个“登录抖音”按钮，打开登录页并预选抖音。哔哩哔哩一组如下：头像、昵称、`UID`、登录方式（扫码 / 手动凭证）；“自动续期”（扫码登录：“可用 · 上次续期 11 月 7 日 08:30”，失败时附原因；粘贴凭证：“不可用：粘贴的 Cookie 与浏览器共用会话，续期会让浏览器那边掉线。过期后请重新粘贴，或改用扫码登录”）；“重新登录”“退出登录”（退出时确认，说明会暂停缓存任务和录制）。
  - **缓存与下载**：保存位置（路径 + “更改”，说明“只影响之后的缓存”）；同时下载数（1～4）；缓存弹幕（开关）；缓存字幕（开关）；包括 AI 字幕（开关，缓存字幕关闭时禁用）。
  - **画质与音质**：视频清晰度（能拿到的最高（推荐）/ 不超过 4K / 1080P / 720P）；编码偏好（顺序：AVC 兼容性最好 / AV1 / HEVC，HEVC 注明“部分电脑无法在应用内播放”）；音质（能拿到的最高（推荐）/ 192K）；多 P 视频（全部分 P / 只缓存第 1 P）；打开已缓存视频时检查画质更新（开关）。
  - **缓存规则**（DEC-040）：所有订阅共用的规则列表。每条规则一行：名称、摘要（如“定时检查 · 自动缓存视频、图文 · 开播录制”）与“N 个订阅”；点一行在原地展开编辑：名称、定时检查、自动缓存新动态（只缓存选用这条规则之后发布的动态）及类型（视频 / 图文 / 文字 / 转发）、开播自动录制，“保存”“取消”，非默认规则另有红字“删除”（用这条规则的订阅改用“默认”）。列表下方“新建规则”。“默认”规则不能删除，初始为“定时检查，不自动缓存，不录制”。改一条规则，所有用它的订阅一起改。
  - **订阅与直播**：定时检查更新（开关，说明“只在 TRACE 打开时检查；遇到风控会自动放慢”）；检查间隔（30 分钟 / 1 小时 / 2 小时 / 6 小时，定时检查关闭时禁用）；上次与下次检查时间，退避按站点分行写，如“抖音：因风控放慢到 1 小时，11 月 7 日 12:00 恢复”；开播检查间隔（1～30 分钟，说明“只在有订阅开启开播自动录制时运行”）；同时录制数（1～4）。
  - **存储**：安装位置、数据目录、缓存位置（只读路径 + “打开文件夹”、“重建索引”，缓存位置的修改也在本页）；显示当前是正式版还是开发版；媒体库占用空间；“添加已有的缓存文件夹”（选择文件夹后显示“接入了 N 条，跳过 M 条（已存在）”，说明“文件留在原处”）。
  - **常规**（滑杆图标）：关闭窗口时（最小化到托盘（推荐）/ 退出），说明“最小化到托盘时，TRACE 会释放界面占用的内存，缓存、定时检查和录制在后台继续”。
  - **网络**（链接图标，DEC-046 ⑤）：“代理”下拉框：跟随系统（推荐）/ 不用代理 / 自定义，说明“站点接口、缓存下载和直播录制都走这里的设置，改动立即生效”。跟随系统时下面一行小字“使用 Windows 的代理设置（含自动配置脚本）；设置了 HTTP_PROXY / HTTPS_PROXY 环境变量时以环境变量为准”。选“自定义”后出现地址输入框（`http://`、`https://` 或 `socks5://`，只写协议、主机和端口，没写协议按 `http://`；带账号密码的地址不接受，红字提示改用不需要登录的本机代理）与“保存”按钮；地址通过检查才改用，不通过时在框下红字说明原因。
  - **日志**（终端/日志图标，DEC-033）：上方“后台状态”卡片显示索引重建、检查更新、自动缓存、直播录制的当前情况；下方“最近运行日志”卡片以等宽字体显示脱敏后的最近运行日志（最多 500 行，经服务层接口读取，不含任何 Cookie 或签名 URL），右上角提供“打开日志文件夹”和“复制”按钮。
  - **关于**（FR-UPD-001、FR-UPD-003）：应用名（TRACE / TRACE Dev）；“版本 0.1.1（正式版）”或“版本 0.1.1-dev.202611091530（开发版）”；“提交 1a2b3c4d5e6f · 构建于 2026-11-09 15:30 UTC”。正式版接着一行更新状态：左边是状态文字（“已是最新版本”“正在检查更新…”“正在下载新版本 0.1.2（35%）”“新版本 0.1.2 已就绪”，失败时红字如“更新包校验失败，已保留当前版本”）和“上次检查：2026-11-09 16:00”（没检查过写“还没有检查过”），右边一个按钮：平时“检查更新”（检查中“正在检查…”不可点），有新版本而没下载时“下载并安装”，已就绪时“重启以更新”；下面两行开关“自动检查更新”“自动下载更新”（默认开，改动立即保存）。开发版这一行写“开发版由本机打包自动更新”，没有按钮与开关；没有联网更新的构建写“这个构建没有联网更新”。最后是诊断概览与第三方开源许可说明。

<a id="login"></a>
### 3.8 登录页

一个站点都没登录时唯一可进入的内容页（设置页除外）；已登录一个站点后也可以从设置或“请先登录”提示进入，来登录另一个站点。居中一张卡片，最上面是站点切换（两段式切换“哔哩哔哩 / 抖音”，从提示进入时预选对应站点），标题“登录哔哩哔哩”或“登录抖音”，说明“TRACE 需要登录后才能解析和缓存”。

**抖音**只有“粘贴凭证”一种方式（FR-DY-001）：说明怎样在浏览器打开抖音网页、登录后从开发者工具复制请求里的 Cookie（只写步骤，不放截图）；单行密码型输入框，占位“粘贴 Cookie（至少包含 sessionid）”；“验证并登录”；结果一句话：成功显示头像、昵称、抖音号后进入应用，失败写原因（“缺少 sessionid”“抖音认为这个 Cookie 没有登录或已过期”“抖音要求验证，请先在浏览器里正常打开一次抖音再复制”）。提交后输入框立即清空。

**哔哩哔哩**下面两个标签：

- **扫码**：二维码、状态文字（未扫码 → 已扫码，请在手机上确认 → 登录成功 / 已过期）、取消与刷新。
- **粘贴凭证**：说明怎样从浏览器复制 Cookie（只写步骤，不放截图）；单行密码型输入框，占位“粘贴 Cookie（至少包含 SESSDATA）”；强调色胶囊按钮“验证并登录”；验证中按钮显示加载状态；结果用一句话说明（成功后进入主页；失败写原因，如“缺少 SESSDATA”“凭证已失效”）。提交后输入框立即清空。下方一行浅色提示：“凭证只保存在这台电脑上，并按当前 Windows 用户加密”。
- 登录已失效时卡片上方多一行：“登录已失效，请重新登录”。

<a id="subscriptions"></a>
### 3.9 订阅（DEC-026、DEC-033）

每个界面区域最多只放一个强调色主按钮。

**订阅列表** `/subscriptions`：

- 顶部栏标题“订阅”，右侧只放一个强调色主按钮“添加订阅”和一个“⋯”（菜单“检查全部”“从 B 站关注列表导入”；检查进行中时顶部显示“正在检查 M / N”和“取消”按钮）。
- 顶部栏下面一个搜索框（按订阅名、备注和账号昵称过滤，只在本机过滤）。
- 主体是**较大的圆形头像网格**（头像约 92px，下方一行订阅名称，过长自动省略），按可用宽度自动排列列数（3～5 列），按行虚拟化滚动（NFR-UI-002）。
- 正在直播的订阅头像外有橙色直播圆环，头像下沿带橙色胶囊小标“直播”（正在录制时带红点与“录制中”）；点击该直播/录制小标即可一键开始或停止录制，点击头像或名称进入订阅详情 `/subscriptions/:id`。
- 空状态：“还没有订阅。把你关心的人建成订阅，一个人可以关联他的多个账号”，搭配顶部“添加订阅”主按钮和空状态“从关注列表导入”按钮。

**添加订阅**（对话框）：名称输入框（必填，≤ 64 字）；“关联账号”输入框（可选，粘贴哔哩哔哩主页链接或 UID，或抖音主页链接、分享文本或 `sec_uid`，可预览显示头像、昵称、站点小字与 UID/抖音号确认卡片；账号已属于别的订阅时卡片里写“该账号已属于订阅 X”并提供“创建并移到新订阅”）；强调色主按钮“确认添加”。

**订阅详情** `/subscriptions/:id`：

- 顶部返回箭头与订阅名。详情头部（不套卡片）只有大头像、订阅名（及备注说明）、一个**规则按钮**“规则：<规则名> ▾”和一个“⋯”（菜单“检查更新”“改名”“备注”“更换头像”，分隔线后红字“删除订阅”；检查中头部附“取消检查”）。规则按钮弹出全部缓存规则（名称与摘要，当前规则打勾），选一条立即生效，最后一项“管理缓存规则”进入设置的“缓存规则”（DEC-040）。
- 标签栏只有两个：**直播**（默认）、**账号**。订阅的内容在主页（“有更新”里点这个订阅）和媒体库里看，不再有“更新”“已缓存”“规则”标签（DEC-040）。
  - **直播**：每个关联账号的直播间状态（未开通直播间 / 未开播 / 直播中），直播中或录制中显示标题、房间号、清晰度与编码（如“原画 · AVC”），右侧只有“录制”（强调色主按钮）或“停止录制”，“在浏览器中观看”在该行的“⋯”里；标题右侧的“⋯”提供“刷新直播状态”。已录制的录像点行播放，“详情”“在资源管理器中显示”在行右侧的“⋯”里。
  - **账号**：列出当前关联的全部站点账号（站点小字“B 站”/“抖音”、头像、昵称、UID 或抖音号，右侧“打开主页”“用作头像”“解除关联”），底部提供“关联另一个账号：粘贴主页链接或 UID”输入框与预览确认卡片（确认按钮为该标签页唯一的强调色主按钮）。
- 删除订阅确认框：“删除订阅‘X’？只删除这个订阅和它的账号关联，不删除已缓存的内容，也不会在站点上取消关注。”按钮“确认删除订阅”与“取消”。

**从关注列表导入** `/subscriptions/import`：

- 顶部返回箭头与“从关注列表导入”；下面一行：分组下拉（全部关注、特别关注、各分组，带人数）和本页搜索框。
- 列表每行：复选框、头像、昵称、签名首行；已经属于订阅的账号复选框禁用，写“已在订阅‘X’中”。滚到底加载下一页，失败时底部显示原因和“重试”，已加载的保留。
- 底部固定一条操作栏：“已选 N 个”、“全选本页”、强调色“导入 N 个订阅”；导入完成后提示“已建立 N 个订阅，跳过 M 个”，并回到订阅列表。

<a id="tray"></a>
### 3.10 托盘与退出（DEC-030）

- 托盘图标用 TRACE 自己的字标缩略（与应用图标一致的深灰底白色“T”），有任务或录制时右下角加一个琥珀色小块；悬停提示“TRACE · 正在缓存 3 项 · 录制 1 场”或“TRACE”。
- 单击图标打开窗口（已打开就置前）；右键菜单：“打开 TRACE”、状态行（禁用）、“检查全部订阅”、分隔线、“退出”。有任务或录制时“退出”是子菜单，唯一一项写明后果“退出（会暂停 3 个任务、结束 1 场录制）”。
- 窗口里退出（托盘菜单之外，例如设置“常规”里关闭行为为“退出”时点关闭按钮）：有任务或录制时弹确认框，写明会暂停几个任务、结束几场录制，按钮“退出”与“取消”。
- 第一次关到托盘时的系统通知：标题“TRACE 仍在后台运行”，正文“缓存、定时检查和录制会继续。可以从托盘图标打开或退出”。

<a id="states"></a>
## 6. 状态

每个页面都要覆盖：加载中（骨架屏，不用整页转圈）、空状态（告诉用户下一步做什么）、错误（按错误类别给一句说明和下一步按钮，[错误分类](research/bilibili.md#errors)）、部分成功（列表已加载的部分保留，底部显示错误和“重试”）、到底（明确说明没有更多）。

<a id="accessibility"></a>
## 7. 可用性

- 键盘：Tab 顺序合理，焦点环可见；Esc 关闭弹层；输入框按回车提交（组合输入时除外）；看图层左右键切换、`+`/`-` 缩放、`0` 适应窗口。
- 图片有替代文字；只显示图标的按钮有无障碍名称和悬停提示；状态圆点有文字名称。
- 长中文标题按行截断，不撑破布局；数字用“万”“亿”缩写（如 12.3万），悬停显示精确值。
- 界面截图只证明看到的状态；后台行为、键盘和输入法要分别验证。
