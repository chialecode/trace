# 界面规范

依据 DEC-039：窗口由**图标栏、上下文侧栏、页面**组成，类似桌面聊天与素材库应用；视觉参考 Cindy 设计系统的细分隔线与 Inter 字体，底色是白色内容区加通透的中性浅灰侧栏（DEC-046 ③），强调色是一种清新的蓝（可预览绿色）。只借鉴布局、字体和配色方法，不复制任何站点或应用的标识、图标与品牌色。需求见[需求](requirements.md)，实现约束见[技术设计](design/architecture.md#frontend)。

## 1. 窗口布局（DEC-039）

| 宽度 | 图标栏 | 上下文侧栏 | 页面 |
| --- | --- | --- | --- |
| ≥ 1280 | 52px | 272px（有侧栏的页面） | 其余宽度 |
| 1000～1279 | 52px | 240px | 其余宽度 |
| 720～999 | 52px | 不显示（设置除外，只显示图标的 72px） | 其余宽度 |

- **沉浸式标题栏**（DEC-046 ④）：窗口不画系统标题栏，图标栏、侧栏和页面都延伸到窗口顶部；系统的最小化、最大化、关闭按钮保留在右上角，盖在页面上。页面顶部栏右侧给这些按钮让位（按 MyGo `TitleBar()` 的宽度），图标栏和侧栏顶部一条与按钮同高的区域、以及页面顶部栏的空白处都可以拖动窗口，双击最大化。看图层与播放层的面板上边距不小于按钮高度加 8px；全屏时没有这些让位。
- **图标栏**（最左，浅灰底 `#f7f7f7`）：只放图标，名称在悬停提示与无障碍名称里，见[第 2 节](#nav)。
- **上下文侧栏**（`#f7f7f7` 底，细分隔线）：当前页面里“看什么”的选择，像素材库的文件夹或聊天应用的会话列表。顶部是页面名（18px，600），下面是条目（图标或头像 + 名称，选中项浅强调色底、强调色文字），分组标题用 12px 灰字：
  - **主页**：“全部动态”、站点筛选，然后直接是订阅列表（DEC-053 ②，不加分节标题、不写状态文字）：正在直播的在最前（头像橙色直播圈），然后未读（头像右下角蓝色圆点），再是已读；点一行只看这个订阅的时间线，选中项高亮（[§3.1](#home)）。
  - **订阅**：“全部订阅”（头像网格）、“全部账号”（按站点列出全部订阅的账号，DEC-057 ⑥）、“检查计划”（`/subscriptions/checks`，各账号定时与开播检查排程及手动检查，[DEC-081](decisions.md#dec-081)）和全部订阅的列表（虚拟滚动，直播中的头像带橙色圆环），点一项打开订阅详情。
  - **媒体库**（含媒体库本机详情 `/library/item`）：类型（全部 / 视频 / 图片 / 直播录像 / 转发；“图片”“视频”只列作者自己的内容，转发的动态与它带的图片、视频在“转发”里，DEC-056）；“来源”（全部来源、各订阅、不属于订阅的 UP 主；每行纯离线显示当前站点筛选下的条目数与占用空间，标题右侧提供“按占用空间”降序排序切换，[DEC-083](decisions.md#dec-083)）；底部一行“N 项 · 占用大小”。
  - **解析页、视频页与用户页**：“最近解析”，在解析过的对象之间切换，当前对象高亮（DEC-049 ②）。
  - **我的**：按站点折叠的四组功能（哔哩哔哩、抖音、微博、X），默认折叠，见[第 3.11 节](#mine)。
  - **任务**（[DEC-081](decisions.md#dec-081)）：四组——“进行中（N）”（N 为排队/进行中下载任务数与未结束缓存队列数之和，合并下载任务与缓存队列）、“直播（N）”（N 为正在录制的场数，录制行内可原地展开异常明细）、“待处理（N）”（N 为内容冲突数 + 可重试失败/未完成下载任务数 + 近 7 天录制异常场数之和，为 0 时不带数字）、“记录（N）”（N 为进行中与等待确认的导入导出数，为 0 时不带数字），见[第 3.6 节](#library)。
  - **设置**：设置分类（含“更新”与“关于”等），见[第 3.7 节](#settings)。
  - 登录页没有上下文侧栏。
- **页面**：白底。顶部栏（不随内容滚动）左边是返回箭头（需要时）与页面标题（18px，600），右边是该页的操作（不放快速解析框，链接与 UID 统一在解析页解析，DEC-069）。帖子、视频与用户详情及媒体库本机详情限宽 680px 居中；解析页主面板全宽居中承载一个最宽约 640px 的大输入框；媒体库网格、任务列表、订阅头像网格用满宽度；设置限宽 860px。
- **图标栏与上下文侧栏固定**：只有页面随内容滚动（NFR-UI-001）。窄窗（< 1000）没有侧栏时，主页的订阅列表退回为时间线上方的横向头像条（“全部动态”在最前），媒体库的类型与来源退回为页面里的标签与“作者筛选”，解析页的“最近解析”退回到大输入框下方，任务页的侧栏退回为页面顶部的分段选择。
- 不再有右栏：链接与 UID 解析集中在图标栏“解析”页（DEC-069）；排队与进行中的下载任务数量在图标栏“任务”的角标（DEC-049 ①）；正在直播的订阅排在主页侧栏订阅列表的最前。
- **悬浮通知气泡**（[DEC-086](decisions.md#dec-086)、FR-UPD-003）：所有全局通知（操作消息反馈、全局错误与单站登录失效提示、正式版更新提示及轻提示）统一悬浮停靠在窗口右下角（距底边距与右边距 16px、限宽 380px 并自适应窄窗、带轻阴影与细边框，非模态透传不阻挡页面其余区域操作），**不占页面顶部栏高度、不推动或改变页面布局**。**所有通知均不自动收起**；有多条通知时新通知在视觉上直接覆盖显示在旧通知之上（旧通知保留在下方，气泡顶边露出叠层边缘并显示“还有 N 条”提示），用户可逐条点击关闭按钮依次查看与收起。
  - **更新提示**（FR-UPD-003）：正式版有更新时在右下角悬浮通知区显示浅蓝底气泡：“新版本 0.1.2 已就绪”（自动下载关着时“有新版本 0.1.2”），带“更新内容”、“重启以更新”（或“下载并安装”）与关闭按钮（这次运行不再出现）。点“更新内容”在气泡内部限高展开这一版的说明（`CHANGELOG.md` 的那一节，多行可滚动），再点“收起更新内容”。点“重启以更新”：没有缓存与录制时直接重启；有时先弹确认框“重启以更新”，正文“重启会暂停 N 个缓存任务并结束 M 场录制，重启后可以继续缓存。”，按钮“重启以更新”“取消”。更新后第一次启动显示一次“已更新到 0.1.2 · 更新内容”，可以关掉。
- **数据来自更新的版本**：启动时发现数据文件来自更新的 TRACE（例如装回了旧版本），弹一个系统对话框“这些数据来自更新的 TRACE 版本，请安装新版”，确定后退出，不打开窗口、不改动任何数据。

## 2. 图标栏

- 顶部是 TRACE 字标“T”（DEC-046 ② 起不带点），只是标志，不是按钮，也不占导航项的位置；第一个导航项紧挨标志下方（DEC-057 ③）。
- 导航项（DEC-022、DEC-026）是 40px 圆角方块里的线性图标（描边 1.6，选中 2），悬停浅灰底，选中浅强调色底、强调色图标：
  1. **主页**：已缓存内容的信息流。
  2. **订阅**：被追踪的人（[第 3.9 节](#subscriptions)）；图标栏不显示未读角标或正在直播的圆点（DEC-033、[DEC-072](decisions.md#dec-072)），悬停提示固定为“订阅”，开播状态在进入主页、订阅页或订阅详情时主动查看。
  3. **我的**：登录账号在站点上的关注、收藏、稍后再看、历史等（[第 3.11 节](#mine)，DEC-047）。
  4. **解析**：粘贴链接或 UID。
  5. **媒体库**：已缓存的图片、视频和直播录像。
  6. **任务**：进行中（下载任务与缓存队列）、直播（含行内录制异常）、待处理（内容冲突、失败/未完成下载与近期录制异常）与记录（导入导出）；只有存在排队或进行中的下载任务时，右上角显示强调色小数字（严格保持 [DEC-072](decisions.md#dec-072)：只数排队和进行中的下载任务，不数直播录制、缓存队列等待项、待处理内容冲突、失败任务或录制异常，DEC-049 ①、DEC-050 ②、[DEC-076](decisions.md#dec-076) ⑤、[DEC-081](decisions.md#dec-081)）。
- 底部固定当前账号的小头像（悬停显示昵称和 `UID`，点击进入账号设置，未登录时进入登录页）和**设置**（齿轮图标）。
- 不显示做不了的功能入口。

## 3. 页面

通用：

- **整洁原则**（DEC-037、DEC-038）：同类条目（帖子、投稿、最近解析、媒体库条目、录像）**点本体完成常用动作，其余操作收进一个“⋯”更多菜单；每个区域最多一个主按钮**，不堆砌文字按钮。
- **“⋯”菜单是浮在按钮旁边的弹出菜单**（白底圆角、阴影，在按钮下方右对齐，没有空间时翻到上方；点外面或按 Esc 关闭，键盘可用），菜单项不占页面空间、不推开下面的内容；危险操作（删除）用红字并与其他项用分隔线隔开。不要用在页面里展开一排胶囊按钮的方式代替菜单。
- **点开即跳转**（DEC-038）：从帖子、投稿、头像、最近解析打开视频或用户页时，立刻切换到目标页面，先显示卡片上已有的标题、作者和封面，并显示“正在打开…”；读取完成后填入完整内容。失败时在该页面显示原因和“重试”。后点的覆盖先点的，已经离开的页面不会被迟到的结果拉回。
- **顶部栏**：返回箭头、页面标题与页面操作（不含快速解析框，DEC-069），不随内容滚动；页面里的标签选中项下方是一条强调色粗短线。
- **帖子**（主页信息流、订阅详情、用户页动态共用 `PostCard`，DEC-037）：左边圆形头像（点击进入用户页），右边第一行“昵称 · 发布时间 · 类型”和右上角的[状态圆点](#status-dot)（主页不画，DEC-046 ⑦）；正文（超过 6 行折叠，可展开；正文与转发引用中的跳转链接、历史缓存 `标题 (https://...)` / `标题 (sinaweibo://pageinfo?containerid=...)` / `标题 (sinaweibo://userinfo?uid=...)` 及内联 `http(s)://` 地址统一渲染为主题强调色可点击超链接，显示站点可读标题或精简域名路径而非裸地址，悬停提示完整目标地址，点击经外部链接校验在浏览器打开且严格仅允许安全转换后的 `http://` 与 `https://`，DEC-073）；图片像站点上那样尽量完整显示（DEC-040）：1 张时按原比例完整显示（竖图高 360px、宽按比例，横图最宽 480px，比例限制在 1:2 到 2.4:1 之间），2 张或 4 张排两列、其他排三列的正方形格子（最多显示 9 张，多出的在最后一格写“+N”），实况照片左上角标“实况”，图片没加载出来时是浅灰底块，不写文字；点击图片打开[看图层](#viewer)。视频是一张横向卡片：左边 200px 宽的 16:9 封面（右下角时长），右边标题（最多两行）、简介（最多两行）和清晰度规格；不显示播放数、评论数这类会变的数字，也不缓存它们；点卡片任意位置播放（已缓存时在播放层播放本机文件）；转发在白底细线圆角框里显示原动态摘要；不支持的类型显示类型名说明。
  - **在主页信息流（含单个订阅视图）与订阅详情“内容”标签中**：帖子下方**不放任何文字按钮**（不显示“内置播放”“查看图片”“补存弹幕和字幕”“浏览器打开”“复制链接”“查看封面”等），直接点视频画面播放、点图片看图、点头像或昵称进用户页（DEC-037、DEC-051 ⑦）。订阅详情“内容”标签的每条帖子右上角另有一个“⋯”，菜单是“在资源管理器中显示”，分隔线后红字“删除”（打开与媒体库相同的删除确认，DEC-064）；主页帖子没有“⋯”。**主页**里作者已订阅时，点头像进入这个订阅的详情，没订阅的才进用户页（DEC-057 ④）；用户页（解析页）只在用户主动解析或从别处明确打开时出现。
  - **在用户页与动态详情中**：帖子同样**没有文字按钮**；右上角状态圆点旁一个“⋯”，菜单依次是“缓存”（仅未缓存时）、“在浏览器中打开”“复制链接”（DEC-038）。点未缓存视频的画面打开视频详情。条目之间用细线分隔，不用卡片阴影。

### 3.1 主页：信息流（DEC-023、DEC-037）

- 顶部栏标题“主页”；始终按从新到旧（最新在上）排列，不提供“最新在前 / 最早在前”切换（DEC-037）。顶部栏右侧提供一个纯图标的离线刷新按钮（34×34 圆形按钮，`refresh` 图标，不放文字，悬停提示“刷新”，无障碍名“主页刷新”；点击在后台协程调用无锁增量 `RefreshLibrary` 并一并预读刷新后的信息流、统计与订阅列表，完成后以单次快照切换更新界面，不卡住主线程、零网络请求、不弹窗；保留当前站点筛选或单订阅视图）。
- **订阅列表**（DEC-053 ②，替代 DEC-037 的“有更新”与 DEC-039 的“正在直播”分节）：主页侧栏自上而下是“全部动态”、站点筛选，然后直接是订阅列表，**不加任何分节标题**，每行只有头像与名称、不写状态说明。正在直播的头像一圈橙色直播圈；**未读**时头像右下角一个约 8px 的强调蓝色圆点（带一圈背景色描边，样式参考哔哩哔哩动态页的头像条）。分三组：正在直播的在最前（组内未读在前，再按最近更新），然后未读，然后已读；后两组各按该订阅在当前站点筛选下最新一条已缓存内容的发布时间从新到旧。没有已缓存内容的订阅不列出（正在直播的除外）；只列订阅，没订阅的作者与直播间不进列表。订阅很多时列表虚拟化。窄窗没有侧栏时，变成时间线上方可横向滚动的头像条：圆形头像（约 52px）、下面一行名称，“全部动态”在最前，同样有直播圈与未读圆点。
  - **未读**：该订阅全部关联账号在当前站点筛选下最新的已缓存发布时间晚于 `homeSeen["sub:<id>"]`；没有这一项时与启动时读到的 `anchor`（看过的最新一条）比；两者都没有（第一次使用）算已读，不会满屏圆点。在主时间线上往下翻不改变某个订阅的已读状态，只有点开它才算看过。
  - **顺序在进入主页时定下**：本次停留期间（含点开、返回“全部动态”、切换站点筛选）只更新圆点与直播圈，不挪动行；新缓存的内容只让圆点出现，开播或下播只改直播圈，新出现的订阅加在末尾。下次进入主页（从别的页面切回来，或重新启动）重新排序，看过的移到已读组。
  - 点击某一行（包括正在直播的），进入**只含该订阅（全部关联账号）已缓存内容的信息流视图**：顶部栏显示返回箭头、头像与订阅名称，下方从新到旧列出该订阅的已缓存帖子（同样使用无底部按钮的主页 `PostCard`）；点击返回箭头回到主时间线原来的位置。
  - 成功打开后把该订阅的 `homeSeen` 记为原值与其最新缓存内容时间戳中较大的一个，圆点立即消失、行不挪动，直到该订阅又有更新的缓存内容；只按订阅记一个时间戳，不按单条记已读。读取失败保留主时间线，保存失败显示原因；返回主时间线时回到原来那条与行内偏移。
- 内容是所有已缓存的动态、直接缓存的视频和直播录像，不分作者，按发布时间（录像按开播时间）从新到旧排列，每条是一个帖子；录像帖子显示“直播录像”与清晰度编码规格。已缓存的视频卡片点击后在播放层播放本机文件；图片点击打开看图层看本机原图。
- **回到上次阅读的位置**（DEC-053 ①，替代 DEC-040 的“每次从最新处开始”）：“全部 / B 站 / 抖音 / 微博 / X”分别记下主时间线可见区最上面那条与它顶边的偏移（滚动停下约 1 秒后、离开主页、切换筛选与关闭窗口或退出时保存）。每次启动后第一次显示某个筛选时停在那条与偏移，往上滑载入之后缓存的内容，当前看到的条目不跳动；那条被删掉时停在不晚于它的最近一条；没有记录时从最新处开始。同一次运行内切到别的页面或别的筛选再回来，回到当时的位置。单个订阅的信息流不记位置。不提示“N 条更新的内容”，往上翻过的就是看过了（DEC-040）；看过的最新一条仍记为 `anchor`，作为没有 `homeSeen` 的订阅的初始已读基准。
- 抖音、微博与 X 的作品同样是帖子（DEC-043、DEC-065、DEC-066）：抖音视频作品按视频卡片（竖版封面在左、文案在右），抖音图文作品按图文帖子显示图片并在下方显示配乐条（[§3.4](#douyin-pages)）；微博单条按图文、混排、视频与转发帖子显示（[§3.4](#weibo-pages)）；X 单帖按长帖、作者自回复对话串（纵向堆叠、头像下 2px 细竖线相连、逐条展示正文链接与各自媒体，2～4 条完整展开，超长串默认展示前 3 条并支持原地展开/收起，[DEC-090](decisions.md#dec-090)）、多图/GIF/视频混排与转帖/引用框显示（[§3.4](#x-pages)）；作者行均带站点小字。主页上下文侧栏“全部动态”下面有站点筛选“全部 / B 站 / 抖音 / 微博 / X”（窄窗时是时间线上方的五段式切换，720 宽无横向溢出），默认“全部”，记在 `ui-state.json`（FR-SITE-002）。
- **作者行的订阅名与共创头像**（DEC-063 ②）：帖子的账号名后面用小一号（13px）的强调色文字显示它所属订阅的名称，不加“订阅”二字；订阅名与账号名相同时不重复显示；点账号名或订阅名打开这个订阅。为订阅账号缓存的共创或合作作品（`via.reason = "collab"`）在主页与订阅详情“内容”中按这个 `via` 账号归属订阅，并优先显示该 `via` 账号的本机头像（不再显示共创发布者头像；`via` 账号无本机头像时回退到其所属订阅主账号的本机头像）。
- 底部到头时显示“已经到最早的缓存了”。
- 分页读取失败保留帖子并显示“重试”，等待用户重试；查看时间保存失败显示原因，“看最新”失败仍停在原位置。主页缺少本机图片时使用占位图，不自动补发远程图片请求。
- 空状态：“还没有缓存的内容。到‘解析’里打开一位 UP 主、抖音作者、微博博主或 X 用户，在动态、作品、微博或帖子上点‘缓存’”，带一个去解析页的按钮。

### 3.2 解析页（DEC-022、DEC-033、DEC-037、DEC-049 ②）

- **上下文侧栏**（≥ 1000 宽）：与视频页、用户页共用同一份“最近解析”列表。窄窗没有侧栏时，同一份列表（含“⋯”与行内确认）显示在大输入框下方，输入框靠上放置。
  - 侧栏顶部标题“最近解析”，右侧只放一个“⋯”按钮，展开“全部清空”（点击后在行内确认再执行，同时清理无引用缩略图；失败显示原因并保留确认，缩略图清理的恢复契约见[数据设计](design/data-and-cache.md#storage)）。
  - 解析成功后，封面与头像缩略图缓存到本机数据目录 `<DataDir>/thumbs/`（不进媒体库，不带 Cookie、不带外站 Referer，地址过白名单，大小有上限，文件名不含签名参数；未缓存到媒体库的条目也能显示封面与头像，失败时显示占位图而不是空白）。
  - 每行显示本机小封面或圆形头像、单行标题、一行“类型 · 站点”（如“视频 · B 站”“作品 · 抖音”“微博 · 微博”“帖子 · X”“X 用户 · X”“列表 · X”），**点击整行直接打开详情**，当前正在查看的条目高亮；悬停或聚焦时右侧出现一个“⋯”按钮，展开“在浏览器中打开”与“删除”（删除单条时一并删除对应本机缩略图）。
- **主面板**：顶部栏标题“解析”（不显示“正在加载”“正在重建索引”等与解析无关的后台状态，DEC-033；所有页面顶部栏均无快速解析框，解析统一在本页进行，DEC-069）。主面板**不再列出最近解析**，只在页面竖直方向略偏上居中的位置放一个**大输入框**（最宽约 640px，高约 52px，全圆角胶囊形，类似搜索引擎首页）：左侧是当前登录账号头像，中间输入区提示可粘贴哔哩哔哩、抖音、微博或 X 的视频/图文/微博/帖子/直播链接、分享文本（含 `t.cn`、`t.co` 短链与镜像链接）、用户主页或 UID/`sec_uid`，右侧是强调色按钮“立即解析”。按回车解析；中文输入法正在组合输入时按回车不提交；解析中按钮显示“解析中…”并禁用。识别或解析失败在输入框正下方用一句话说明；微博直播链接给出提示“微博直播暂不支持录制，可以在浏览器中打开”且不发请求，X 直播与 Spaces 链接给出提示“X 直播与 Spaces 暂不支持录制，可以在浏览器中打开”且不发请求，未登录微博或 X 时分别提示“请先登录微博”“请先登录 X”且不发请求。

<a id="status-dot"></a>
### 3.3 状态圆点（DEC-024）

帖子、投稿条目和视频详情页显示一个直径 8px 的纯色小圆点（DEC-039；媒体库和主页不显示，主页只列已缓存的内容，DEC-046 ⑦）。**一条帖子只有一个圆点**，表示动态和其中的图片、视频合起来的状态：都缓存完整才是绿色，其中有缺的（例如视频只缓存了一部分）就是黄色，图片和视频卡片上不再各自显示圆点；视频详情页的圆点在“缓存视频”按钮旁，封面上不显示，配合“缓存”操作（帖子与投稿在“⋯”菜单里，视频详情页是“缓存视频”按钮）：

| 状态 | 圆点 | 按钮 |
| --- | --- | --- |
| 未缓存 | 不显示 | “缓存”（下载线性图标） |
| 排队 / 缓存中 | 蓝色进度圆环 + 悬停显示百分比 | 禁用，悬停显示“正在缓存” |
| 已缓存（最高档） | 绿色小圆点 | “已缓存”，点击进入媒体库对应条目 |
| 部分缓存 / 已暂停 / 可升级 | 黄色小圆点 | 部分：“补全”；暂停：“继续”；可升级：“升级缓存”。悬停列出缺什么、为什么，或“可升级到 4K（当前 1080P）” |
| 失败 / 文件缺失 / 清单损坏 | 红色小圆点 | “重试”或“删除记录”；悬停显示原因 |

圆点里不画对勾、短横等符号；含义靠悬停提示和无障碍名称（如“已缓存，1080P 高码率，最高档”“部分缓存”）给出，不只靠颜色。

### 3.4 视频详情与用户页

- **视频详情页**（解析路由）：顶部返回箭头与“视频”；UP 主行（头像与昵称，点击进入空间；右侧“缓存视频”主按钮、状态圆点，已缓存非归档条目另带“⋯”菜单提供“强制重新下载”“复制链接”“在浏览器中打开”“打开文件夹”，[DEC-079](decisions.md#dec-079)）；标题（大号，充电专属视频并列“充电专属”或“充电专属（已解锁）”标记，未开通权益时在标题下方显示提醒横幅并禁用“缓存视频”按钮）；大封面（已缓存时点击播放本机文件）；简介（超过 6 行折叠）；发布时间、分区；统计行（图标加数字）；多 P 列表（已缓存时每 P 显示实际清晰度，如“1080P 高码率 · AV1 · 杜比全景声”，有 `chapters` 时在分 P 卡片下展示“章节看点”时间点胶囊，点击直接打开播放层并跳转到对应秒数）。在解析路由打开已缓存视频时集中提供缓存维护操作（DEC-037）：探测到更高档时，标题上方显示黄色横幅与“升级缓存”按钮；同时在详情操作行提供“补存弹幕和字幕”按钮。
- **单条强制重新下载确认弹窗**（[DEC-079](decisions.md#dec-079)）：四站点联网已缓存详情页（微博帖子/视频、X 帖子、抖音作品、B 站视频，不含离线 `/library/item` 与 `archivedOf` 归档快照）的“⋯”菜单提供 **「强制重新下载」**；点击后先弹出二次确认对话框（标题“强制重新下载”，说明“将从源站重新完整下载并覆盖本机已有文件；若源站已删除或失效，仍会保留本机原文件不覆盖。”，取消 / 危险描边确认按钮），确认后从源站完整重拉并在校验通过后原子覆盖本地。微博与 X 详情页已缓存时的主按钮「重新缓存」维持非破坏性按新标准补全。
- **站点标记**（FR-SITE-002，DEC-043、DEC-065、DEC-066）：用次要文字色、12px、无底色的小字“B 站”“抖音”“微博”“X”，紧跟在作者名或元信息后面（中间一个“ · ”）。出现在用户页头部、订阅详情“账号”列表、主页帖子作者行、媒体库卡片的元信息行、任务行、最近解析条目六处；订阅网格的头像不加。不使用站点的图标与品牌色。
- **本机内容详情**（`/library/item`，DEC-049 ③）：从媒体库条目右下角“⋯ → 详情”进入媒体库自己的本机详情路由，图标栏仍高亮“媒体库”，上下文侧栏仍保持媒体库侧栏，返回箭头回到媒体库原来的筛选与滚动位置。只读本机清单和媒体，不发任何站点请求，缺图用占位图；不显示互动数据（播放数等会变，不缓存，DEC-040），未知时长不冒充 0；动态详情保留本机图片和引用视频卡片，直播录像显示“直播录像详情”、直播间、清晰度与分段原地播放，详情里的图片、视频、多 P、实况、配乐与录像分段点击都原地打开看图层或播放层。隐藏所有需要联网的操作（缓存、补存弹幕和字幕、升级缓存、刷新元数据），只在右上角“⋯”菜单保留一项“在解析页打开”供用户明确选择联网查看。
- **用户页**：横幅（带头像、昵称、`UID`、等级）；下面一行“关注 N · 粉丝 N · 投稿 N”，右侧只有一个订阅按钮（未订阅时强调色“订阅”，点击打开[加入订阅对话框](#subscribe-picker)；已订阅时“已订阅”，点击进入所属订阅）和一个“⋯”（“全部缓存”或“在缓存队列中查看”，“在浏览器中打开空间”，直播中另有“在浏览器中观看直播”）；签名；标签栏为“动态”（默认）和“投稿”，标签不带数字，标签栏右侧是筛选“全部 / 未缓存”。动态是帖子（充电专属锁定动态标“充电专属”并显示锁定说明，不提供“缓存”菜单项）；“投稿”标签下方提供简洁工具栏——关键词搜索框（仅在中文输入法非组合态按回车或点击“搜索”时发请求，绝不在输入过程防抖发请求；可“清空”）、排序切换（最新发布 / 最多播放 / 最多收藏）与分区筛选胶囊（服务端返回 `tlist` 非空时显示），切换条件重置分页并与本机“全部 / 未缓存”筛选协同；投稿是缩略图在左、标题和时长/播放数在右的紧凑行，点行打开视频，“缓存”“在浏览器中打开”在行右侧的“⋯”里。**整个头部是列表的第一行，随内容一起滚走**，窗口矮时也能看到内容（DEC-038）。两种列表都滚动到底自动加载。
  - **只看未缓存**（DEC-046 ⑧）：筛选只作用于已加载的页，切换不请求站点；之后加载的页同样按筛选显示。已加载的都缓存了时显示“已加载的内容都缓存了”和“加载下一页”按钮，不自动连翻。
  - **全部缓存**（DEC-050 ①，替代原按 10 / 20 / 50 条一次入队的做法）：用户页“⋯”提供一项“全部缓存”（哔哩哔哩按当前标签是“动态”还是“投稿”决定列表，抖音为“作品”，微博为“微博”且只补原创微博，X 为“帖子”且补全原创帖子与引用帖、跳过纯转帖，[DEC-091](decisions.md#dec-091)，看不到作品的私密/受保护账号不提供）；当该账号的这一列表已在缓存队列中且未结束时，菜单项变为“在缓存队列中查看”（点击跳到任务页并选中该队列任务）。点“全部缓存”不弹确认框，直接建立后台缓存队列任务并在右下角悬浮气泡提示“已加入缓存队列，会在后台慢慢缓存”。队列在后台按慢速、不规律的节奏逐条缓存（Q-017 默认值：每个站点同时只跑一个队列任务，每次只把 1 条未缓存条目排进下载队列、等它下载结束再随机等 40～150 秒，每缓存 15～25 条长歇 10～25 分钟；已加载的页不重发请求，后续翻页计入站点的每小时额度并遵守退避，遇风控、限流或额度用完进入“等待退避结束”、退避过后再随机等 10～30 分钟继续，登录失效暂停并在重新登录后继续，重启后接着做；微博到博主可见范围边界、X 到时间线可见上限时正常结束并把提示写入队列摘要）。缓存规则开了“全部缓存”时，后台按同样的队列定期补齐，任务页里这类队列的名称写“<账号> · 定期全部缓存 · 投稿/作品/微博/帖子”（DEC-061 ①）。从用户页点开的视频，在视频页点“缓存视频”也按这个用户存放合作视频（DEC-061 ③）。
  - 正在直播时，签名下方出现一条直播横幅：橙色“直播中”标记、直播标题（悬停显示房间号）与清晰度编码（如“原画 · AVC”），右侧只有一个按钮“录制”（录制中变为“停止录制”，DEC-033、DEC-038）。

### 3.5 看图层（DEC-033）

- 点击任何图片打开看图层：一个浮在应用上方的深色圆角面板（四周留边，背后的应用变暗，点面板外面关闭；DEC-040），默认按面板适应显示**原图**（已缓存的用本机文件，否则用去掉尺寸后缀的原图地址）。
- 滚轮、快捷键（`+` / `-` / `0`）或双击缩放，按住拖动平移；只保留少量半透明圆形悬浮按钮：右上角**关闭**，左右两侧**上一张 / 下一张**，底部居中**适应窗口 / 原始大小（1:1）**，左上角轻量胶囊显示“当前 / 总数 · 缩放百分比”；当当前已缓存图片存在无水印伴侣文件（微博 `images/NN_nowm.<ext>`，[DEC-078](decisions.md#dec-078)）时，左上角进度胶囊旁显示简洁的 **「原图 / 无水印」** 分段胶囊切换按钮（默认显示原图，点击即时切图且平滑加载；切到无伴侣文件的图片时自动隐藏按钮并显示原图，不报错）。
- 鼠标静止约 2 秒后悬浮控件自动隐藏，鼠标移动或按键时重新出现；左右键切换同一条动态里的图片，Esc 关闭。
- 实况照片与 X GIF（MP4 静音循环）翻到这一页就在看图层里原地自动播放动态片段（DEC-040、DEC-046 ①、DEC-049），底部圆形“播放”按钮用来重播：已缓存的播放本机片段，没缓存的先从站点取到临时文件再播放（哔哩哔哩、抖音、微博与 X 均一致，按 `InlineSite` 区分站点通道），不跳到播放层。
- 抖音图文的视频页在看图层里直接播放（点画面暂停/继续，底部一条细进度条与时长，没缓存时播放在线地址）；切到别的页时停止。视频页或实况片段播放时，配乐条暂停，停止后不自动恢复。

### 3.6 媒体库与任务

- **媒体库**（图标栏“媒体库”，DEC-037、DEC-039、DEC-049 ③、[DEC-083](decisions.md#dec-083)）：独立的离线浏览页面。顶部栏标题“媒体库”（“重建索引”在设置“存储”），右侧提供次要描边按钮“多选”与一个“⋯”（菜单“导入…”“导出…”，DEC-062）；搜索框右侧一个“刷新”按钮（DEC-055）：在后台重新检查保存位置里的文件（只看文件在不在、大小对不对，不算哈希、不联网，进行中显示“正在刷新…”），完成后弹窗列出这次发现的变化——“文件夹已删除，已从媒体库移除（N）”（标题与文件夹路径）和“缺少文件（N）”（标题与缺少的文件名，最多列 6 个），没有变化时写“检查了 N 个条目，没有发现被删除的文件。”，底部“知道了”；类型与来源在上下文侧栏（窄窗时退回为页面里的标签“全部 / 图片 / 视频 / 直播录像 / 转发”和“作者筛选”，同样展示各订阅/作者的条目数、占用空间与“按占用空间”降序排序切换）；页面里一行搜索框，**固定按发布时间从新到旧排序**（直播录像按开播时间；不再提供“发布时间 / 缓存时间”切换，已保存的旧缓存时间排序偏好静默忽略）。来源分组里加站点筛选“全部 / B 站 / 抖音 / 微博 / X”（720 宽无横向溢出），与类型、作者筛选叠加（FR-SITE-002）；来源行纯离线不发远程头像请求。
  - **多选与批量操作**（[DEC-083](decisions.md#dec-083)）：点顶部栏“多选”进入多选模式后，网格上方出现批量操作栏（720/1000/1280 宽均无横向溢出），显示“已选 N 项 · 占用大小”，以及“全选已加载 / 取消全选”、强调色“批量导出”、红框“批量删除”和“退出多选”（保持页面区域最多一个强调色主按钮）。多选模式下点击卡片缩略图或标题切换该条目的勾选状态（不再打开播放层或看图层），卡片左上角显示复选角标且选中项带强调色描边，多图条目按 `itemKey` 同步全部卡片的勾选状态，同时隐藏单卡右下角“⋯”菜单避免误触；无弹窗打开时按 `Esc`、点“退出多选”或离开媒体库均自动退出并清空选择。

  - 网格：卡片约 240px 宽，按页面宽度每行 2～6 个；**16:9 圆角缩略图**（圆角 14px），视频右下角显示时长、正中播放图标；**不显示状态圆点**（媒体库里都是已缓存的内容，DEC-039）；缩略图下方是**最多两行的标题**（14px，600）、一行元信息（作者名，直播录像附清晰度与编码如“原画 · AVC”）和右侧一个“⋯”按钮。虚拟滚动，滚到底继续加载。
  - 点击缩略图或标题直接在原地打开对应文件的看图层或**播放层**（DEC-033、DEC-037、DEC-049 ③、[DEC-084](decisions.md#dec-084)），不按网格位置猜测分 P、不跳转到解析路由、不发任何站点网络请求；点击右下角“⋯”展开菜单：**详情**（在媒体库自己的本机详情路由 `/library/item` 打开所属动态、视频、作品或直播录像，保持“媒体库”图标高亮与媒体库侧栏，返回时保留原筛选与滚动位置，只读本机数据，仅在详情“⋯”里留“在解析页打开”作为明确联网入口）、**在资源管理器中显示**、**删除**。播放层和看图层一样是浮在应用上方的深色圆角面板（点面板外关闭；全屏时铺满窗口），**打开即自动播放**（DEC-040），底部悬浮条只保留圆形**播放/暂停**、**进度条**、**音量**、**全屏**（当分 P 有 `chapters` 章节看点时，进度条上方浮现可点击的章节胶囊栏，点击直接跳转到该章节起点 `FromSec`，字幕显示位置自动上移避让），右上角保留圆形**“⋯”更多菜单**与**关闭**。以未缓存视频进入**临时预览模式**（`PreviewMode`，抖音/微博/X 单文件 MP4 短视频 ≤128 MiB）时，顶部悬浮栏在标题旁显示克制的**「临时预览」**胶囊标签，右侧在“⋯”前提供**「缓存到媒体库」**主操作按钮（点击触发对应作品/帖子的缓存任务并反馈“已加入缓存任务”，随后切换为禁用的“已加入缓存”）；若预览加载失败、超过 128 MiB 上限或缺失解码器，错误卡片内同样直接提供**「缓存到媒体库」**一键回退，且临时预览下隐藏“在文件夹中显示”与“用系统播放器打开”，不暴露 `<DataDir>/cache/preview/` 临时路径。音量按钮展开 0～100% 滑块与静音开关；全屏作用于原生窗口，切分段保持全屏，关闭播放或登录失效时恢复。**弹幕**（开关、透明度滑块 20%～100%、显示区域上方 1/4 / 上半屏 / 全屏、密度低/中/高/不限）、**字幕**（语言选择与关闭）、**分段切换**（多 P 或多段直播录像的“上一段 / 下一段”）、**在文件夹中显示**、**用系统播放器打开**统一收进“⋯”菜单。鼠标静止约 2 秒后悬浮控件自动隐藏，鼠标移动或任意按键时重新出现；菜单打开时保持控件可见。音量、静音、弹幕与字幕偏好记住并沿用，保存失败显示原因。
  - 单条“删除”或“多选 › 批量删除”打开同一个安全删除确认弹窗：单条显示“类型：标题”（动态没有标题时用正文第一行），批量显示“已选择 N 个媒体库条目”；写明预计清理的已登记缓存文件数与总大小、随批一并删除的独占引用视频数、因单独缓存或仍被未选动态引用而保留的共用视频数、以及目录内将原样保留的非 TRACE 用户文件数，并提供“同时删除磁盘上的 TRACE 缓存文件”开关；删除完成后刷新媒体库、自动退出多选，若保留了非 TRACE 文件则在右下角悬浮气泡提示“已保留 N 个不是 TRACE 创建的文件”。
  - 空状态：“还没有符合筛选的媒体。缓存图片、视频或直播录像后，它们会出现在这里”。
- **任务**（图标栏“任务”，DEC-049 ①、DEC-050 ②、DEC-051 ③、[DEC-076](decisions.md#dec-076) ⑤、[DEC-079](decisions.md#dec-079)、[DEC-081](decisions.md#dec-081)）：通过上下文侧栏（≥ 1000 宽；窄窗 `< 1000` 时退回为页面顶部的可换行分段选择，720 宽无横向溢出）组织四组内容，点哪一项主面板显示哪一项（旧版分区键自动向后兼容归一化）：
  1. **进行中（N）**（N 为排队/进行中下载任务数与未结束缓存队列数之和；图标栏“任务”角标仍只数排队与进行中的下载任务，[DEC-072](decisions.md#dec-072)）：顶部栏右侧保留“检查画质更新”按钮（执行时显示“检查 M / N · 取消”），主面板顶部以两段式子标签在 **下载任务（M）** 与 **缓存队列（K）** 之间切换，两类进度均触手可及、互不掩埋：
     - **下载任务**：列表上方固定批量操作栏——存在可重试任务（失败、部分完成或非用户手动暂停的暂停任务，按 `IsRetryableTask` 计数，不含用户手动暂停）时提供强调色“批量重试（N）”按钮（点击调用 `RetryAllTasks` 并按已登录站点隔离批量重新入队、在右下角悬浮气泡反馈重试/缺登录跳过/重复跳过结果），存在已结束（已完成 / 已取消）的任务时并排提供“清除已结束（N）”按钮。任务列表使用 `ui.List` 虚拟化滚动（仅渲染可见卡片，配合轻量摘要查询 `ListTasksSummary`、256px 缩略图与按 `libraryRev` 缓存的封面，不随每秒下载进度清空重查，单条操作只刷新任务列表），任务增多时仍流畅滚动。每行是对象缩略图、标题、站点小字、进度条与“已下载 / 总大小”、状态文字和操作（进行中/排队可暂停或取消；已暂停可继续；失败/部分完成可重试或移除；已完成/已取消可移除，不能取消；DEC-033；当排队中下载任务 ≥ 2 个时，每张排队中卡片显示“排队第 N 位”并在操作行提供紧凑的“置顶 / 上移 / 下移”排序按钮，720/1000/1280 宽自动换行零溢出，[DEC-088](decisions.md#dec-088)）。失败或暂停原因直接显示在任务行内；移除失败或部分完成的任务前，行内弹出确认提示“确认移除该任务？会删除未完成的临时文件，已缓存完成的文件会保留”。点“展开详情”（FR-CACHE-009）按需读取逐文件进度清单与脱敏后的分段重试记录。
     - **缓存队列**（DEC-057 ②、[DEC-079](decisions.md#dec-079)、[DEC-088](decisions.md#dec-088)）：当离线统计发现待补全历史微博且当前没有进行中的补全队列时，顶部展示一行紧凑操作条「发现 N 条历史微博可补全」与强调色「一键补全」按钮；下方一行提示“各站点独立并行推进，单站退避不影响其他站点；取消或移除队列不会删除已缓存到媒体库的内容”，有结束的队列时右侧“清除已结束（N）”；紧接着一行可换行的**站点筛选栏**（“全部 / B站 / 抖音 / 微博 / X”，带各站点状态圆点与未结束数），主体按固定站点顺序（B 站 → 抖音 → 微博 → X）**分站点展示**，每个站点分组头清晰标出该站点独立运行状态（“进行中 · 独立并行”“等待下一条 · 独立并行”“退避中 · 不影响其他站点”“已暂停”“排队中”“已全部结束”）与任务数；组内未结束任务按实际执行顺序排在已结束任务之前。下面每个队列一张卡片：头像、“账号名称 · 列表类型”（历史补全队列固定标题为「历史缓存补全 · 微博」）、站点小字、状态（或下次时间）与“已缓存 x · 跳过 y”（补全队列显示“已补全 x / z 条 · 跳过 y 条”），右侧展开箭头与操作（进行中“暂停”“取消”，等待退避 `waiting_backoff` 时额外提供强调色“立即重试”按钮触发单次手动探测并可立刻解除站点退避，已暂停“继续”“取消”，已结束“移除”，[DEC-089](decisions.md#dec-089)）；同站点未结束任务 ≥ 2 个时，状态行标注站点队列位次（`#1`、`#2` 及让位/优先提示），右侧操作组紧邻“暂停 / 继续 / 取消”提供紧凑的“置顶 / 上移 / 下移”按钮，首尾边界自动禁用，720/1000/1280 宽零横向溢出。点卡片展开：当前正在缓存/补全的条目、暂停或等待的原因、“最近缓存的内容”（本机封面——动态没有图片时用它引用的视频封面——、标题与缓存时间，点击直接打开本机内容）。从用户页“在缓存队列中查看”或设置页“查看补全队列”进入时自动定位到“进行中 › 缓存队列”并展开对应卡片。
  2. **直播（N）**（N 为正在录制的场数）：列出正在录制的直播行与最近结束的录制行（主播头像、直播标题、站点小字、橙色“录制中”标记、已录时长、大小、速度、段数与清晰度编码如“原画 · AVC”，进行中右侧“停止录制”）；没有录制在进行时显示“现在没有直播在录制”。

     - 最近结束的录制每行右侧“查看录像”“移除”，标题行右侧“全部移除（N）”：只从这个列表隐藏（8 天内不再出现），录像留在媒体库（DEC-057 ①）。
     - **页内实时预览**（DEC-049 ①）：在“直播”里点击一场正在录制的直播，在页面内直接实时播放正在写入的 `.part` 分片 MP4 画面（边写边读本机录制文件并等待新分片，**不另开任何站点连接**；画面落后直播约 10 秒以内；预览区不渲染弹幕、也不显示弹幕开关，实时弹幕待实现 FR-LIVE-003）。离开“直播”视图（含切到“进行中”“待处理”“记录”或离开任务页）、切换预览对象或停止录制时立即停止预览并同步释放文件句柄，换段时跟随新段或平滑结束，不影响 `.part` 的收尾转换与改名；若某条录制路径不支持实时预览，页面如实说明“这场录制暂不支持实时预览”。
  3. **待处理（N）**（N 为待处理内容冲突数 + 可重试失败/未完成下载任务数 + 近 7 天录制异常场数之和；为 0 时侧栏与窄窗分段显示“待处理”不带数字，图标栏“任务”角标不计入待处理项，[DEC-081](decisions.md#dec-081)）：统一汇总全部需要用户介入的事项，三个分组按需展示、全部为空时显示居中空状态“目前没有需要处理的事项”：
     - **内容冲突**（[DEC-076](decisions.md#dec-076) ⑤，[数据与缓存 §2.10](design/data-and-cache.md#conflict-protection)）：保留完整批量操作栏（默认选中无损的 **保留两版（推荐）**、**保留本地**、**用新版替换** 及该栏唯一的强调色主按钮 **批量应用**；批量“用新版替换”先展开行内二次确认）、白底 1px 细边框圆角冲突卡片（纯离线本地缩略图、浅琥珀色原因标签、两行脱敏差异对比框、失败横幅保留“（本地原文件未改动）”、单卡最多一个强调色主按钮 **保留两版**，以及 **保留本地**、行内确认的 **用新版替换**、**对比差异** 与纯离线 **查看本地**——打开 `/library/item` 后返回回到“待处理”）。
       - **内容冲突并列对比弹窗**：点击冲突卡片的“对比差异”打开（支持 Esc 与点击遮罩关闭；窄窗 `720px` 自适应宽度、零横向溢出）。弹窗顶部显示冲突原因、标题、站点小字与“刷新对比”，下方固定左右双栏栏头（左“本地已缓存（旧版 V1）”、右“源站当前（新版 V2）”；源站不可用或未登录时仍保留本地栏并说明原因）；主体分两区——**文字差异对比**（标题与正文/简介左右并排，字级差异在左侧以淡红底高亮旧文字、右侧以淡绿底高亮新文字；当任一侧存在安全外部超链接时，在正文左右两栏下方并排展示可点击的强调色超链接胶囊列表——悬停提示完整目标链接、点击经安全校验在系统浏览器打开，仅一侧有链接时另一侧明确显示“（无超链接）”，不含签名流地址或 Cookie；仅因 DEC-073 之前旧缓存内联 `(URL)` 格式造成的纯文字误报冲突会在读取或复核时自动清洗补写规范 `text`/`links` 并消解，不改动媒体文件）与**图片与视频并列对比**（按分 P `CID`/媒体标识对齐左右媒体卡片并标 `已变更` / `仅本地有` / `源站新增` / `可升级` / `相同`，展示分辨率、时长、编码与 `CID`，本地图片与视频可直接点击看图或播放，源站预览图仅内存按需加载、不写入 `cache-conflicts.json`）；底部提供“查看本地详情”“保留本地”“用新版替换（行内确认）”与强调色“保留两版（推荐）”。
     - **失败 / 未完成的下载任务**：汇总全部可重试的失败、部分完成与非用户手动暂停（如网络中断、应用退出暂停）下载任务，顶部提供“批量重试（N）”，每行展示失败或暂停原因、重试/继续与移除（行内确认）/取消操作。
     - **近期录制异常**：汇总最近 7 天（含进行中）有异常的录制场次，按场次列出主播/直播间、站点小字、开始时间与全部异常明细；进行中场次提供“查看正在录制”（跳转回“直播”），已结束场次点击本体或“查看录像详情”纯离线打开 `/library/item`（返回回到“待处理”）并提供“删除记录”（仅删异常记录，保留录像）。
  4. **记录（N）**（DEC-062、[DEC-081](decisions.md#dec-081)；N 为进行中与等待确认的导入导出数，为 0 时显示“记录”不带数字）：本次运行里的导入与导出，新的在上。每个一张卡片：上传图标、“导入 · <来源文件夹>”或“导出 · <目标文件夹>”、右侧状态（正在扫描 / 等待确认 / 正在导入 / 正在导出 / 已完成 / 失败 / 已取消）；进行中有进度条、“已复制 / 总大小 · 速度”（扫描时“已检查 / 总数”）、“取消”与当前条目名；扫描完等待确认的写各分类条数，右侧“放弃”与强调色“查看预览”（回到导入页）；结束后一行摘要（导入：“新增 · 补充 · 跳过 · 处理冲突 · 未传完 · 复制 N 个文件（大小）”，勾了删除来源时附删除的文件数；导出：“导出 N 个条目 · M 个文件（大小）”及本地已缺失的文件数），失败原因与没完成的条目红字列出。没有任务时空状态“还没有导入或导出”，说明从媒体库右上角“⋯”开始。

### 3.7 设置页（DEC-019）

打开设置时，**上下文侧栏是设置的分类**（DEC-038、DEC-039），图标栏不变：

- 侧栏最上面是返回箭头加“设置”（回到进入设置前的页面），下面是分类，只有**图标 + 名称**，不带说明小字；选中项浅强调色胶囊底、图标和文字强调色。宽度 ≥ 1000 时侧栏约 232px 显示名称，更窄时 72px 只显示图标（悬停有提示，带无障碍名称）。
- 内容区顶部栏标题就是分类名，下面直接是设置项，不再重复分类标题。
- 路径 `/settings/<分类>`，默认“账号”；分类列表以后可以加搜索框，现在不做。
- 设置内容不套卡片：分组和设置项之间只用细线分隔，不出现白、灰、白层层嵌套的框；侧栏条目文字 14px（DEC-040）。
- 每个设置项一行：名称 + 当前值 + 操作，用细线分隔。**设置项默认没有说明小字**；只有需要提醒后果或限制的具体设置才有一行说明（如“关闭窗口时”“检查间隔”“缓存保存位置”）。下拉框显示中文选项名（如“能拿到的最高（推荐）”“最小化到托盘（推荐）”），不显示内部值。改动立即保存，保存失败在该行下方显示原因。
- 分类：
  - **账号**（FR-AUTH-007、FR-WB-001、FR-X-001）：按站点分成四组，组标题“哔哩哔哩”“抖音”“微博”“X（原 Twitter）”，组之间细线分隔。抖音一组：已登录时头像、昵称、抖音号、“登录方式：粘贴 Cookie”、“自动续期：不可用，粘贴的 Cookie 与浏览器共用会话；过期后请重新粘贴”、“重新粘贴”“退出登录”（确认里说明会暂停抖音的缓存任务和录制，另外三个站点不受影响）；未登录时一个“登录抖音”按钮，打开登录页并预选抖音。微博一组：已登录时头像、昵称、`UID`、“登录方式：扫码登录”或“登录方式：粘贴 Cookie”、“自动续期：不可用，微博扫码登录暂不支持自动续期；过期后请重新扫码或粘贴 Cookie”（粘贴登录为“自动续期：不可用，粘贴的 Cookie 不续期；过期后请重新粘贴”）、“扫码重新登录”“重新粘贴”“退出登录”（独立确认“退出微博登录？”，只暂停微博的缓存任务与规则请求，另外三个站点不受影响）；未登录时提供“扫码登录”（主按钮）与“粘贴 Cookie”（次按钮），分别打开登录页并预选微博对应标签。X 一组：已登录时头像、昵称、`@handle` 与 `ID`、“登录方式：粘贴 Cookie”、“自动续期：不可用，粘贴的 Cookie 不续期；过期后请重新粘贴”、一行简版“风险说明”（非官方 API，建议使用专用账号，只读不写，遇验证或锁号即停）、“重新粘贴”“退出登录”（独立确认“退出 X 登录？”，只暂停 X 的缓存任务与规则请求，另外三个站点不受影响）；未登录时一个“登录 X”按钮，打开登录页并预选 X。哔哩哔哩一组如下：头像、昵称、`UID`、登录方式（扫码 / 手动凭证）；“自动续期”（扫码登录：“可用 · 上次续期 11 月 7 日 08:30”，失败时附原因；粘贴凭证：“不可用：粘贴的 Cookie 与浏览器共用会话，续期会让浏览器那边掉线。过期后请重新粘贴，或改用扫码登录”）；“重新登录”“退出登录”（退出时确认，说明会暂停缓存任务和录制）。
  - **缓存与下载**：同时下载数（1～4）；多 P 视频（全部分 P / 只缓存第 1 P）；缓存弹幕（开关）；缓存字幕（开关）；包括 AI 字幕（开关，缓存字幕关闭时禁用）；自动保存视频封面（开关）；微博同时保存无水印版（开关，默认开启，一行说明“主图保存官方原图，同时额外保存无水印最大版（oslarge），GIF 跳过。”，切换后立即生效，[DEC-078](decisions.md#dec-078)）。

  - **远程**（上传图标，DEC-062，[远程 §7](design/remote.md#status)）：没有连接时一节“连接远程”：一段说明（远程是 VPS 上的 `trace-server`，在 VPS 上运行 `trace-server init` 后把连接码粘贴到这里）、“远程连接码”输入框（或切换为分别填写地址、令牌、证书指纹三个输入框）、强调色“连接”（连接中“正在连接…”）与“分别填写地址、令牌与指纹 / 粘贴连接码”切换；失败时红字写原因（无法连接、证书变了、令牌错、版本不同各自的文案）；底部小字说明只连接指纹一致的远程、令牌存本机凭证。连接后：顶部一张浅灰卡片（名字、地址 · 版本 · 已运行时长、证书指纹缩写，右侧“刷新”与红色描边“断开”，断开前行内确认）；有错误时一条红底提示；下面按细线分节——**订阅**（“已同步”绿点或“有改动未同步”、远程订阅与账号数、上次同步时间，右侧强调色“同步订阅”，一行说明远程只缓存同步之后的新内容、“全部缓存”不在远程执行）；**登录**（哔哩哔哩、抖音、微博、X 四个站点各一行：状态圆点与“有效 · 昵称 · Cookie 同步于 …”/“需要重新同步”/“未登录”/“退避到 …”，前三个站点本地标了“Cookie 待同步”时写出来，右侧“同步 Cookie”，有登录时另有红色描边“清除远程登录”；点击 X 行的“同步 Cookie”不直接发请求，先弹出确认对话框说明云服务器机房 IP 风险——“在云服务器的网络上用网页 Cookie 访问 X，被要求验证或锁号的可能明显高于家里的网络，不建议本地和远程同时用同一个 X 账号检查”——确认仅对本次推送有效，取消零请求；下方一行说明 B 站/抖音/微博自动推送、X 绝不自动推送以及远程不续期）；**检查与缓存**（定时检查的账号数与下次时间、缓存中与排队数、录制中的场次、最近完成与失败）；**上传与空间**（上传方式与目标、待上传条目与大小、今天已传、正在上传的条目、最近一次失败的原因与下次重试，rclone 找不到等按类别说明；导出目录剩余 / 总空间，低于 5 GiB 警告、低于 1 GiB 写“已暂停新的缓存”）；**最近错误**（时间、类别、脱敏说明）。页面显示时每 30 秒刷新一次，离开页面不请求远程。
  - **移动端**（手机图标，[DEC-085](decisions.md#dec-085)，计划，见[第 3.12 节](#mobile)）。
  - **日志**（终端/日志图标，DEC-033）：上方“后台状态”卡片显示索引重建、检查更新、自动缓存、直播录制的当前情况；下方“最近运行日志”卡片以等宽字体显示脱敏后的最近运行日志（最多 500 行，经服务层接口读取，不含任何 Cookie 或签名 URL），右上角提供“打开日志文件夹”和“复制”按钮。
  - **更新**（刷新图标 `refresh`，放在“关于”之前，路径 `/settings/update`，DEC-051 ①，FR-UPD-001～003）：按细线分隔自上而下展示：① 当前版本区域：应用名（TRACE / TRACE Dev）、版本与通道（“正式版”或“开发版”）、“提交 1a2b3c4d5e6f · 构建于 2026-11-09 15:30 UTC”；② 更新方式一句话：正式版显示“打开 TRACE 时每 24 小时自动检查一次（可在下面关闭），也可以立即检查”，开发版显示“开发版不会自己联网检查；Agent 打包后会自动安装，正在运行的 TRACE Dev 会先退出，装完在托盘打开”；③ 通道专属区：正式版展示上次检查（时间与结果：已是最新 / 发现 `x.y.z` / 失败原因；没检查过写“还没有检查过”）、下次检查时间、右侧按钮（平时“立即检查”，检查中“正在检查…”不可点，有新版本未下载时“下载并安装”，已就绪时“重启以更新”）以及两行开关“自动检查更新”“自动下载更新”（默认开，改动立即保存；没有联网更新的构建写“这个构建没有联网更新”）；开发版不显示检查按钮与开关，显示“本机安装的开发版”（读取卸载项版本，未安装时如实说明；已安装版本高于正在运行的版本时提示“已安装更新的版本，重启 TRACE Dev 后生效”）；④ **检查记录**（最近 20 次：时间、自动/手动、结果；开发版说明不联网检查）与**更新记录**（最近 50 次：时间、从哪个版本到哪个版本、方式：自动更新 / 本机打包安装 / 手动安装）。
  - **关于**（FR-UPD-001、DEC-051 ①）：应用名（TRACE / TRACE Dev）、版本与通道、提交与构建时间；一行“版本与更新见‘更新’”（点击跳转到设置“更新”分类，不再重复放检查按钮与开关）；下方是诊断概览与第三方开源许可说明。

### 3.8 登录页

一个站点都没登录时唯一可进入的内容页（设置页除外）；已登录任一站点后也可以从设置或“请先登录”提示进入，来登录其他站点。居中一张卡片，最上面是站点切换（四段式切换“哔哩哔哩 / 抖音 / 微博 / X”，从提示进入时预选对应站点），标题“登录哔哩哔哩”“登录抖音”“登录微博”或“登录 X（原 Twitter）”，说明“TRACE 需要登录后才能解析和缓存”。

**抖音**只有“粘贴凭证”一种方式（FR-DY-001）：说明怎样在桌面浏览器打开抖音网页登录、进入「我的 → 喜欢」页面后从开发者工具复制请求头里的整段完整 Cookie（只写步骤，不放截图）；单行密码型输入框，占位“粘贴 Cookie（至少包含 sessionid）”；“验证并登录”；结果一句话：成功显示头像、昵称、抖音号后进入应用，失败写原因（“缺少 sessionid”“抖音认为这个 Cookie 没有登录或已过期”“抖音要求验证，请先在浏览器里正常打开一次抖音再复制”）。提交后输入框立即清空。

**微博**支持两个标签（FR-WB-001）：

- **扫码登录**（默认）：PC 网页 SSO 二维码、状态文字（请使用微博 App 扫码登录 → 已扫码，请在微博 App 确认登录 → 扫码登录成功 / 二维码已过期 / 已取消）、刷新二维码与取消扫码；标明“不自动续期”，切换标签、切换站点或离开登录页时自动取消进行中的扫码会话，遇风控或限流立即停止轮询。
- **粘贴 Cookie**：说明怎样在桌面浏览器打开 `weibo.com`、登录后从开发者工具复制请求头里的整段 Cookie；单行密码型输入框，占位“粘贴 Cookie（至少包含 SUB）”；“验证并登录”；结果一句话：成功显示头像、昵称、UID 后进入应用，失败分别说明缺 `SUB`、未登录或访客 Cookie、验证或风控且不保存、不改变已有凭证。提交后输入框立即清空。

**X（原 Twitter）**只有“粘贴凭证”一种方式（FR-X-001）：说明怎样在桌面浏览器打开 `x.com`、登录后从开发者工具复制发往 `x.com` 请求头里的整段 Cookie；单行密码型输入框，占位“粘贴 Cookie（至少包含 auth_token 与 ct0）”；**提交按钮上方**固定显示中立事实风险提示框（说明 X 网页端接口不是官方开放 API、X 条款限制自动化访问、存在触发限流/验证/临时锁号甚至封号风险、建议使用专门账号或小号但不阻止粘贴自有账号、TRACE 只读不写不存密码不自动续期、遇验证或锁号立即停止 X 全部自动请求）；“验证并登录”；结果一句话：成功显示头像、昵称、`@handle` 与 ID 后进入应用，失败分别说明缺 `auth_token`/`ct0`、未登录或访客态、账号不一致、限流（带预计恢复时间）或验证/锁定（“X 要求验证或账号被临时锁定，TRACE 已停止 X 的全部自动请求，请先在浏览器里处理”）且不保存、不改变已有凭证。提交后输入框立即清空。

**哔哩哔哩**下面两个标签：

- **扫码**：二维码、状态文字（未扫码 → 已扫码，请在手机上确认 → 登录成功 / 已过期）、取消与刷新。
- **粘贴凭证**：说明怎样从浏览器复制 Cookie（只写步骤，不放截图）；单行密码型输入框，占位“粘贴 Cookie（至少包含 SESSDATA）”；强调色胶囊按钮“验证并登录”；验证中按钮显示加载状态；结果用一句话说明（成功后进入主页；失败写原因，如“缺少 SESSDATA”“凭证已失效”）。提交后输入框立即清空。下方一行浅色提示：“凭证只保存在这台电脑上，并按当前 Windows 用户加密”。
- 登录已失效时卡片上方多一行：“登录已失效，请重新登录”。

### 3.9 订阅（DEC-026、DEC-033、DEC-051 ⑦）

每个界面区域最多只放一个强调色主按钮。

**订阅列表** `/subscriptions`：

- 顶部栏标题“订阅”，右侧只放一个强调色主按钮“添加订阅”和一个“⋯”（菜单“检查全部”“从关注列表导入”“批量设置缓存标签…”“导出订阅…”“导入订阅…”；检查进行中时顶部显示“正在检查 M / N”和“取消”按钮）。
- **导出订阅 / 导入订阅**（DEC-062、[DEC-070](decisions.md#dec-070)、[DEC-082](decisions.md#dec-082)，[远程 §6.4](design/remote.md#export-local)）：都是对话框。导出：标题“导出订阅”、一行说明（订阅、关联账号、缓存标签和部分设置，不含 Cookie；填文件夹时自动补上文件名）、路径输入框与次按钮“选择位置…”（唤起系统保存文件框，默认文件名 `trace-subscriptions.json`、`*.json` 筛选，保留手动输入）、“取消”与强调色“导出”，成功后右下角气泡提示“订阅已导出到 <文件>”。导入：标题“导入订阅”、路径输入框（文件或它所在的文件夹）、次按钮“选择文件…”（唤起系统打开文件框、`*.json` 筛选，选择新路径后清空旧预览；保留手动输入）与“预览”；预览一行摘要“新订阅 N 个 · 已订阅的账号 N 个 · 已全部订阅 N 个”，下面分节列出新订阅（名称、账号数、缓存标签摘要）、已在订阅里的账号（昵称、站点、本地在哪个订阅）与开关“把导入订阅里的新账号合并进这些已有订阅”（默认关：跳过已订阅的账号，其余账号建成新订阅）及“合并时一并加上导入订阅的缓存标签”（默认关：保留本地已有订阅原本的缓存标签）；底部“取消”与强调色“确认导入”（有预览后才出现），成功后关闭并提示新增的订阅数，失败在框内说明、什么都不改。
- 顶部栏下面一个搜索框（按订阅名、备注、账号昵称和自定义链接过滤，只在本机过滤）。
- 主体是**较大的圆形头像网格**（头像约 92px，下方一行订阅名称，过长自动省略），按可用宽度自动排列列数（3～5 列），按行虚拟化滚动（NFR-UI-002）。
- 正在直播的订阅头像外有橙色直播圆环，头像下沿带橙色胶囊小标“直播”（正在录制时带红点与“录制中”）；点击该直播/录制小标即可一键开始或停止录制，点击头像或名称进入订阅详情 `/subscriptions/:id`。
- **全部账号**（DEC-057 ⑥）：侧栏“全部账号”（窄窗 `< 1000` 宽由页面顶部“全部订阅 / 全部账号 / 检查计划”三段切换进入，720 宽无横向溢出）打开按站点列出全部订阅账号的页面：顶部“全部 / B 站 / 抖音 / 微博 / X”与“N 个账号”，下面每个账号一行：头像、名称与站点小字、“UID …”“抖音号 …”或“`@handle`”及作品数（B 站与抖音写“作品 N · 已缓存 M · <统计时间> 统计”，微博写“微博 N · 已缓存 M · <统计时间> 统计”，X 写“帖子 N · 已缓存 M · <统计时间> 统计”；还没解析过这个账号时写“已缓存 M · 作品总数在打开主页后统计”，DEC-061 ②），右侧胶囊“订阅 <所属订阅名>”和行尾“⋯”菜单（“更改关联订阅”“打开订阅”“打开主页”）；按固定站点顺序（B 站 → 抖音 → 微博 → X）、再按名称排序，虚拟滚动；点一行进入所属订阅的详情。
- **检查计划**（`/subscriptions/checks`，DEC-059 ①、[DEC-080](decisions.md#dec-080)、[DEC-081](decisions.md#dec-081)）：侧栏“检查计划”（位于“全部订阅”“全部账号”下方；窄窗由页面顶部三段切换进入）打开所有订阅账号的定时与开播检查排程页。顶部一行“下一轮定时检查：今天 21:07”（没有订阅开启定时检查时写“当前没有开启定时检查的订阅”，已开启站点均未登录时写“已开启定时检查的站点当前未登录”），下面两行小字：更新检查每轮每个站点最多检查的账号数（B 站 30、抖音 20、微博 25、X 15）、上次查得早的先查、额度不足或退避时顺延；开播检查的规则摘要（B 站每轮查全部，抖音两次至少隔 6 秒、一轮最多几个、超过后轮流查、不占每小时额度，微博与 X 不查开播，完整规则见设置 › 订阅与直播，DEC-060 ⑤）。每个订阅账号（含微博与 X 账号）一张卡片：头像、昵称、站点小字、所属订阅名；“更新检查：上次 今天 20:07 · 正常”（从未检查时“还没有检查过”，失败时红字写原因，如“本小时额度用完，已顺延”）；开了“开播录制”的订阅，哔哩哔哩与抖音账号再加一行“开播检查：上次 今天 20:51 · 约每 3 分钟”，微博账号显示“微博直播暂不支持录制”、X 账号显示“X 直播与 Spaces 暂不支持录制”（`LiveNote`）而不显示开播频率；右侧“下次 今天 21:07”（退避时“退避后 …”），或“只手动检查”“定时检查未启用”“未登录，不检查”。按下次检查时间排列，不发站点请求，每 20 秒重读一次本机状态。顶部右侧“检查全部”，检查进行中换成“正在检查 x / y”与“取消”；每张卡片最右“检查”只查这一个账号，查的时候显示“检查中…”，其他卡片的按钮暂不可用，未登录站点的账号按钮不可用（DEC-060 ③）。
- 空状态：“还没有订阅。把你关心的人建成订阅，一个人可以关联他的多个账号”，搭配顶部“添加订阅”主按钮和空状态“从关注列表导入”按钮。

**添加订阅**（对话框，[DEC-080](decisions.md#dec-080)）：名称输入框（必填，≤ 64 字）；“关联账号”输入框（可选，粘贴哔哩哔哩主页链接或 UID、抖音主页链接/分享文本/`sec_uid`、微博主页链接/分享文本，或 X 主页链接/分享文本，可预览显示头像、昵称、站点小字与 UID/抖音号/`@handle` 确认卡片；账号已属于别的订阅时卡片里写“该账号已属于订阅 X”并提供“创建并移到新订阅”；不属于任何订阅、且已有订阅时，卡片里另有“加入现有订阅…”，关闭这个对话框并以预览的账号打开加入订阅对话框）；“追踪模式”选择区（默认选中“完整存档（默认）”，可选“追更并保存”“只看新动态”“仅手动”，右上角可叠加开关“录直播”，点“自定义”展开全部 7 个原子标签，若选了自动缓存但未选`定时检查`则显示温和提醒）；强调色主按钮“确认添加”。

<a id="subscribe-picker"></a>**加入订阅**（对话框，DEC-058、[DEC-080](decisions.md#dec-080)，FR-USER-003）：用户页“订阅”（哔哩哔哩、抖音、微博与 X）、“我的”里关注的人“⋯ → 加入订阅”、添加订阅里的“加入现有订阅…”都打开它。顶部是账号头像、“订阅 <昵称>”与站点小字，一行说明“加入一个现有订阅（同一个人的多个账号放在一起），或者新建一个订阅。”；紧凑的“新建订阅追踪模式”选择区（默认“完整存档（默认）”，支持切换预设、叠加“录直播”或展开“自定义”原子标签）；下面是唯一的强调色主按钮“新建订阅“<昵称>””（按所选追踪模式新建，名称即昵称）；再下面“或加入现有订阅”、搜索框（按订阅名称、备注与账号昵称过滤，输入法组合输入时不过滤）与订阅列表（头像、名称、一行“B 站 N · 抖音 N · 微博 N · X N · 备注”，右侧“加入”，虚拟滚动；没有订阅时写“还没有订阅，可以新建一个”，没有匹配时写“没有匹配的订阅”）。点一行把账号加入那个订阅并关闭，右下角气泡提示“已把 X 加入订阅“Y””；失败（例如账号已属于别的订阅）在列表下方说明原因、对话框不关。底部“取消”；Esc 与点空白处也关闭。

**更改关联订阅**（对话框，[DEC-080](decisions.md#dec-080)）：从订阅详情 › 账号行尾“⋯ → 更改关联订阅”或订阅 › 全部账号行尾“⋯ → 更改关联订阅”打开，与“加入订阅”共用搜索选择框；标题为“更改关联：<昵称>”加站点小字，副标题写明当前所属订阅并说明保留已缓存内容与检查起点；提供“新建订阅追踪模式”选择区（默认“完整存档（默认）”）与主按钮“移到新建订阅“<昵称>””原子新建并移入该账号，下方搜索列表排除当前所属订阅（无其他订阅时显示“还没有其他订阅，可以移到新建订阅”），点选任一目标订阅即原子转移并刷新界面，不发站点请求。

**订阅详情** `/subscriptions/:id`：

- 顶部返回箭头与订阅名。详情头部（不套卡片）上方是大头像、订阅名（及备注说明）和一个“⋯”（菜单“检查更新”“改名”“备注”“自定义链接”“更换头像”，分隔线后红字“删除订阅”；检查中头部附“取消检查”）。配置了自定义外部链接（[DEC-074](decisions.md#dec-074)）时，头部下方紧跟一行自动换行的可点击链接胶囊（外链图标 + 显示名称或自动提取的域名/路径，悬停提示完整 URL，点击经 `OpenExternalLink` 校验 `http://`/`https://` 后在系统浏览器安全打开）与末尾“管理链接”胶囊；再下一行是**追踪模式与缓存标签栏**（[DEC-070](decisions.md#dec-070)、[DEC-080](decisions.md#dec-080)）：左侧为主下拉按钮“追踪：<预设名或自定义> ▾”，开启开播录制时旁列可点关闭的“录直播”胶囊，处于“自定义”组合时同时显示已开启的原子标签胶囊（点击可移除）。点击下拉按钮弹出 4 个意图预设（勾选当前匹配预设，点击一键切换并保留“录直播”状态）、“录直播”开关、“自定义原子标签 / 收起原子标签”（展开行内全部 7 个原子标签芯片逐项切换）、“清空全部标签”（有标签时）以及“批量管理缓存标签”（进入设置 › 缓存标签）。当开启了任意自动缓存标签而未开启`定时检查`时，标签栏下方显示温和提示“已开启自动缓存但未开启「定时检查」：仅在手动检查更新时生效。”并提供一键“开启定时检查”按钮。
- **自定义链接**（对话框，[DEC-074](decisions.md#dec-074)）：从详情头部“⋯ → 自定义链接”或“管理链接”胶囊打开；列出当前订阅已保存的外部链接（可点击打开、逐条“编辑”或红字“删除”），下方提供“显示名称（可选，留空自动生成）”与“`http://` / `https://` 地址”输入框及强调色“添加”按钮（输入法组合输入期间回车不误提交；非法协议、凭证参数或重复链接在框内提示原因）。
- 标签栏只有两个：**内容**（默认，`tab=content`）、**账号**（`tab=accounts`；旧保存状态或路由里的 `live` 读入时自动归到“账号”，DEC-051 ⑦，替代 DEC-040 的“直播 / 账号”标签；不再有“更新”“已缓存”“规则”标签）；从任一标签点开哔哩哔哩、抖音、微博或 X 账号主页（及从该主页再进入单条详情）后，按顶部返回箭头逐级回到这个 `/subscriptions/:id` 并**保留原激活标签**（不退回订阅列表或重置标签）：
  - **内容**（默认）：这个订阅**全部关联账号**（含同时关联的哔哩哔哩、抖音、微博与 X 账号）已缓存内容的信息流（动态、视频、作品、微博、X 帖子与已录制的直播录像帖子），与主页时间线（及主页点进单订阅视图）共用同一套帖子渲染、虚拟化列表与滚到底自动加载更早内容，固定按发布时间（录像按开播时间）从新到旧排列，全程只读本机索引与清单、零站点网络请求；每条帖子右上角的“⋯”可“在资源管理器中显示”与“删除”，用来清理异常的缓存（含只有文字或图片的动态，DEC-064），删除后列表从最新处重新载入；没有已缓存内容时显示“还没有缓存这个订阅的内容”，并按订阅实际标签给出准确的下一步提示（如已开启`全部缓存`时说明后台慢速队列会陆续补齐、也可切到“账号”打开主页立即浏览和缓存；已开启定时与自动缓存时说明后续新内容会自动追踪并缓存、历史内容可在“账号”浏览缓存；仅开启自动缓存未开启`定时检查`时提示仅在手动检查更新时生效；仅定时检查或仅手动时分别说明原因并引导切换追踪模式或在“账号”手动缓存；不加额外强调色主按钮，零网络请求，[DEC-080](decisions.md#dec-080)）。
  - **账号**（合并原“直播”）：关联账号按固定站点顺序（B 站 → 抖音 → 微博 → X，同一站点的多个账号保持原有相对顺序，[DEC-071](decisions.md#dec-071)）排列，每个关联账号一行——第一行显示头像（优先使用本机头像副本，DEC-051 ⑥）、昵称、站点小字（“B 站”/“抖音”/“微博”/“X”）、UID、抖音号或 `@handle`；第三行是与“全部账号”相同的作品数（DEC-061 ②，微博显示“微博 N · 已缓存 M”，X 显示“帖子 N · 已缓存 M”，打开页面不发请求）；哔哩哔哩与抖音账号的第二行显示直播状态（未开通直播间 / 未开播 / 直播中“标题 · 清晰度与编码，如 原画 · AVC” / 录制中“已录 时长 · 大小”及清晰度编码），直播中或录制中时右侧放置“录制”（强调色主按钮）或“停止录制”按钮；**微博与 X 账号不显示直播状态、不出现录制按钮**。其余操作收进该行的“⋯”菜单（“打开主页”、“在浏览器中观看”（微博与 X 不含直播观看）、“用作头像”、“更改关联订阅”、“解除关联”、“刷新直播状态”（仅 B 站/抖音））。已录制的录像不再在这里重复列出（在“内容”标签里作为直播录像帖子出现）。底部保留“关联另一个账号：粘贴主页链接或 UID”输入框与预览确认卡片（未直播时确认按钮为该标签页唯一的强调色主按钮）。
- 删除订阅确认框：“删除订阅‘X’？只删除这个订阅和它的账号关联，不删除已缓存的内容，也不会在站点上取消关注。”按钮“确认删除订阅”与“取消”。

**从关注列表导入** `/subscriptions/import`：

- 顶部返回箭头与“从关注列表导入”；下面一行：站点切换（“哔哩哔哩 / 微博 / X”，未登录所选站点时提示先登录）、分组下拉（哔哩哔哩为全部关注、特别关注、各分组带人数；微博仅在服务端返回分组时显示分组下拉；X 无分组）和本页搜索框。
- 列表每行：复选框、头像、昵称、签名首行；已经属于订阅的账号复选框禁用，写“已在订阅‘X’中”。滚到底加载下一页，失败时底部显示原因和“重试”，已加载的保留。
- 底部操作区包含紧凑的“导入后追踪模式”选择区（默认“完整存档（默认）”，可切换预设、叠加“录直播”或展开“自定义”原子标签）与固定操作栏：“已选 N 个”、“全选已加载”、强调色“导入 N 个订阅”；导入完成后提示“已建立 N 个订阅”，并回到订阅列表。

### 3.10 托盘与退出（DEC-030）

- 托盘图标与应用图标用同一套图形画（`internal/brandicon`）：深灰底白色“T”，开发版与测试身份右下角带同样的琥珀色“DEV”角标、正式版没有；有缓存任务或直播录制时保持静态通道图标，不在右上角加琥珀色活动圆点，悬停提示固定为应用显示名“TRACE”（开发版为“TRACE Dev”），不被动显示缓存或录制数量，缓存与录制状态在打开窗口进入“主页”或“任务”时主动查看（[DEC-072](decisions.md#dec-072)）。
- 单击图标打开窗口（已打开就置前）；右键菜单只有“打开 TRACE”（开发版为“打开 TRACE Dev”）和“退出”两项（DEC-050），是在指针处打开的系统原生菜单（系统菜单字体，与图标之间没有空隙，首项为默认项，与“退出”之间以分隔线隔开）。有任务或录制时点“退出”先弹确认框（同下一条）。
- 窗口里退出（托盘菜单之外，例如设置“常规”里关闭行为为“退出”时点关闭按钮）：有任务或录制时弹确认框，写明会暂停几个任务、结束几场录制，按钮“退出”与“取消”。
- 第一次关到托盘时的系统通知：标题“TRACE 仍在后台运行”，正文“缓存、定时检查和录制会继续。可以从托盘图标打开或退出”。

### 3.11 我的（DEC-047）

登录账号自己在站点上的关注、收藏、稍后再看、历史等列表（FR-ACCT-001～005），在线浏览、只读。

**上下文侧栏**（≥ 1000 宽）：

- 顶部页名“我的”。下面四组，组头是站点名“哔哩哔哩”“抖音”“微博”“X”（14px，600），左边一个展开箭头（折叠向右、展开向下），右边是该站点登录账号的小头像（24px；未登录时是灰色“未登录”小字）。
- **启动后四组都折叠**；点组头展开该站点、同时折叠其他组（手风琴）；再点已展开的组头折叠它。展开状态与选中的功能只在这次运行里保留，不写进 `ui-state.json`。
- 展开后列出功能条目（图标 + 名称，选中项浅强调色底、强调色文字）：
  - 哔哩哔哩：**关注**、**收藏夹**、**稍后再看**、**历史记录**；
  - 抖音：**关注**、**喜欢**、**收藏**、**观看历史**（`ACT-026` 实测确认可用后开放，[Q-015](https://github.com/chialecode/trace/issues/22) 第 3 条）；
  - 微博：**关注**、**收藏**，以及真实检查确认可用后才出现的**赞过**与关注分组筛选（[Q-023](https://github.com/chialecode/trace/issues/22) 第 3 条，默认隐藏）；
  - X：**关注**、**书签**、**喜欢**，以及真实检查确认可用后才出现的**书签文件夹**与**列表**（[Q-024](https://github.com/chialecode/trace/issues/21) 第 9 条，默认隐藏）。
- 站点未登录时展开后只有一行“未登录 · 登录”（点“登录”进入登录页并选中这个站点，登录成功回到“我的”）；登录失效时同样，写“登录已失效 · 重新登录”。不显示做不了的功能。
- 收藏夹与抖音收藏的“哪个收藏夹”不放在侧栏，放在页面顶部（见下）。

**页面**：

- 没有选中功能时（刚进入）：页面中间一句“在左侧选择一个站点和功能”，不发请求。窄窗（< 1000，没有侧栏）时页面本身列出与侧栏相同的四组与功能条目（同样默认折叠），选中后进入列表页，顶部栏左侧出现返回箭头回到这个列表。
- 顶部栏标题是“<功能名>”加站点小字（如“收藏夹 · B 站”），右侧是一个“⋯”（“刷新”“在浏览器中打开”——打开站点上对应的页面）。
- 第一次选中某个功能时才请求第一页；滚到底自动加载下一页（加载中底部一行“正在加载…”）。之后切到别的功能再切回来，列表与滚动位置都保留、不重新请求；“⋯ → 刷新”才从第一页重来。
- 状态（NFR 与 FR-ERR-001 同口径）：首次加载中显示 6 行灰色占位；**真正为空**写“还没有关注 / 收藏夹是空的 / 稍后再看是空的 / 还没有历史记录 / 还没有喜欢的作品”；到底写“没有更多了”；风控、限流、登录失效、网络、格式变化在列表底部（首屏失败时在页面中部）写原因与“重试”，已加载的条目保留。
- 条目点击与菜单（FR-ACCT-003）：点条目本体打开详情（视频详情、抖音作品详情或用户页，与从用户页点开相同，记入最近解析，DEC-038 的“点开即跳转”）；从详情点返回箭头回到“我的”同一位置。右侧“⋯”：视频与作品为“缓存”（仅未缓存时）、“复制链接”、“在浏览器中打开”；用户为“加入订阅”（已在订阅里时改为“打开订阅‘X’”）、“在浏览器中打开”。状态圆点规则同[第 3.3 节](#status-dot)。打不开的条目整行用次要文字色，本体不可点。

### 3.12 移动端（DEC-085，计划）

尚未实现；行为与接口见[移动端设计](design/mobile.md)，需求见 [§2.13](requirements.md#mobile-scope)。

**电脑端“设置 › 移动端”**（`/settings/mobile`，放在“远程”之后）：

- 第一行开关“允许手机连接”（默认关），一行说明“手机只能在同一局域网（或你自己的 VPN）里连接这台电脑；关闭窗口时选了‘退出’的话，窗口关掉后手机就连不上了”。打开后下面一行状态：“正在监听 192.168.1.20:47381”（多个地址都列出）；端口被占用或防火墙阻止时红字写原因与处理办法（第一次打开时 Windows 可能弹出防火墙提示，需要允许“专用网络”）。
- **手机**一节：已配对的手机每台一行（手机图标、名称、型号、“在线”绿点或“上次连接 11 月 26 日 09:30 · 192.168.1.35”），右侧“⋯”（改名、移除；移除前行内确认“移除后这台手机要重新扫码才能连接”）；最多 5 台。右上角强调色“添加手机”。
- **添加手机**对话框：二维码（约 240px）、5 分钟倒计时与“刷新”，下面一行“用手机上的 TRACE 扫码；扫不了时输入 地址 + 配对码 3F7K-9Q2M”，再一行“电脑身份码 3F7A-91C2-0B5E-D844（手动输入时请在手机上核对）”；手机扫码后对话框换成确认：“允许『Pixel 9』连接这台电脑？”与“拒绝”/强调色“允许”。
- 底部“重置移动端身份”（红色描边，确认说明“所有手机都要重新配对”）。

**手机端**（MyGo 原生界面，[设计 §7](design/mobile.md#app)）：

- 视觉沿用本规范：白底与浅灰分区、强调色 `#1a73e8`、直播橙色、站点小字“B 站”“抖音”“微博”“X”、状态如实（第 6 节）；字号随系统，最小触控 44 dp；只用浅色主题。
- **配对引导页**（没有配对记录时）：标题“连接你的电脑”，三步说明（在电脑上打开 TRACE → 设置 › 移动端 → 添加手机），强调色“扫码连接”，次要按钮“手动输入”（地址与配对码两个输入框，组合输入时回车不提交；连接后先整页显示“电脑身份码 3F7A-91C2-0B5E-D844”与“请与电脑上显示的逐组核对”，按钮“一致，继续”/“不一致，取消”）。扫码或核对后显示“等待电脑上确认…”。
- **连接页**（未连上、断开时整屏覆盖，任何旧内容都不显示）：电脑名与图标、一句原因（[设计 §8](design/mobile.md#states) 的文案）、强调色“重试”与“重新扫码”；正在连接时显示转圈与“正在连接 192.168.1.20…”。
- **底部标签**：主页、媒体库、订阅、任务（角标同电脑端）、我的电脑。二级页面用系统导航栏与返回。
- **主页**：顶部站点筛选（横向分段，可滑动）与订阅头像条（直播圈、未读圆点）；帖子同电脑端主页的帖子，单列铺满，图片按原比例 / 九宫格，带有回复上下文的 X 帖子正文上方显示次要灰字「回复 `@<screenName>`」（自回复串内部普通续帖不显示，[DEC-091](decisions.md#dec-091)），X 作者自回复串同样采用适配 360dp 宽度的纵向头像连线布局、分段媒体与线程节点内嵌引用展示（>4 条默认展开前 3 条并可原地展开/收起，[DEC-090](decisions.md#dec-090)），引用框支持最多 1 层内嵌引用摘要，点图片看图、点视频卡片播放；下拉刷新。
- **媒体库**：顶部筛选按钮打开底部面板（类型、站点、订阅/作者）；网格两列（平板三到四列）16:9 缩略图、两行标题、一行元信息，长按或“⋯”打开详情（X 离线详情同步展示「回复 `@<screenName>`」提示、纵向头像连线各段正文/媒体/节点内嵌引用及最多 1 层嵌套引用摘要，不重复渲染拼接正文）。
- **看图**：黑底全屏，双指缩放、双击放大、左右滑；顶部半透明栏：关闭、“3 / 9”、“查看原图”、有伴侣图时“原图 / 无水印”；实况照片左上角“实况”。
- **播放**：系统播放器全屏，可横屏；多 P 时底部面板选分 P；不能解码时整块深色底写“这台手机不能播放 AV1 视频”。
- **订阅**：顶部分段“全部订阅 / 全部账号 / 检查计划”（同电脑端订阅页）；全部订阅是头像网格（圆形头像、名称、直播/录制标记）；检查计划只看排程，顶部“检查全部”、每行“检查”；详情顶部头像与名称、跟踪预设与能力标签胶囊（只读）、自定义链接胶囊，分段“内容 / 账号”，账号行右侧“录制”/“停止录制”。
- **任务**：顶部分段“进行中 / 直播 / 待处理 / 记录”（同电脑端任务页四组）：进行中含下载任务与缓存队列，直播含录制中与最近结束的录制，待处理含内容冲突（只读，顶部一行“在电脑上处理”）、失败或未完成的下载任务与录制异常，记录是导入导出（只读）。每行的左滑或“⋯”只给这一行能做的操作，规则同电脑端：下载任务按状态给暂停、继续、取消、重试、移除（已结束的只有重试或移除）；缓存队列给暂停、继续、取消，结束的可以移除；“直播”组正在录制的给“停止录制”，其余只看；内容冲突与导入导出没有操作。
- **我的电脑**：电脑名、版本与通道、运行时长、四个站点登录状态（只读）、剩余空间、连接地址；底部红色“解除配对”（确认）。

<a id="states"></a>
## 6. 状态

每个页面都要覆盖：加载中（骨架屏，不用整页转圈）、空状态（告诉用户下一步做什么）、错误（按错误类别给一句说明和下一步按钮，[错误分类](research/bilibili.md#errors)；X 未登录写“请先登录 X”，限流写明预计恢复时间，验证或临时锁定写“X 要求验证或账号被临时锁定，TRACE 已停止 X 的全部自动请求，请先在浏览器里处理”）、部分成功（列表已加载的部分保留，底部显示错误和“重试”）、到底（明确说明没有更多）。

<a id="accessibility"></a>
## 7. 可用性

- 键盘：Tab 顺序合理，焦点环可见；Esc 关闭弹层；输入框按回车提交（组合输入时除外）；看图层左右键切换、`+`/`-` 缩放、`0` 适应窗口。
- 图片有替代文字；只显示图标的按钮有无障碍名称和悬停提示；状态圆点有文字名称。
- 长中文标题按行截断，不撑破布局；数字用“万”“亿”缩写（如 12.3万），悬停显示精确值。
- 界面截图只证明看到的状态；后台行为、键盘和输入法要分别验证。
