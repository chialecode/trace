## 开发流程

| 编号 | 决定 | 正本 |
| --- | --- | --- |
| DEC-001 | 开发由 A 规划整个阶段并集中审查、B 连续实现与自检；A 审查通过后直接向用户交付，不再交 B 复审。每次计划尽量覆盖完整阶段，减少交接轮次；双方结束时都给出可复制给对方的 prompt | [开发流程 §2](dev-rules/workflow.md#agent-handoff) |
| DEC-002 | 连续执行、集中审批：需要用户做的事只写在 USER-ACTIONS；非阻塞事项按默认值继续，不打断开发 | [开发流程 §1.1、§3](dev-rules/workflow.md#continuous-execution) |
| DEC-003 | 通用技术优先采用活跃开源方案；网站规则单独研究，下载器的支持列表不代表满足需求 | [来源与安全](dev-rules/sources-and-safety.md) |
| DEC-004 | 先做基本功能 MVP，再按反馈迭代；数据正确、凭证隔离、真实状态不因 MVP 放宽 | [开发流程 §1.2](dev-rules/workflow.md#mvp-loop) |

| DEC-007 | 项目关键内容（决定、选型、契约、版本、故障与证据、交接 prompt）写进仓库长期保留 | [开发流程 §5.3](dev-rules/workflow.md#project-records) |

| <a id="dec-025"></a>DEC-025 | 构建与测试产物只保留最新一份（用户，2026-11-07）：打包固定输出到 `dist/trace-windows-x64/`，每次替换成最新包，包旁 `trace-data/` 里的登录与缓存保留继续用；`artifacts/` 每类只留最近一次（输出位置与“包旁 `trace-data/`”已由 [DEC-029](#dec-029) 替代：数据不再放在包旁，打包输出按通道放在 `dist/<通道>/`；“只留最新”不变） | [工程规则 §5](dev-rules/engineering.md#generated-outputs) |
