# 两站全内容归档与录制契约

状态：active（2026-10-17核对）。§1～6为内容类型、全内容、质量与直播的数据合同，§7～8为获取历史与升级确认，§9为链接到真实下载/录制的要求；多站规则目录、统一元数据、订阅与下载位置见[多站契约](design/multi-site-contracts.md)。实际接线和故障只见代码、[状态](delivery/status.md)及[阶段报告](delivery/stage-report.md)。本页细化[设计](design.md)且不替代INV；历史自动证据不代填新行为，来源事实见[解析资料](research/site-parsing-current.md)。

## 1. 身份、类型和覆盖

每项记录包含内部 entry_id、平台命名空间、账号稳定 ID、原生内容 ID、原生类型与归一类型。dynamic、opus、article、BV/av/cid、aweme、room 和 session 分别表达；跨类型映射记录来源证据，禁止仅按字符串数字相同合并。转发是一条独立发布记录，指向原内容并保留转发正文，原文失效仍可读已有快照。未知卡保留安全文字/来源和 unsupported 原因，不能以空媒体清单确认完整。

订阅可以同时选动态、图文、长文、视频和直播；每类独立游标/覆盖，增量与历史独立调度。覆盖含扫描范围、页/条数、最早最新观察、结束原因、会话能力、预算消耗和未覆盖类型。列表摘要不降级覆盖完整详情；置顶、编辑、乱序、延迟出现和重复游标不导致提前完成。暂停撤销代次，迟到页/资源/录制提交拒绝；恢复幂等，不消耗失败预算。

## 2. 元数据保存目录

以下字段族由版本化 DTO/schema 与安全站点扩展表达；实际载体与读取接口见第 6 节。所有大整数 ID 用字符串；时间携带来源、精度、时区/单位及 observed_at。未返回、明确为空、权限受限、解析不支持分别表示，不能用 0 或空串补成事实。

API 已提供的安全元数据尽量保留，不只选固定几个标题字段。公共归一字段与版本化站点扩展并存；扩展递归过滤认证头、Cookie、token、签名 URL、设备指纹和无关用户信息，限制深度、字符串及整体大小。超限记录省略字段/原因；不能把未过滤原始 JSON 当长期档案。主体完整性、资源完整性、附属评论覆盖和质量达标独立计算。

## 3. 资源与本地阅读

动态/文章下载应保存全文与内嵌资源，离线渲染仅通过 blob ID 获取本地字节。外链点击有明确外部动作，渲染不自动请求追踪图或执行脚本；禁止事件属性、iframe、javascript URL、任意 CSS URL。净化后仍保留原顺序、必要语义和缺失占位；原始不可信内容不能直接进入 v-html。

多 P、DASH 音视频、durl 独立有序段、图集、文章附件分别表达 required/optional。逐段与整组已知长度/摘要全部核对，全部必要组通过才切换引用；不按总量平分，不直接拼接媒体。下载长连接采用空闲超时与取消，不以 30 秒总时限截断正常大媒体。签名失效按稳定 ID 重解析；强 ETag Range 验证，证据不足安全重下。

同一主体的更高质量候选按质量策略验证后短事务切换保留引用，失败保持旧版；§7的登录后补全还必须等待用户确认。用户固定保留、共享 blob 和独有直播覆盖不得被回收。派生预览不替代原件，不能比较时记录 unknown/incomparable。历史副本删除与停止订阅、清缓存、删除档案独立处理，删除代次防止迟到任务复活。

## 4. 直播状态、传输与恢复

房间检测状态与录制会话状态独立。会话至少表达 waiting、recording、reconnecting、stopping、sealed、interrupted/failed，并记录原因；同一房间/场次最多一个有效录制租约。来源未给稳定场次 ID 时使用本地持久会话 ID 加房间/开播证据，不每次重连创建新场次，也不把下一次开播合进旧场次。

FLV/TS/fMP4 按有界片段保存：默认每 10 分钟或 512 MiB 轮转，可配置；以可解复用边界封口，字节上限不能直接截断后伪称可播放。HLS 处理 master/media、音轨、MAP、BYTERANGE、media sequence、discontinuity、ENDLIST、key/IV/轮换和重复/滑出窗口；缺片记录 gap，不能填补或跳过后宣称无缝。普通授权 AES-128 可按受控方案处理，DRM/不可得密钥明确受限，不绕过授权。

core 负责所有媒体、清单、key、初始化片段和重定向的逐跳 DNS/IP/域名/凭据校验；FFmpeg 只处理本地输入或窄管道，禁止接收任意远程 URL 或 file/concat 注入。签名计划在内存；重连刷新后核对房间/场次，退避有上限，两个站点互不拖死。磁盘预算、缓冲、队列与子进程均有界；丢弃不能静默。

封片、对象入库、引用与事件有明确提交边界；PREPARED/OBJECT_READY/引用提交后任一崩溃重开不重复、不丢已封口片。未封口片标记需修复，不冒充完整。暂停、单场停止、停订阅、停插件、完全退出撤销旧代次并封口；手动停止本场后不能被下一轮轮询立即重启本场。GUI 关闭继续后台，完全退出等待有界封口并记中断。休眠时间不能算作录制时间。

## 5. 兼容与控制接口

旧 schema 的数据库、旧备份与插件协议 0.x 是兼容输入；现行 schema 版本以 `crates/domain` 的 `SCHEMA_VERSION` 为准，控制/插件协议仍为 0.x，新增字段采用 serde 默认值与能力声明。增加版本化迁移和旧 fixture，失败保留可恢复备份；新格式被旧程序拒写。DTO 新字段定义 serde 默认/缺省行为，版本协商不兼容时明确拒绝，禁止把未知类型当视频。未知站点扩展仍可离线浏览、导出和恢复。

UI、CLI、后台复用同一持久服务。所有创建/更新/暂停/恢复/录制/停止/补查/导出命令必须有身份、版本、幂等、错误和取消语义。查询组合筛选、entry_id 定位、排序、分页和统计使用同一过滤条件；事件刷新保留有效选择、已加载页、媒体节点及 currentTime，失效才清理。实际方法和失败边界如下；桌面命令仅转发同一 Core 服务。

普通订阅默认300秒、直播30秒、元数据最小2秒加0～250ms抖动、每轮10页、下载全局2路/每账号1路、直播默认4路；Profile和后台状态显示实际值。派生文件使用本地FFmpeg，受共享缓存锁与提交预算约束。凭证与所有采集类型、备份/导出/维护任务复用租约检查，退出安全封口最多等待8秒，超时保留可恢复物化记录。具体覆盖与真实条件仍以阶段报告、能力表和 USER-ACTIONS 为准。

## 7. 获取认证历史与登录后补全

依据 FR-AUTH-007、FR-QUALITY-006、FR-LIVE-007 和 AC-26～28。`quality.list/configure` 和当前凭证状态不能代替这里的获取记录或统一确认页。

### 7.1 身份、采集观察与两条时间线

Core 为一次资源获取保存不可变的认证上下文：本地 acquisition ID、entry/revision/resource/variant 关联、获取起止、`anonymous/authenticated/expired/unknown`、验证时间及结果依据、所用凭证的本地不透明引用和代次。具体类型由 contracts 定义；凭证路径、Cookie、认证头、签名参数和秘密的摘要不进入普通档案。恢复或导出保留安全状态/时间，不继承可用凭证；历史标签与当前凭证引用是否有效是两个字段。

认证标签属于解析与获取所使用的请求身份和凭证代次，不能只看最后一跳媒体 HTTP 有没有 Cookie。全程以访客身份解析和获取才标 anonymous；authenticated 需要对应站点、同一凭证代次在本次采集批次的能力验证证据，不能只检查 Cookie 非空或数据库曾标 valid。已认证解析取得临时媒体地址后，Core 按域规则不向 CDN 附加 Cookie，仍保留该解析身份的 authenticated 获取上下文；不得为了标签把 Cookie 发送给 CDN。匿名回退必须建立独立上下文，不沿用上一次已登录解析的标记。

失效、访客降级和网络未知分别记录；重试/更新凭证后新一次获取另有上下文，不能回写旧观察。登录有效与资源已达最高质量分开，保留目标、来源可得候选、选中和实际探测规格。现场无法证明时质量为 unknown。

登录/未登录是同一内容库按获取上下文投影的两条时间线；同一 entry 可在两边出现，不能复制内容身份或按 Cookie 构造 entry ID。unknown/expired 有明确筛选和标记，不冒充登录获取。查询游标绑定认证筛选以及原有创作者、平台、类型、日期、排序条件；总数、分页和按 entry_id 定位使用同一筛选。混合资源逐项标记，整条记录只可显示混合状态，不能将一个附件的状态传播给整组。相同 blob 的不同获取观察独立保留。

### 7.2 补全调度与统一升级确认

两站未登录时的清晰度与列表范围依实际端点、内容和权限变化。按 DEC-026 检查用户给定样本的登录前后差异，不硬编码“未登录只能720P”或“登录必有1080P原画”；质量标签不能替代实际分辨率/码率，单页返回也不能证明全部视频已取得。403/412/挑战/未知与合法空列表分开，不能因抓取受限标记作者没有内容。

1. 凭证导入/更新后先验证。成功时以新凭证代次建立有界、持久的补全扫描，对该身份获准服务的订阅中既有 anonymous/expired/unknown 普通资源重新解析；历史扫描与普通增量保持独立预算。退出登录、暂停、停模块、取消及重启沿用旧租约拒绝机制；不因重复验证无限重排，不越过删除墓碑或严格策略。
2. 重解析选择当前身份当时可得的最高质量组合，保留必要音轨、所有有序段、逐段及整组已知长度/摘要与实际规格。仍不可得、权限受限、无提升、内容已编辑、不可比较或资源失败分别可解释。登录不是会员/原画许可证明，也不绕过访问限制。
3. 新候选完整校验后进入持久待确认记录，旧选择/引用保持可读。统一“资源升级”页按站点、创作者、状态分页，展示新旧获取时间/认证状态、质量与字节差异、完整性、可比较性和回收影响；支持逐项或明确选择范围的批量接受、拒绝、保留两份。只有用户确认才切换；不把下载完成或打开页面当批准。
4. 确认携带候选 ID、预期旧选择、正文修订及删除/配置代次。Core 在同一事务重查候选完整性、当前选择、固定/共享引用和权限范围；过期点击返回明确冲突。重复确认幂等，拒绝不损旧版，保留两份建立保留理由；已确认后仍遵守既有等待回收与读取租约。预览到确认间有新下载、删除、取消或另一窗口确认都须有定向反例。
5. 多订阅重叠时，内容身份和文件去重不等于任务只属于第一个订阅。发现关系、请求身份/质量作用域与工作执行权明确建模；有活跃消费者时不能被另一个暂停订阅永久阻塞，也不得把已取消工作、另一个身份的凭证或旧代次重新激活。F-019 修复须覆盖 observe 和 media 链路，保留原单订阅暂停断言。

### 7.3 直播标签和兼容

直播不进入普通资源补全或覆盖队列，不在登录后尝试重录过去。同场凭证切换或失效时，在可恢复封片边界记录新上下文；各片保留实际宽高、码率、帧率、编码、音轨和来源声明的区别。测不到的字段显示未知，不能用最高一片规格覆盖整场。场次摘要可显示混合认证/规格与已有 gap；导出和离线详情保留这些事实。后续回放是独立内容，不能冒充补回直播原始区间。

新持久结构通过新迁移引入，不修改迁移1～4；schema4及schema3样本都须验证升级、备份、失败回滚、恢复与旧程序拒写。旧数据没有认证证据时为 unknown，不依据现在的登录配置补造历史。正文、资源、分页、媒体节点/播放位置和原证据仍须保留；所有类型共用 Core 服务，不在 UI 维护另一份真相。

### 7.4 真实测试输入

本地准备工具和安全边界以[数据与安全](dev-rules/data-and-security.md#local-site-credentials)为准，用户配置步骤/当前授权只在 [ACT-002](../USER-ACTIONS.md#act-002)。生产产品继续使用系统保护的 Vault；开发用 Cookie 文件不是产品凭证库。缺输入只停止所依赖真实测试，合成完整链、故障验证、文档、打包及代码修复继续。

## 8. 持久执行与确认接线

schema 5 由 `MIGRATION_005` 引入，迁移1～4保持原文。每步升级前留一致快照；schema3先升4再升5，失败回滚该步，先前快照继续可恢复。`entry_subscriptions`只补回旧任务能证明的发现关系，不根据同账号猜测所有订阅都发现过全部内容。旧变体各自产生unknown获取记录。

`jobs::consumers`维护共享逻辑任务的逐订阅需求、完成序号、状态和失败预算；同一内容仍只有一个entry，同一详情或资源组使用稳定工作键。认领时从合法且待执行的消费者中选择作用域，在payload保存订阅配置版本、凭证不透明引用及代次、质量要求。执行前、心跳及提交重查作用域。运行中的合法租约不会被后来的消费者抢占；owner暂停/换凭证或配置时撤销旧租约，其他活跃消费者继续。失败预算属于消费者；暂停、取消、停模块、退出均不记作失败尝试。显式取消保留在逻辑任务上，发现或恢复订阅不自动撤销。站点明确拒绝签名、权限或策略时，停止标记留在被拒consumer及同一订阅的独立扫描lane上；凭证复查、补全、质量重排、扫描时钟和重启都不能自动撤销，另一个订阅owner仍可继续，只有显式重试才恢复对应用户请求。

`acquisition_contexts`保存一次解析批次的认证观察，`resource_acquisitions`保存各次实际接收或本地副本复验。二者具有禁止更新/删除的数据库触发器。authenticated来自同代次、本批次生产适配器的登录探测；过期和网络未知分别保存。`cache_verified`明确是本地副本复验，跨认证身份首次获取仍重新接收字节；blob去重不删获取历史。CDN只接收允许的公开头；解析身份不由CDN的Cookie有无反推。适配器显式报告匿名解析时另建anonymous上下文。当前凭证是否仍可用由查询另算，不回写历史。

`auth_completion`按凭证代次、订阅及配置版本建唯一持久任务，固定发现关系的上界，每轮最多16条、至少2秒续行。普通扫描保持自己的游标和预算；既有未登录/失效/未知普通资源进入详情与媒体补全，直播及删除墓碑被排除。认证观察、目标/可得/实际规格仍独立。凭证更新和控制操作沿用租约屏障；再次验证同一代次不无限重建队列。

`upgrade_candidates/upgrade_members`把完整候选与旧选择分开；每个变体的approval_state决定能否参与自动质量选择。pending/rejected不被后台质量维护选中。必要资源按这次候选验证，不能借旧音轨或旧分段凑完整。实测没有提升与相同字节单列；不可比较的候选保留明确说明。获取失败保留旧选择和不可变的失败观察；候选分别显示访问受限、身份失效、网络或空间失败。补全发现正文编辑时保留原修订及资源，并明确说明新候选属于新正文版本。候选确认携带完整比较的摘要，绑定正文修订、旧选择/固定状态、资源代次、订阅/凭证/工作代次与质量配置。Core复验候选对象的实际哈希，并在一个事务内重查全部范围后切换；重复同一决定幂等，冲突拒绝。接受后的回收继续受等待期、固定、共享引用和读取租约保护；保留两份固定新旧副本。

新增共享接口：`archive.acquisitions`（50条获取历史/页）、`upgrade.list`（10候选/页）、`upgrade.resources`（20项资源比较/页）、`upgrade.decide`（1～50个明确候选及各自expected比较）。时间线与搜索的authentication筛选共用查询与游标；同一entry可同时存在于多条获取时间线。统一资源升级页显示新旧身份、获取时间、实际规格/字节、比较结果和保留影响，显式接受/拒绝/保留两份后调用Core。

直播在解析和封片边界记录context_id，实际宽高、fps、bitrate_bps、编码/音轨来自本地probe；未知不补造，认证失败可记录带上下文的gap。已封片在撤销租约后的恢复仍引用原上下文；不会改成新登录身份。直接传输但没有解析证明的旧/测试入口标unknown。获取JSONL与直播导出均保留历史状态和实际规格；恢复清除可用凭证、暂停订阅并取消未完成执行，历史不变，旧确认必须重新核对。

旧任务在已提交资源之间恢复时，可复核同一任务/代次的旧副本而不新增变体。缺原始认证证据的复核仍单列为unknown/cache_verified，不补造匿名或已登录下载历史；新的已认证消费者必须实际取得该身份的资源字节。正文内嵌资源与默认播放器都排除待确认或已拒绝的自动选择。

同一逻辑请求/代次补齐自己已提交的资源时不新建升级确认；新的消费者、凭证或显式登录补全仍遵守候选隔离。恢复后清理已经失效的候选状态，档案质量标签与确认接口共用当前比较校验，失效的旧确认不再显示为可接受升级。

元数据节流在每个命名空间内使用Tokio FIFO Mutex分别排队普通/紧急请求，两类队首仍共享原最小间隔、抖动与最多四次连续紧急请求的预算。取消等待释放位置，站点之间独立；持续直播或新扫描不能反复抢过已经排队的详情/媒体消费者。

## 9. 链接、可得质量与真实产品链

本节对应FR-ARC-009、FR-LIVE-008和AC-29/30。控制接口、持久结构和限制见下文；实现和验收事实以[状态](delivery/status.md)与[阶段报告](delivery/stage-report.md)的对应输入为准。

### 9.1 解析和选择

视频链接、主页/账号、直播展示房号和真实房号先识别类型，再根据站点响应核实身份，不能把房号直接当主播账号。解析只访问允许的目标与有界重定向，不启动整账号扫描。视频多P保持各自cid/必要资源组；直播保留别名→真实房间→主播→场次的证据。输入无效、未开播、访问受限、未知结构、缺必要资源分别返回可操作状态。

预览列出本次解析实际可得的表示及组合：源质量标识、分辨率、帧率、编码、HDR/音轨、已知长度及必要分段。来源未给出的字段显示未知；不能将最高标签当实测。用户选择后创建持久一次性采集请求，复用现有消费者、对象提交、认证观察、停止/取消和重开服务；不建立另一套下载器或对象库，不自动订阅该作者全部内容。

确认绑定不透明预览/候选身份、稳定来源、选择、凭证代次、认证证明和请求代次。短期URL过期时按稳定身份安全重解析；相同目标仍可得才继续。可得质量降低、必要音轨/分段改变或凭证换代时明确刷新选择，不能把原选择静默改成低清。重复点击幂等、晚到响应不能改写新预览；已有档案保持同一entry。普通用户的明确下载选择不等于允许覆盖已有版本，升级沿§7.2统一确认。

### 9.2 受保护端点与有界元数据

Bilibili WBI按公开算法使用32字符混淆密钥、发送一次wts，参与摘要的序列化字节与实际查询一致；签名过期只有限刷新。站点所需UA/Referer按端点区分，直播使用直播来源上下文。不能以弱化证书、Cookie隔离或无限重试修复412。

签名公钥的nav请求沿用调用范围的可用凭证。匿名nav的`code=-101/isLogin=false`只在两枚32字符十六进制公钥完整且无挑战时允许用于签名；它仍不能作为登录成功、媒体权限或清晰度证明。其他错误码、挑战、缺失或畸形公钥均失败，实际来源请求继续使用原身份范围，不因公钥可用切换身份。

Douyin登录证明继续来自self端点；受保护的详情/投稿等请求还需要对应SecSDK访问上下文，两者独立。Cookie派生的访问者ID/指纹/短期签名由Core在被授权的固定host/method/path内处理，绑定同一凭证代次，不交给适配器或UI。适配器仍只提交业务URL/公开头；Core新增的敏感查询不得从final_url、异常、快照、日志、导出或包泄漏。缺访问上下文、明确认证失效和站点拒绝分别分类；不得伪造msToken或把访客ID当登录。原401/403/412/挑战停止条件保持。

元数据HTTP体上限、base64/序列化开销、插件帧上限与页大小必须一致。正常20条投稿约1.45MB的来源事实超过内置适配器普通512KiB请求默认值；支持该页的显式`proxy.fetch_large`请求体预算为8MiB，插件逻辑消息最多12MiB。超过1MiB的逻辑消息使用`plugin_chunk_v1`：每片原始字节最多192KiB，绑定request_id、序号、总长和SHA-256，最多四个在途组，30秒过期；有序完整组装后才解释响应。普通`proxy.fetch`保留1MiB响应帧，兼容旧端提交4MiB预算但实际小于单帧的请求；其实际响应不能装入帧时发送小型明确错误，不升级协议或静默丢弃响应。宿主所有元数据请求上限8MiB，控制帧上限不变。生产两站适配器只在明确大型JSON路径申请扩展；超限、缺片、重复、跨请求或坏摘要明确失败，不截断数组/正文、不把失败页记为完成或推进游标。大型正文、必要资源、分页统计、同时请求、取消和重启继续适用原反例。

### 9.3 直播传输及实测证据

真实来源返回的已知媒体CDN可在有来源证据的窄策略内注册，API凭证域与媒体域保持分离。源URL为HTTP时，只能对已证实支持TLS的同一站点CDN保留host/path/query升级到HTTPS；失败明确停止，不回退明文、不放开任意重定向。每跳及嵌套HLS/key/MAP继续核对域、全部DNS结果和实际连接地址，媒体请求不携带Cookie/Authorization。用户不应为已支持站点手填测试域白名单。

直播开始、GUI关闭、停止封片、恢复和导出均由Core实际执行。每个片段记录接收墙钟窗口、源时间戳范围和实际宽高/码率/帧率/音轨；直播流绝对时间戳不是保存时长。低于目标、混合规格、缺口、探测失败如实标记，不补录过去。至少720P按短边≥720核实，失败仍保护已保存片段。

AC-29/30必须使用当前生产包、两个站点的指定真实对象和隔离Profile，记录可得选项、明确选择、任务/消费者/认证上下文、实际接收字节、所有必要对象哈希、封片与离线读取/导出及完整自动解码。原始目标和签名响应只留本机，公开只给脱敏摘要；A的外部诊断下载/录制文件不能冒充这些Core提交。自动解码不等于用户实际听到声音、原生播放器/IME/缩放验收。

### 9.4 Core接口、持久范围与恢复

`source.preview`接收HTTPS来源链接和可选的不透明credential_id，返回稳定作品或真实房间身份、作者、认证状态及验证时间、五分钟有效期和安全选项；媒体URL不进入预览快照。`source.confirm`接收preview_id及各资源明确选择的选项ID，同预览/同选择重复提交返回原任务，变更选择必须重新预览。`source.list`返回最近50项请求及真实子任务/场次状态；`source.cancel`撤销该请求代次，正在录制的正常停止使用既有`live.set_recording`封片。`/acquire`页通过这些接口完成链接归档，已有资源升级继续使用`upgrade.decide`。

schema6由`MIGRATION_006`追加，迁移1～5保持原文；逐步迁移仍留一致备份。`source_requests`保存稳定身份、认证代次、所选规格/必要资源指纹、任务和场次关联。内部`subscriptions.acquisition_kind='one_shot'`仅承载现有凭证与取消检查，不是作者订阅：列表/登录补全排除它，数据库禁止为其创建或改成scan/auth_completion/account_profile。同一直播的不同预览在排队阶段就检查已有请求，同选择共享原执行；不同选择/身份或已有普通录制返回冲突。登记时再次检查，防止确认与创建场次之间竞争。

`source_acquire`在执行时重解析稳定来源，核对正文/必要资源及选择指纹；随后进入原Core媒体或录制任务。短期地址轮换不改变选择，分辨率/编码/帧率下降、必要资源变化、身份换代及预览过期均拒绝旧选择。写入前及复用本地副本时都检查实际视频规格和必要音轨；直接直播封片检查实际短边至少720。来源声明时长在安全DTO中单独保留，不受展示元数据省略预算影响，也不以容器绝对时间戳推算直播时长。

直接来源的选项规格在预览与执行两端使用同一安全规范化，包括数字quality_id转字符串；正常脱敏不能改变用户选择的指纹。该规范化只作用于新source选项/缓存比较，原acquisition_spec和schema5物化摘要字段保持兼容。DASH视频与必要音轨分别保存并由Core生成播放派生，较高的其他可得选项不得替代用户明确选择。

完整共享候选保存原消费者的请求序号；其他消费者正常接管执行租约不撤销它。真实取消、原消费者需求/订阅/凭证变化、正文/选择/固定状态变化仍使旧确认失效。非共享schema5确认保持原比较字段形状。资源代次由选择及固定状态变更推进，待确认新字节到达不改变旧选择代次。

共享候选的质量比较同时冻结原消费者的帧率/分辨率偏好，展示和确认不读取后继消费者的执行配置。旧确认没有该可选字段时保持原token形状，只能从配置版本仍相同的原订阅恢复比较偏好；原配置已变化且没有历史依据时显示unknown，不猜测历史偏好。

已有链接录制在重解析时取得明确停播状态，应进入既有场次封口路径；预览停播来源仍不创建新任务。来源拒绝、未知结构、身份变化和网络错误不能当作停播。Douyin停播响应省略房间/主播时，只承认Core宿主保留的白名单offline状态，并沿用该请求已经绑定的房间；不得用错误正文或其他来源身份补造结束证据。

物化键包含job_id、任务代次及资源/表示/完整性摘要，receiving/ready/commit全部核对所有权；旧任务的已准备字节不交给新补全。schema5旧格式物化键仅在原job_id、资源和代次仍匹配时允许原任务继续，不能让另一任务沿旧键取得准备文件。相同任务恢复可继续自己的collecting候选并复用自己的pending变体；另一任务不复用未批准资源，同身份普通已批准副本复验仍记录cache_verified。`deletion_selections`保存删除前的选择/固定状态，恢复只使用automatic/accepted/kept且验证可读的对象；pending/rejected保留历史，不成为默认选择、播放派生或导出来源。

启动恢复对COMMITTED暂存路径按rowid键集分页，每批最多64条，在实际清理完成后用一个FULL事务确认该批相同状态/路径，避免每个历史片段一次同步。路径必须属于该操作且不经链接；在清理与确认之间中断可重入，不能先清空记录再跳过残留目录。该批处理不跳过未完成对象重算、录制封片或副本完整性检查，也不延后到后台假装恢复已经完成。

可选Profile `acquisition_limits`仅用于获准的有界运行：metadata_requests、media_bytes、interval_ms由实际跑次配置，每跳计数、间隔不少于2秒；预算与停止状态持久化，媒体按1MiB块保守预留防止重启重置额度。有明确修正依据后另建复验时，执行器读取已保留跑次的预算并扣除消耗，门禁核对历史预算摘要，不通过新Profile重置本次授权总额。实际媒体接收、范围读取及必要对象哈希均由Core产生。正式包示例不包含测试白名单或真实凭据。授权和具体预算只从[ACT-002](../USER-ACTIONS.md#act-002)取得。
