# 移动端选型（2026-11-26）

为 [DEC-085](../decisions.md#dec-085) 的移动端做的选型记录，只对查询当时的版本有效。设计见[移动端设计](../design/mobile.md)。

## 1. 来源

- MyGo `v0.10.0`（Go 模块代理记录的发布时间 2026-11-17T18:14:32Z，2026-11-26 查询）随模块发布的中文文档 `docs-zh/mobile/README.md`、`building.md`、`interface.md`、`plugins.md`，以及 `cmd/mygo` 的 `android.go`、`doctor_mobile.go` 与 `internal/mobile/android` 的 Gradle 配置。
- 本机 `mygo doctor`（v0.10.0）结果，2026-11-26。

## 2. MyGo 的手机支持（v0.10.0）

| 方面 | 现状 |
| --- | --- |
| 平台 | iOS / iPadOS（原生界面用 Metal 绘制）与 Android（OpenGL ES）；Go 代码、绑定的服务与事件不变 |
| 命令 | `mygo doctor`、`mygo devices`、`mygo dev -platform android|ios`（改 Go 代码约 2 秒重启并恢复路由与 `ui.Local` 状态）、`mygo build -platform android`（`.apk` 与 `.aab`）/ `ios`（签名 `.ipa`）、`mygo publish` |
| 构建条件 | Android：SDK（`compileSdk`/`targetSdk` 36，默认 `minSdk` 26）、NDK（用其 clang 为每个 ABI 链接 Go 共享库）、JDK 17 或以上，Gradle 构建，任何桌面系统都可以；iOS：只能在装 Xcode 的 Mac 上构建，真机与上架要 Apple 开发者团队 |
| 开发版 | 名称加“ Dev”、标识符加 `.dev`，与正式版并存 |
| 界面 | `mygo.NewTabs`（系统底部标签栏）、`Window.Push` 与 `ui.Router.SystemStack`（系统导航栈、Android 预测性返回、iOS 左滑返回）；`ui/mobile`：`Sheet`、`ActionSheet`、`Drawer`、`PageView`、`SwipeRow`、`TopBar`/`BottomBar`、`ListRow`/`Section`、`Switch`、`Zoomable` 等；`Element.PullToRefresh`；手指、长按、双指缩放；输入法与系统编辑菜单；TalkBack / VoiceOver |
| 生命周期 | 应用不自己退出；后台是 `Power.OnSuspend`，回前台是 `resume` 与 `App.OnActivate`；系统可能在后台结束应用，`App.OnSaveState` / `RestoredState` 恢复；内存不足 `App.OnMemoryWarning` |
| 设备能力 | `mygo.Network`（是否在线、是否计费）、`mygo.Share`、`mygo.Haptics`、`mygo.SetOrientations`、`Context.SafeArea`；`Secrets` 在 Android 上用密钥库加密保存 |
| 官方插件 | `videoplayer`（Android MediaPlayer / iOS AVPlayer，文件或 URL，含 HLS）、`camera`、`imagepicker`、`permissionflow`、`preferences`、`background`、`push`、`websocket` 等；自写原生代码用原生模块（Kotlin / Swift） |
| 手机上不起作用 | 菜单栏、托盘、程序坞、全局快捷键、更新器（由应用商店更新） |
| 测试 | `ui.Tester` 的 `FingerDown/Move/Up` 与 `SetInsets`、`ui/golden` 截图比对；自动化插件可在模拟器与真机上做端到端测试 |

本机 2026-11-26：`go`、`gh` 等可用；`android  no SDK`，也没有 JDK，所以现在不能构建 Android（[#116](https://github.com/chialecode/trace/issues/116)）。查询时仓库依赖 MyGo `v0.9.1`，同日升级到 `v0.10.0`（[#115](https://github.com/chialecode/trace/issues/115)）。

## 3. 方案比较

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| **MyGo 原生应用（选用）** | 采用 | 全项目已是 Go + MyGo 原生界面（DEC-032），手机端可共用 DTO、协议类型与部分展示代码；同一工具链出 Android 与以后的 iOS；与持续同步 MyGo 最新版的方向一致 |
| 电脑端提供网页，手机用浏览器打开 | 不采用 | 局域网自签名证书在浏览器里会出现安全警告，要用户手动信任；要另写一套网页前端（项目已去掉 Web 前端，DEC-032）；后台与返回手势等体验差 |
| Kotlin / Flutter 等原生框架 | 不采用 | 引入第二套语言与工具链，不能与电脑端共用代码，违背 DEC-032 的单一语言取舍 |

## 4. 待原型核对的组件

- **视频播放**：`plugins/videoplayer` 不认自签名证书，计划在手机端 Go 里做 `127.0.0.1` 回环转发（[设计 §6](../design/mobile.md#media)），由原型 [#117](https://github.com/chialecode/trace/issues/117) 确认。
- **二维码扫描**：`camera` 插件取画面后用纯 Go 二维码解码库，或经原生模块调用系统扫码能力；候选库的许可、活跃度与识别率在原型时按[开源优先](../dev-rules/sources-and-safety.md#open-source)查证。电脑端生成二维码沿用已有依赖 `yeqown/go-qrcode`。
- **局域网自动发现**（第二版）：mDNS 的 Go 实现与 Android 组播权限在第二版选型时查证。
