# 本地参考、未跟踪文件与公开内容

依据 DEC-014。本文是参考发现、隔离和本机文件生命周期正本；协作合同仍在[开发工作流](development-workflow.md)，文档状态和清理原则在[治理](../governance/documentation-policy.md)。

## 1. 找到本机参考

1. 优先使用进程环境变量 `TRACE_REFERENCE_DIR` 指向的目录。本项目不自动加载整个 `.env.local`；如用户使用该文件，只读取显式需要的同名配置，不输出其他值。
2. 未设置时，从仓库根逐级向上查找 `reference/<仓库根目录名>/`，第一个存在的目录为本次参考根。
3. 依次选择其中的 `README.md`、`INDEX.md`、`REFERENCE.md`，找到第一份就停止。
4. 找不到时记录“未找到本地参考索引”，继续不依赖它的工作，不建立虚假副本或随意搜索用户磁盘。

参考列表、本机路径、外部仓库 HEAD、源码摘录和原图只在这个仓库外目录维护。公开仓库只说明功能领域和 TRACE 自己的结论。正式采用的第三方依赖、官方协议链接和必须保留的法律声明仍如实入库；不得以“隐藏参考”为由删除归属或许可证。

## 2. 参考与选择

A 规划和 B 实施一个功能前，先看索引有没有对应的功能领域；有的话按索引写的“参考什么”读本地副本，再结合[开源规则](open-source-first.md)判断。参考不等于照搬：结论仍按 TRACE 的需求、契约和验证来定。

- **只读。** 索引和外部项目都只读：不修改、不移动、不自行 pull。开始参考前先看本地副本的提交日期，明显过旧时在 [USER-ACTIONS](../../USER-ACTIONS.md) 请开发者更新。
- **提建议。** 想新增或修改参考时，在索引同目录的 `PROPOSALS.md` 末尾追加一行（功能、项目、本地路径或建议路径、许可证与用法、理由），再在 USER-ACTIONS 加一行不含项目名的提示；用户同意后才移入索引。用户在对话里直接要求登记的参考，直接写入索引并在 `PROPOSALS.md` 记一行“已采纳”。
- **许可证。** 只参考设计与做法。需要复用代码时按其许可证作为第三方依赖或许可声明进入仓库；GPL/AGPL 等著佐权项目只参考交互、流程和协议要点，不复制代码。
- **不进公开内容。** 仓库文件、提交信息、PR、证据和报告都不写参考项目名、参考关系和本机路径；需要提到时只写功能领域，例如“按本地参考索引的直播录制条目”。

重叠功能先比较 GitHub 日期，但区分 `updated_at`（仓库元数据）、`pushed_at`（最后推送）和默认分支/目标模块的实际提交。记录查询日期、时区、SHA、是否归档和许可证；同等适用时优先近期有效维护的项目。最新一次更新不证明长期频率最高；正式采用还要看相关功能的 30/90 天修复、发行和问题处理证据。机器人、文档和 CI 更新不能替代功能修复。

仅有支持列表不证明 TRACE 的身份、历史、版本、质量、凭证和恢复契约。GPL 参考本轮仅限交互/流程研究；复制或链接源码必须另核实际义务并受 Q-004 约束。MIT/Apache 也须保留所需通知。GitHub 查询失败记 unknown/not-run，不能编造最新状态。

## 3. 文件放哪里

| 类别 | 位置 | Git 与处理 |
| --- | --- | --- |
| 源码、规则、类型、锁文件、合成夹具与生成脚本 | 职责目录 | 纳入 Git，按明确文件列表暂存 |
| 原图、参考代码索引、参考项目分析、本机路径 | 仓库外 reference 根 | 不入 Git；不是构建依赖；默认只读 |
| 临时草稿、诊断、PR 正文 | `.local/` 或 `tmp/` | 忽略；结束时说明用途，必要结论提炼入正本 |
| 编译、下载工具、安装包、运行日志 | `target/`、`dist/`、`build/` | 忽略；按产物类别保留，不当作源码 |
| 临时验证 JSON/截图 | `artifacts/<跑次>/`；含参考作品画面的截图放仓库外 | 忽略；可公开、经审阅的最终摘要才进入 docs/evidence |
| 真实 Profile、档案、凭证、数据库和个人配置 | 用户指定的受保护位置；本地例子可在忽略目录 | 不入 Git；不是缓存，不自动删除 |
| `.env.example` / `.env.local` / `.local/site-secrets` | 公共配置模板 / 本机配置与用户提供的秘密 | 模板只含键和非敏感示例；本机内容忽略，只按当前任务读取必要键，不能自动复制秘密到模板 |
| 需要评审但尚未提交的新源码/文档 | 最终职责目录 | 只是 untracked，不能因未跟踪而忽略或清理 |

`.gitignore` 是共享的类别规则，`.git/info/exclude` 用于本机特例；不得把个人绝对路径或参考项目名写进共享规则。已被跟踪的文件不会被新增忽略规则移出索引，须先核对归属、备份及授权，不能自动 `git rm`。

## 4. 开始、交付与清理

开工检查 `git status --short --branch`、`git ls-files --others --exclude-standard` 和 `git status --short --ignored`，先看名称和类别，不输出凭证文件内容。分清用户已有、新实现和生成物；脏工作区不自动成为阻塞。

交付前执行 `python scripts/check_publication.py`、`python scripts/check_docs.py` 和 `git diff --check`。公开检查同时扫描当前文件与 Git 索引，防止暂存后工作树改干净但索引仍含私密内容；只输出路径及规则，不输出秘密正文。它是启发式检查，不能替代人工检查图片、法律归属与授权。

清理必须先解析绝对路径，验证位于明确的生成目录，确认不是 junction/symlink 指向真实资料；使用单一 shell 的原生文件命令。禁止全仓 `git clean -fdx` 或按“未跟踪”批量删除。用户数据、Profile、环境文件、参考目录和仍被引用的失败证据保留；不确定归属只暂停清理，继续开发。报告记录类别、保留/提炼去向和未处理原因，不复制私密路径。

已有 `.env.local`、Cookie 文件和 Profile 的键值归用户所有。先列明需新增或调整的键及原因，在会话已有具体授权内修改；没有对应授权时只给建议，不覆盖或整理与任务无关的键值。明确要求建立本地方案时可创建尚不存在的无秘密模板，不覆盖已存在配置。真实测试缺输入的处理统一见[数据与安全](data-and-security.md#local-site-credentials)。

## 5. 本地界面图像

当前开发服务器通过 `apps/desktop/reference-assets.ts` 从参考根的 design 目录仅读取六个白名单 webp；只绑定回环地址，生产构建不加载此中间件。未知路径或越界符号链接不得返回文件。没有本地图像时用 CSS 占位，干净 clone 仍可编译与预览布局。

用户提供的原图由 `scripts/prepare_ui_reference.py --source <原图> --reference-dir <参考根>` 生成本地裁切；需 Pillow，非产品构建前置。脚本保留原图，检查尺寸、拒绝不同原图覆盖及写入仓库。代码复刻布局，不能把整张截图作为可交互界面。截图只证明所见 UI，不代表下载或后台可用。
