# 来源与安全：开源选型、站点规则、本地参考、凭证与公开内容

<a id="open-source"></a>
## 1. 通用技术开源优先

触发：引入或更换前端框架、组件、HTTP、存储、媒体、测试、构建等通用能力，以及升级依赖、打补丁或扩大自研范围。

A 推荐前按下表记录证据，写进 `docs/research/`：

| 维度 | 最低依据 |
| --- | --- |
| 来源与版本 | 官方仓库、文档、包链接，查询日期，所评估的稳定版本 |
| 维护 | 是否归档或停维，近期有意义的修复与发行；不只看 star 数或机器人提交 |
| 适用范围 | Windows 桌面、中文与输入法、离线、资源占用 |
| 许可 | 源码和二进制的实际许可、随包通知义务；AGPL/GPL 不作为依赖引入 |
| 集成成本 | 官方扩展点、体积、原生依赖、升级影响、替代路径 |
| 实证与未知 | 资料判断与运行证据分开记录 |

查不到就记 unknown，不补造“活跃”的结论。A 给出推荐、备选和集成边界，B 完成最小接入和真实流程验证；安装成功、编译通过和产品可用是不同事实。自研通用能力要说明候选不存在或不适用的实证，只实现必要缺口。补丁要有来源、适用版本、测试和移除条件。选型缺口、上游缺陷和维护风险登记在[交付状态的开发与上游事项](../delivery/status.md#issues)。

<a id="site-rules"></a>
## 2. 网站规则

网站解析规则单独研究，不因某个库或下载器“支持某个站点”就认为满足 TRACE 的需求。每个站点在 `docs/research/` 有一份协议资料：稳定 ID、端点与参数、签名、分页、登录与访客差异、错误码、请求节奏、来源与证据等级、已验证与未验证。

- 社区协议资料不是站点对 TRACE 的稳定承诺；端点写进常量不代表已接通，固定样本通过不代表真实可用。
- 限流、风控、权限不足、网络故障不能当作“内容不存在”或空列表，要显示真实原因。遇到风控或限流不自动重试，交给用户手动重试。
- 登录是否有效要有“不带 Cookie”的对照；HTTP 200 或拿到访客 ID 都不证明已登录；登录成功也不证明某个列表完整。
- 规则不对、目前又没有思路的情况，记到 USER-ACTIONS 的 S 项：现象、试过的做法、当前判断、用户能帮什么。
- B 先用合成夹具和固定向量验证协议，再在 USER-ACTIONS 授权的对象和额度内做有界的真实检查。

<a id="local-reference"></a>
## 3. 本机参考索引

怎样找到和使用本机参考索引见[开发流程 §1.3](workflow.md#local-reference)。要点：索引与本地副本只读；新增参考追加到索引同目录的 `PROPOSALS.md`，并在 USER-ACTIONS 留一行不含项目名的提示；仓库文件不写参考项目名和本机路径。

<a id="public-content"></a>
## 4. 公开内容

仓库文件、提交信息、PR、报告不写参考项目名、参考关系、本机绝对路径、源码摘录、真实账号、Cookie 和签名 URL；需要时只写功能领域。正式依赖的名称、官方协议链接和许可声明照实保留。文档检查工具只做启发式检查，不替代人工审阅。

<a id="credentials"></a>
## 5. 凭证与真实站点请求

- **产品凭证**由应用自己保存（设计见[技术设计](../design/architecture.md#credentials)）：用操作系统提供的加密按当前用户保存，只在后端使用；界面只拿到账号摘要（昵称、头像、站内 ID、状态）。凭证不进日志、错误消息、历史记录、包和 Git。测试用合成哨兵值检查泄漏边界，不用真实秘密做断言。
- **开发用测试 Cookie** 与产品凭证分开：`.env.local` 只写 `TRACE_TEST_<站点>_COOKIE_FILE` 这样的路径（模板见 [.env.example](../../.env.example)），正文放在 Git 忽略的 `.local/site-secrets/`，由用户提供。只在获得授权的真实检查里读取，不打印，不复制到其他位置，不读取浏览器的登录数据库。
- **真实请求的前提**：对象、额度和动作都已在 USER-ACTIONS 授权。缺哪项就停止对应检查，记为 `blocked/not-run`，继续合成测试和开发。遇到风控、拦截、验证码或权限不明，立即停止该跑次，记录条件，不换会话反复尝试。
- 真实目标、原始响应和账号字段只留在本地忽略目录；报告只写类别、状态、计数和必要的非敏感指标。
- 本机文件：`.env.local`、Cookie 文件和用户数据归用户所有，不覆盖、不整理与任务无关的键值；需要调整时先列在 USER-ACTIONS。临时草稿放 `.local/` 或 `tmp/`。

<a id="github-requests"></a>
## 6. 应用与工具对 GitHub 的请求

- **正式版 TRACE 检查更新**（FR-UPD-003）：只访问 `github.com/chialecode/trace` 的 Releases——清单 `releases/latest/download/update-windows-amd64.json` 与清单里列出的更新包或差分包（经 GitHub 重定向到它的下载域名），一律 HTTPS，遵循系统代理；只带 MyGo 默认的请求头（版本与平台由下载的文件名体现），不带账号、Cookie 或设备信息。启动 1 分钟后一次、之后每 24 小时一次，或用户手动检查；“自动检查更新”关掉就不请求。这些请求与哔哩哔哩无关，不计入站点请求额度（NFR-NET-002）。开发版与源码运行不请求。
- **打包与发布工具**：`tools/package` 不访问 GitHub（版本号只看本机标签）。`tools/release` 联网时用 `git ls-remote` 读 `origin` 的标签与 `main`、用 `gh release list` 读已发布的 Release、MyGo 做差分包时下载上一版的清单与更新包；`-offline` 时都不做。只有带 `-publish` 且用户已授权时才创建标签与 Release、上传文件。
- **测试**：单元测试与 ptest 演练只用本机回环地址上的假发布源，不访问 GitHub。
