# 网站适配与下载规则

首批目标为抖音、哔哩哔哩的视频，决定来源见 [DEC-005](../decisions/confirmed-decisions.md)。具体网站规则在对应适配器开发前单独研究，通用技术的开源优先不预先指定某个站点下载器。

## 独立能力表

每个站点至少记录：稳定账号/内容 ID、主页变化、用户视频列表与分页范围、置顶/乱序/重复、正文与媒体关系、编辑/删除信号、媒体候选规格、音视频合并、签名地址过期、登录和不同访问能力、请求预算、失败分类以及来源证据。直播尚未进入该批次时标明未支持，不伪造空实现。

一个公开视频可下载，不证明能够收录创作者的历史和更新；某下载器声称“支持抖音/哔哩哔哩”，不证明覆盖需要的接口、身份、质量、字幕、合集或登录能力。不得混淆抖音与海外 TikTok 的身份及规则。

## 实现选择

可评估官方开放能力、适用库、专门工具或站点专用实现，具体取舍留在站点方案。通用 HTTP、解析和媒体处理仍复用合适开源基础；平台规则通过规范化契约连接核心。必要的下载工具只是可替换执行部件，不拥有 TRACE 的来源身份、归档目录、成功判断或回收规则。

方案注明可支持/不支持/未知能力、运行版本、验证日期和回退路径。能证明的范围才进入 UI 覆盖声明；限流、网络故障、权限不足不能直接视作内容被删除。

## 验证与交付

1. A 基于目标需求完成站点研究、范围建议与失败用例；决定先做哪个平台时依据证据，不按候选工具的支持列表猜测。
2. B 用脱敏固定样本验证协议，再在授权账号和内容范围做受控真实验证；缺真实配置不阻塞模拟源、核心恢复与 UI。
3. 必测重复分页、增量/历史并行、旧内容编辑、链接过期/断点目标变化、凭证失效、部分资源失败、取消与重启。
4. 报告逐项说明来源、元数据、实际保存规格、覆盖与限制。模拟适配器通过不能替代真实网站验收。
5. 站点取舍与人工配置进 Q/ACT；采用的开源组件问题进 OSS；可延期优化进 LOOP，全部汇入[总表](../decisions/open-questions.md)。

首个平台形成可用闭环后，再接第二个平台验证抽象。不以完成两个站点全部复杂规则作为第一个可用版本的前置条件。
