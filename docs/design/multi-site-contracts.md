| 关系 | 补充[技术设计](../design.md)与[归档契约](../site-archive-contracts.md)，不改变其中的不变量；站点资料见[社交站点研究](../research/social-sites-current.md) |

本文回答多站订阅、预览下载、下载位置、资源管理器与网络代理“应该怎样表现”；[技术设计](../design.md)只引用本文，不复写。

## 1. 不变的部分

- 来源身份、内容版本、媒体版本、文件实体分开管理；同字节只存一份托管实体（INV 与[领域模型](../design.md#domain)不变）。
- 站点适配器不接触 Cookie（唯一的例外：站点签名必需、本身又不是登录凭据的字段，由 Core 按站点声明单独交给适配器，目前只有小红书的设备标识 `a1`，见 [§11](#credentials)），不决定文件路径，不写数据库；请求经 Core 代理，计入预算。元数据的只读查询可以是 POST（只发往该站接口域名、表单或 JSON、有大小上限），媒体请求只能是 GET。
- 限流、挑战、需要登录、网络失败都不是“内容被删除”或“没有更新”。
- 抖音、哔哩哔哩已实现的订阅、链接下载、直播录制、认证历史、质量升级、导出备份恢复行为全部保留；已有订阅升级后行为不变。
- 数据库 schema 前进到下一版本时提供逐步迁移、旧备份可恢复、旧程序拒绝写入新库。

## 2. 站点与内容

“通道”是订阅规则覆盖的一类内容。下表是要实现的最小集合；每条规则最终是“已实现”“部分”还是“未实现”，以真实验证结果为准（见第 3 节）。

| 站点 | 订阅通道（用户发布内容） | 单链接 | 登录 | 网络 |
| --- | --- | --- | --- | --- |
| 微博 | 用户微博：原创与转发、长文全文、图片（含实况图）、视频；头条文章只保存摘要与链接 | 微博详情 | 推荐登录；访客可读部分 | 直连 |
| 小红书 | 用户笔记：图文（含实况图）与视频笔记 | 笔记详情 | 推荐登录 | 直连 |
| Instagram | 用户帖子：单图、视频、多图/视频混合（轮播）、Reels | 帖子/Reel | 需要登录 | 通常需代理 |
| X（Twitter） | 用户推文：原创、转发、引用、长推文、图片、视频、GIF | 推文 | 需要登录 | 通常需代理 |
| YouTube | 频道视频、Shorts、社区帖子（文字/图片） | 视频、Shorts、帖子 | 不需要（会员/年龄限制内容不支持） | 通常需代理 |
| 抖音 | 已实现：投稿、图集、长图文、合集；补自动下载开关与统一元数据 | 已实现 | 已实现 | 直连 |
| TikTok | 用户视频与图片（photo mode）帖子 | 视频/图片帖子 | 不需要；登录可选 | 通常需代理 |
| 哔哩哔哩 | 已实现：动态、图文、专栏、视频；补自动下载开关、统一元数据和空间视频风控参数 | 已实现 | 已实现 | 直连 |

不支持：新站点的直播录制、评论与互动数据、Instagram 快拍（Stories）与精选、X 的回复与点赞列表、私密/会员/付费内容、任何站点写操作。

<a id="site-data"></a>
### 2.1 随适配器发布的站点数据

网页端接口的标识会随站点发布变化，所以它们是适配器旁的数据文件（`adapters/<站点>/data/web_client.json`，编译进适配器，可单独更新），不是代码常量：

- Instagram：应用 ID 与查询标识（`doc_ids`）。
- X：网页端公开令牌，以及 `UserByScreenName`、`UserTweets`、`TweetResultByRestId` 三个操作的查询标识、特性开关（按网页端声明的取值发送，不是一律打开）和字段开关（一律关闭）。数据取自公开整理的网页端接口表，取得日期记在文件里；表本身只作事实来源，不复制其文本。
- 读取顺序：先用随包数据，不发请求；站点拒绝（404、400 一类）时才读首页和页面脚本，得到当前标识，同一次读取顺带取得事务 ID 的材料（首页的验证密钥与动画、按需脚本里的字节位置）。同一进程里 120 秒内不重复读取，读取失败记 15 分钟，换来的是变了的站点每个间隔只多出几次请求，而不是每次调用都多出几次。
- 事务 ID：`x-client-transaction-id` 由首页材料、请求方法、路径和当前时间按公开算法（MIT 许可）计算，实现是本项目自写的，由参考实现在合成页面和脚本上产出的固定向量校验。站点拒绝未签名的调用时，用读取到的标识加签名重试；同一标识未签名被拒、签名后被接受，则记下“该站要签名”，之后的读取总是带上材料，旧的材料（超过 6 小时）先重读再用。
- 仍被拒绝是接口改了：失败类别为“接口改变”，不当作没有更新，也不移动游标。

<a id="rule-catalog"></a>
## 3. 订阅规则目录

### 3.1 规则

每条规则由站点适配器在自己的清单里声明，Core 汇总并按适配器版本持久化，支持页面和链接匹配都读这一份。

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定编号 `<站点>.<对象>.<通道>`，例如 `weibo.user.posts`、`youtube.channel.shorts`、`x.post.link`；一经发布不改名，废弃时标 `retired` |
| `site`、`title`、`description` | 站点标识与中文名称、一句话说明 |
| `entry` | 用途：`subscription`（订阅）、`preview`（作者主页预览勾选）、`link`（单链接） |
| `content_kinds` | 可能包含的内容：`text`、`image`、`live_photo`、`video`、`audio`、`article`、`live` |
| `url_patterns` | 能匹配的链接形式（主机 + 路径模式），只用于识别；最终身份由适配器解析确认 |
| `params` | 用户可选参数（例如是否包含转发），带默认值 |
| `login` | `none` / `optional` / `required`，以及登录后多出的能力 |
| `network` | `direct` / `proxy_recommended` |
| `limits` | 已知限制，例如“只能看到最近约 30 条”“历史回填需要登录” |
| `status` | `implemented` / `partial` / `unimplemented` / `retired` |
| `verified_at`、`verified_scope` | 最近一次真实验证的日期与范围（例如“登录态 2 页列表 + 1 条视频下载”）；没有真实验证时为空 |

### 3.2 状态规则

- 只有完成真实验证的规则才能是 `implemented`；`partial` 必须在 `limits` 写清缺什么。
- 规则状态写在适配器源码里，随适配器版本发布；阶段门禁检查“`implemented` 必须有 `verified_at`，且报告里有同一规则编号的真实证据”。
- 没有规则的内容不能被订阅，也不能出现在支持页面上。

### 3.3 支持的网站页面

独立页面，按站点分组列出规则：内容类型、用途（订阅/预览/单链接）、登录与网络条件、状态、最近验证日期、已知限制。页面只读 Core 已持久化的目录，完全离线，不发网络请求；插件停用时仍显示最后一次声明并标“已停用”。

### 3.4 链接识别

粘贴的链接先在本机按 `url_patterns` 匹配候选规则；短链展开由对应适配器有界执行（最多 5 跳，只在该站声明的域名内）。识别结果显示站点、对象类型和将使用的规则，用户确认后才订阅、预览或下载。

- 路径模式的片段可以是字面量、`*`（任意一段）、`{name}`（一段，并捕获）、`@{name}`（以字面量开头的一段，如 `@用户名`）或结尾的 `**`（其后任意内容）；主机按后缀匹配，字面量片段越多越具体，同时命中多条规则时只取最具体的。
- 站点的域名分三类，由[站点清单](../../crates/domain/src/sites.rs)统一声明：接口域名（可发请求；只有属于该站 Cookie 域名的才带 Cookie，见 [§9](#proxy)）、媒体域名（可发请求、永不带 Cookie）、仅链接域名（只用于识别人们粘贴的主页、移动端和分享页，不发请求也不带 Cookie）。规则的链接模式必须落在这三类域名里，否则不能入目录。
- 识别只给出候选；身份由适配器解析确认，识别不到或需要登录时说明原因，不猜测。

<a id="metadata"></a>
## 4. 统一元数据

### 4.1 统一字段

适配器把站点字段映射到下面的统一字段；Core 把它们存成可索引的列或子表，供排序、筛选和搜索。取不到的字段为空，不用其他值冒充。

| 分组 | 字段 |
| --- | --- |
| 来源 | 站点、来源账号、原生内容 ID、规范链接、原生类型、是否转发/引用及被引用内容 |
| 时间 | 发布时间（及精度）、来源声明的编辑时间、首次发现时间、保存时间 |
| 文字 | 标题、正文全文、话题/标签、提及的账号、语言、来源客户端（如有） |
| 地点 | 地点名称、站点标注的 IP 属地 |
| 媒体 | 内容类型集合、图片数、视频数、最长视频时长、最大宽高、封面 |
| 归属 | 合集/播放列表/专辑、站点分类 |
| 状态 | 置顶、年龄限制/敏感标记、商业合作标记、可见范围 |
| 统计观察 | 播放、点赞、评论、转发/分享、收藏、投币、弹幕等，带观察时间；统计变化不产生新内容版本 |

### 4.2 站点扩展

其余字段进入版本化的站点扩展（沿用现有的安全元数据清理）：Cookie、令牌、签名地址、设备标识、内部风控字段一律剔除。扩展字段可以在详情里查看，不参与跨站排序。

<a id="subscriptions"></a>
## 5. 订阅：自动下载视频与手动同步

站点的 PermissionDenied 拒绝按具体 consumer/订阅保持，停止同订阅自动扫描/补全/重排，不饿死其它合法 owner。凭证变化、范围/质量变化、启停、重开和缺失 lane 的补建都不授予新许可；`subscription.check_now` 在拒绝期间返回 VersionConflict，用户须显式 `job.retry`。取消任务或自动取消 history 不解除拒绝：非共享任务的 permission_denied 错误标记保留到显式 retry 清除，consumer 标记保持在相应请求行；不能仅靠当前 job 是否 waiting_user 判定许可。

### 5.1 自动下载视频

- 开关属于订阅本身：每个创作者的每个站点账号单独配置。
- **开启**：更新中发现的视频按订阅质量偏好下载当前身份可得的最高清晰度（沿用现有质量选择与升级规则）。
- **关闭**：视频只保存封面/缩略图、标题、简介、时长、可得清晰度列表等元数据；媒体条目状态为“未下载（按订阅设置）”，与“缺失”“失败”分开显示，不计入“本次内容完整”的必需资源。
- 正文和图片不受开关影响，照常保存；实况图的动态部分随图片保存。
- 开关只影响之后的发现和显式同步，不删除、不补下已有内容。
- 新订阅默认值见 [USER-ACTIONS Q-010](../../USER-ACTIONS.md#q-010)；已有订阅升级后为开启，保持原行为。

### 5.2 手动同步

- 在时间线、创作者页或资源管理器里勾选“未下载”的视频（可以按筛选结果全选），同步到资源库。
- 每个媒体条目按“条目 + 质量策略”形成唯一任务；重复勾选不重复下载；逐条显示进度、失败原因与重试。
- 手动补查（单条、指定时间段、失败项目）复用同一去重规则，不前移订阅游标。

命令（均为幂等写命令，一次最多 200 条）：

| 命令 | 作用 |
| --- | --- |
| `archive.entry.sync` | 把所选条目里“按订阅设置未下载”的视频组各排一个媒体任务，并重试失败的媒体任务；条目逐个返回 `queued`/`already_queued`/`nothing`/`failed`；需要仍启用的订阅提供凭证与质量选择 |
| `archive.recheck` | 按条目列表、发布时间段或失败项目重新观察；只排观察任务，不读也不写任何订阅的扫描位置；失败项目改为重试失败的观察与媒体任务 |
| `archive.entry.recheck` | 旧的单条补查，行为不变，内部走同一条路径 |

<a id="undated"></a>
### 5.3 没有发布日期的列表

有些站点的列表不给确切发布日期（YouTube 只给“几天前”，小红书首屏不给时间）。这类条目不能在列表阶段排除，也不能因此把整个历史当作“范围内”：

- **近似日期**：列表给“几天前”之类的相对时间时，适配器给出推算值，精度记为 `approximate`，并用 `published_margin_seconds` 说明真实时间可能偏离多远（一个单位：N 天前为一天，N 周前为一周）。Core 只在整段误差范围都在订阅范围之外时于列表阶段排除条目；跨在范围边缘的留下等详情。适配器“只读最近几天”的提前截止同样把误差加上再比较。近似值带 `approximate` 精度入库，界面标为“约略”，不会冒充来源给出的时间，也不会覆盖已有的来源时间。
- **没有任何日期**：对只给起点的范围（从现在起、最近 N 天、只有起点的日期范围），一次扫描最多读 5 页（按这轮扫描已记下的游标页数累计，跨调度回合也算）；到上限即停，覆盖说明里记 `undated_page_cap`，如实写明“后面的页没有读”。范围为“全部”或给了终点的日期范围不设此上限。
- **新发现的计数**：列表无法定位的新条目不计入 `new_entries`，单独记入 `unplaced_entries`；它们是否算该订阅的发现，由详情决定。
- **详情给出确切日期后**：Core 把日期与精度写入条目（来源的精度如 `source`、`day` 原样入库）并判断条目是否在订阅范围内。范围外的条目不自动下载（媒体项标为“未下载”，用户仍可手动同步）、不再是该订阅的发现（发现关系移除；已保存的记录可以留着，不显示为该订阅的更新），之后的扫描遇到同一条目（列表仍无日期）直接跳过，不重复观察。范围内的按订阅设置下载。精度为“天”的日期按一天的误差判断，天跨范围边缘的条目不被判到范围外。
- **详情也给不出日期**（或日期只能确定在范围边缘）：条目保持“未知发布时间”，正文和图片照常保存，视频不自动下载，用户可以手动同步。
- 链接下载、预览勾选下载、认证完成后的补取等显式请求从不受订阅范围限制；范围为“全部”的订阅不需要日期。

“未下载”只在发现时判定一次：已被留下的视频组在开关之后打开时仍保持未下载，已保存的内容不受影响，显式请求（链接下载、预览勾选下载）从不被开关拦下；认证完成后的重新观察不会把已经排队的视频改成未下载。

<a id="preview"></a>
## 6. 先预览、再勾选下载

- 粘贴作者主页 → 识别规则 → 分页列出内容（类型、发布时间、缩略图、标题/正文摘要、媒体数、是否已在资源库）。
- 预览只取元数据，不下载媒体，不创建订阅；请求计入站点预算，页数有上限，可继续翻页。
- 勾选跨页保留；确认时选择下载位置（第 7 节）和视频清晰度策略（默认最高），为每个条目创建一次性下载任务。
- 已在资源库的条目只在目标是下载目录时复制一份可读文件，不重复取同一字节。

命令：

| 命令 | 作用 |
| --- | --- |
| `source.profile.preview` | 带 `url`（可加 `rule_id`、`credential_id`）打开新预览，或带 `preview_id` 取下一页；返回 `ProfilePage`：本页新出现的条目（类型、发布时间与精度、标题、摘要、图/视频数、时长、`in_library` 与保存进度）、已载入页数与总条数、`has_more`、`limited`、同一链接的其他预览规则、认证状态 |
| `source.profile.download` | 对预览里出现过的条目发起一次下载请求：`native_keys`（最多 200 个，跨页、去重）加 `target`（`library` 或 `folder`+`dir`）；返回 `delivery_id`、`accepted`、`already_in_library`、`skipped`（预览里没有、已删除/已屏蔽的条目及原因） |
| `source.deliveries` | 列出下载请求及逐条目状态（`queued`/`ready`/`exported`/`partial`/`failed`/`cancelled`）、写出的文件数与原因 |
| `source.delivery.cancel` | 取消下载请求，停止其未完成的任务并停用它的一次性订阅 |

- 预览只调用适配器的账号识别与列表枚举，不建任何订阅、条目、媒体或任务，也不记录扫描位置；预览保存 30 分钟，过期的预览不再信任，操作返回版本冲突，由调用方重新打开。
- 每个预览最多 10 页、400 个条目；到达上限时 `has_more` 为 false 且 `limited` 为 true，并如实说明“主页还有更多”，而不是当作列完。翻页以页数做乐观校验，同一页不会被两次载入；后一页重复出现的置顶条目只显示一次。
- 预览取回的条目键、标题与摘要在存入前截断；选择只能指向预览里出现过的条目，其余一律拒绝。
- 下载请求为它自己建立一个一次性订阅范围（`once-<请求>`，不是用户订阅，不会按计划再扫描，也不受自动下载开关约束）：未在资源库的条目各排一个观察任务，随后沿用现有媒体流水线（身份、版本、质量与凭证规则不变）；已完整保存的条目不再取回字节。所有任务结束（成功、失败、等待登录均算结束，等待重试不算）后才写出可读副本，字节来自资源库，结果以实际保存的内容为准；之后因登录完成等原因补完的任务会让请求再写出一次。
- 取消请求不删除已经保存的内容；已写出的副本照常记录。
- 目标目录在排任何任务之前检查（完整路径、可写、不与资源库或数据目录重叠）。多段视频以编号的分段文件写出，不拼接。
- 单链接下载（`source.preview` → `source.confirm`）同样可带 `destination`（`library` 或 `folder`+`dir`）：带目录时同样排成一次下载请求，沿用 `source.deliveries` 查看进度和写出结果；不带则只进资源库，行为与以前相同。文字类内容（没有媒体的条目）也可作为单链接下载对象。
- 缩略图：适配器可在条目里给出封面链接提示，Core 尚不代取封面，界面目前显示无缩略图的列表。

<a id="destinations"></a>
## 7. 下载位置与资源库位置

### 7.1 两类位置

| 位置 | 内容 | TRACE 的管理方式 |
| --- | --- | --- |
| 资源库 | 订阅数据和同步进来的内容；现有对象库（按哈希存放） | 托管：去重、校验、质量替换与回收按现有规则 |
| 下载目录 | 单链接与批量下载选择放到这里的文件；可读名称 | 只记录：TRACE 记录来源与元数据，但不移动、不改名、不回收；文件被外部改动或删除时标“已变化/已不在” |

设置里配置资源库位置和默认下载位置（默认是系统“下载”文件夹下的 `TRACE`）；每次下载可另选目录，最近用过的目录可再选。下载目录必须是完整路径，不含 `..`，且不能与资源库或数据目录重叠；设置时就检查能否写入。

**下载总是先进入资源库，再写出可读副本**：内容经现有流水线取回、校验并按哈希存入资源库（来源身份、版本和质量规则不变），再把可读副本写到下载目录；同一字节不会因为多个下载目录或重复下载而在资源库里存两份。下载目录里 TRACE 写出的每个文件都有一条外部副本记录（媒体、正文、旁注三种），所以这些内容也出现在时间线和资源管理器中，并标明“在下载目录”。

### 7.2 写入与命名

- 先写到目标卷上的临时目录，校验长度与摘要后再改名到最终路径；中断时不留下看似完整的文件。
- 默认命名：`<站点>/<作者>/<发布日期> <标题> [<内容ID>].<扩展名>`；一条内容有多个媒体时建一个同名文件夹，里面按顺序编号（`01.jpg`、`02.mp4`），正文写成 `正文.txt`。
- 默认在旁边写一份同名 `.json`，含清理后的统一字段与来源链接，便于在 TRACE 以外分类查找；可在设置里关闭。
- 文件名清理：去掉 Windows 非法字符与保留名、末尾的点和空格，单段不超过 120 个字符，超长路径在写入前失败并给出原因；同名冲突靠内容 ID 区分。
- 目录不可写、空间不足、路径过长都在开始下载前或写入时明确失败，不改写已有文件。

实现细节（均有测试）：

- 临时目录是下载目录里的 `.trace-tmp`；每次写入先检查目标卷剩余空间（文件总大小加 64 MiB 余量），写完校验长度与 SHA-256 后用“不覆盖”的改名放到最终名字；目标已存在时报错，不替换。每次开始前清掉上次中断留下的临时文件；`.trace-tmp` 为空时随即删除。
- 只有多个媒体时才建文件夹；只有一个媒体时正文只写进旁注 `.json`；没有媒体的内容把正文写成 `<名称>.txt`；还没下载到的媒体（例如按订阅设置未下载）仍占着自己的编号，后来补下载时名字不变。
- 整条路径不超过 259 个 UTF-16 单位（Windows 传统上限，资源管理器能直接打开）；标题按需截短，ID 总是保留，ID 超过 64 个字符时用前缀加摘要缩短；连空标题也放不下才拒绝，并说明所需长度。
- 目标名字已被别的文件占用（用户自己的文件或别的条目）时，整套名字加 `~<8 位摘要>` 后缀重试；仍冲突则拒绝，已有文件始终不动。
- 同一条目再次写出到同一目录时沿用已记录的文件名（标题改了也不另起一套），已在且长度一致的文件不重写，被删的文件原位补回，被外部改动的文件保持原样并报告“已变化”；旁注内容随目录数据更新且文件未被改动时才刷新。
- 外部副本检查读取文件长度和摘要：与记录一致为“已存在”，内容不同为“已变化”，文件没了为“已不在”（之后恢复会回到“已存在”）；写到一半中断留下的“写入中”记录若没有最终文件，下次检查时清除。TRACE 从不移动、改名或删除用户的文件；“移除 TRACE 记录”只删记录。

### 7.3 同步到资源库

下载目录中的条目可以“同步到资源库”：用资源库记录的摘要校验副本，资源库已有同字节且完好则不复制（同字节只存一份）；资源库缺少该对象或对象已损坏时，从校验通过的副本经暂存文件补回，损坏的旧对象移入隔离区而不是被覆盖。副本已被改动或已不在时不同步并说明原因。原文件始终保留在下载目录。

### 7.4 资源库位置变更

更改资源库位置是一次可恢复的迁移：逐个复制对象到新位置并校验摘要 → 全部通过后在一次数据库提交中切换 → 旧位置保留到用户确认释放。迁移中断后可续做；新位置写入失败时继续使用旧位置。数据库所在的数据目录不随资源库移动。

## 8. 资源管理器页面与统一时间线

### 8.1 资源管理器

- 左侧文件夹树，两个根：
  - **资源库**（虚拟层级）：站点 → 账号（显示名 @站点）→ 年 → 月 → 条目 → 文件；
  - **下载位置**：每个下载目录的真实目录结构，TRACE 记录过的文件显示元数据列，其他文件只读列出。
- 右侧文件列表：名称、类型、大小、时长、尺寸、发布时间、站点、作者、保存状态；列可排序，可筛选，分页或虚拟滚动，不一次加载全部。
- 操作：预览、用默认程序打开、在系统资源管理器中显示、复制路径、同步到资源库、移除 TRACE 记录。不提供改名、移动和删除用户文件；删除资源库内容沿用现有的删除范围与回收规则。
- 文件名与路径按不可信输入处理，任何操作都不能越出资源库或下载目录。

### 8.2 统一时间线

- 一个创作者关联的全部站点账号内容合并为一条时间线；关联入口接受八站任一主页链接（FR-ID-006）。
- 一张卡片可以同时显示正文、图片网格、视频封面与下载状态，保持来源顺序。
- 默认按发布时间倒序，未知发布时间单独分组；可按已保存的统计观察和时长排序；可按站点、账号、内容类型、话题/标签、下载状态、日期范围筛选。

### 8.3 命令与页面

| 命令 | 行为 |
| --- | --- |
| `explorer.tree` | 取文件夹的子文件夹（不带节点时返回“资源库”“下载文件夹”两个根）；每层最多 2000 个，超出标 `truncated`。节点地址由 Core 生成，界面原样回传；Core 每次重新严格解析，伪造、截断或被改写的地址一律拒绝，不会落到路径。 |
| `explorer.list` | 文件夹或条目的文件列表：`sort`（名称、类型、大小、时长、尺寸、发布时间、站点、作者）、`descending`、`query`（名称包含，不区分大小写）、`kind`、`state`、`offset`/`limit`（1–200，默认 100）。资源库侧在数据库里分页排序，下载位置侧读取真实目录（最多 20,000 项，超出标 `truncated`，排序与翻页只覆盖已读部分）后与 `external_copies` 记录合并：大小不符为“已修改”，记录在而文件不在为“缺失”，没有记录为“TRACE 没有记录”。 |
| `explorer.open`、`explorer.reveal` | 只接受 Core 已登记的下载位置和其下的相对路径；用默认程序打开仅限内容类扩展名（视频、图片、音频、文本、文档），拒绝可执行文件和脚本；符号链接、联接点、保留设备名、`..` 与盘符一律拒绝；“在文件夹中显示”调用系统资源管理器选中该文件。资源库内的文件沿用 `media.open_external`。 |
| `archive.tags` | 话题标签及其条目数，最常用的在前；可按创作者、账号、站点和前缀限定（最多 100 个）。 |
| `archive.timeline` | 新增 `sort`（`published` 默认，`plays`、`likes`、`comments`、`favorites`、`duration`）、`tag`、`content_kind`；站点沿用 `namespace`。按计数排序时站点没给的值始终排在最后（不当作 0），`oldest` 表示升序；游标属于其排序与筛选，换了排序或筛选再用旧游标会被拒绝。每条带 `meta`（[§4.1](#metadata)）。 |
| `archive.entry.get` | 增加 `meta`；还没观察到统一字段时为空。同时返回 `discovered_by_subscriptions`、`observation_count` 与 `latest_observation_seq`，用于区分本订阅的发现关系、真实详情观察和其他lane或预览产生的条目。 |
| `archive.entry.sync` | 对未下载的视频补下载（[§5.2](#subscriptions)）。 |

十万条资源库的首屏与翻页目标：满载（四路录制 + 两路下载 + 桌面界面）下发布构建的热 P95 ≤ 500 毫秒、冷 P95 ≤ 1500 毫秒；按名称、最近、类型、站点、发布时间等排序与筛选只读 `entries`；离末尾比离开头近的页从另一端按相反顺序读取再翻转（OFFSET 要走过跳过的每一行；排序以条目 ID 作最后一级，两端读到的是同样的行），所以最后一页不比首屏贵；按大小排序要汇总已存字节（约 0.6 秒）不在目标内（LOOP-003）。本机合成负载的一小时实测见 `docs/evidence/gate/report.json`（热 281 毫秒、冷 274 毫秒）；同一发布构建在同一台机器上的四次一小时跑次，热 P95 随机器后台负载在 281～578 毫秒之间，余量有限（阶段报告 §2.5）。结果只说明本机和合成数据。

页面与入口：

- **统一时间线**（主页）：排序、站点（侧栏）、账号、内容形式、标签、保存状态（含“未下载（按订阅设置）”）、日期范围；卡片显示内容构成（文字 + 图片数 + 视频时长）、站点报告过的计数（没报告的不显示）、IP 属地；未知发布时间单独成组并排在末尾；未下载的条目有“补下载”。
- **资源管理器**（`/explorer`）：左侧文件夹树（键盘：方向键、Home/End、回车），右侧列表（点列头排序、名称筛选、类型/状态筛选、每页 100 条翻页、勾选后批量补下载或导出）；名称按纯文字显示，控制字符与文字方向控制符替换为可见的占位符并标“含隐藏字符”。
- **主页勾选**（`/profile`）：粘贴任一站作者主页 → 逐页读取 → 跨页勾选 → 选择仅资源库或同时写入下载文件夹 → 在“最近的下载”看逐条进度，可取消。
- **支持的网站**（`/sites`）、**设置**（`/settings`：资源库位置与迁移、下载位置与命名、网络与代理、站点登录与风险提示）、创作者页关联任一站账号（粘贴链接自动识别站点）、订阅的“自动下载新发现的视频”开关（默认关闭）。

十万条规模：合成 100,000 条目的库在调试构建下首屏约 0.6 秒、文件夹树约 0.07 秒、改变排序约 0.7 秒、名称筛选约 0.3 秒；发布构建的正式测量见交付报告。

## 9. 网络代理

- 设置：全局与按站点选择直连、系统代理或手动代理（`http://` 或 `socks5://`，主机与端口；代理认证信息存入系统凭证存储）。默认值见 [USER-ACTIONS Q-008](../../USER-ACTIONS.md#q-008)。
- 直连时保持现有的 DNS 固定与地址类别检查，不新增拒绝范围：代理软件 TUN 模式的虚拟 DNS 会让所有站点（含国内站点）解析到 `198.18.0.0/15`，现有检查允许它，新增拒绝会让直连全部失效（[2026-10-16 观察](../research/social-sites-current.md#login-probe-2026-10-16)）。经代理时由代理解析域名，代理地址本身可以是本机回环地址，Core 对**目标**改为：目标主机必须在该站适配器声明的域名内；字面 IP 目标和私网/回环目标拒绝；每一跳重定向重新检查。
- Cookie 只附加到所属站点的 Cookie 域名，也就是用户复制 Cookie 的那个站点域名：微博 `weibo.com`、小红书 `xiaohongshu.com`、Instagram `instagram.com`、X `x.com`、TikTok `tiktok.com`，YouTube 不带 Cookie，抖音、哔哩哔哩保持现状。同一站点的其他接口域名（如 `weibo.cn`、`t.cn`、`twitter.com`、`t.co`、`xhslink.com`）只发无 Cookie 的请求。换站点、换代理都不改变这一点（实现见阶段计划 R2-1）。
- “跟随系统代理”读取系统设置；开关打开但地址为空、或没有设置时按直连处理。直连或代理失败时提示用户检查该站点的代理设置。
- 代理不可用、认证失败显示为网络问题，不改变订阅或内容状态。

## 10. YouTube 媒体解析

- YouTube 适配器自己负责频道识别、视频/Shorts/社区帖子的列表与元数据（网页端公开接口，不需要 API Key）。
- 视频的可得格式与下载地址由 Core 调用锁定版本的外部解析工具获得（当前候选：yt-dlp，配合它要求的 JavaScript 运行时 Deno；选型依据见[开源候选](../research/open-source-candidates.md#social-sites-2026-10-16)）。该工具与 FFmpeg 一样是可替换的执行部件，不拥有来源身份、文件路径、成功判断或回收规则。
- 调用约束：固定参数、忽略用户配置与插件目录、禁止工具自我更新（不用 `-U`）、有超时与输出大小上限、不传 Cookie（只支持公开视频）、代理按第 9 节设置传入。
- 手动更新 yt-dlp（[DEC-039](../decisions/confirmed-decisions.md#dec-039)）：设置页显示正在用的版本与来源（随包 / 已更新），用户点“检查更新”时 Core 才联网，按第 9 节的代理读取 yt-dlp 官方发布页的最新稳定版；有新版时显示版本号，用户确认后下载 `yt-dlp.exe`、`SHA2-256SUMS` 与 `SHA2-256SUMS.sig`。先用随 TRACE 锁定的 yt-dlp 发布公钥核对 `SHA2-256SUMS` 的签名，再核对文件的 SHA-256；任何一步不符就丢弃下载、保持原版本。通过后放进数据目录下按版本分开的工具目录（不改便携包里的随包版本），运行 `--version` 确认能启动、版本号一致，再在没有工具任务运行时切换；保留上一版，可一键退回，也可退回随包版本。不自动检查、不自动更新；更新过程与失败原因在设置页显示，不写进档案。Deno 仍随包锁定；新版 yt-dlp 要求更新的运行时而启动检查失败时，提示原因并保持原版本
- 优先由 Core 按解析结果自行下载；工具只能给出需要自身下载的格式时，下载到临时目录，再由 Core 校验并提交。
- 视频服务器（googlevideo.com 主机）对单次长连接限速到几乎不动：Core 对这类主机按已知大小以 10 MiB 的 `Range` 分段请求，每段必须返回 206 且 `Content-Range` 与请求完全一致，拼接后再校验长度与摘要；其他主机仍用单次流式请求。
- 工具缺失、版本不符或解析失败时，视频按“未下载”保存元数据，规则状态降为 `partial` 并说明原因。
- TikTok 的视频地址在 `*.tiktok.com` 下，站点只认生成该地址的页面会话：这类媒体请求带上同一作用域里页面请求所用的 Cookie（凭证 Cookie，加 Core 在内存中记下的该站响应设置的会话 Cookie；不落盘、不给适配器、不发往 Cookie 域名之外），CDN 域名仍不带 Cookie。仍被拒绝（403、404、410、401）时，改用同一个外部解析工具在临时目录下载，约束与上面相同：固定参数（忽略用户配置、不用 Cookie、不自我更新）、空环境、有时间与大小上限（承诺大小的两倍，限制在 64 MiB～1 GiB，未知时 256 MiB）、只接受单个视频文件、只对数字 ID 的 TikTok 视频页地址运行。工具下载的文件由 Core 接收、校验并入库，表示标记为 `…+media-tool`，规格里记 `acquired_by: media_tool`，不承诺原来那条的大小与摘要；工具缺失时按站点的原拒绝报错，什么也不入库。会话 Cookie 只在内存里按“站点/凭证”作用域记，撤销凭证即清除，每个作用域上限 64 个、值上限 4096 字节。
- 工具和运行时的版本、摘要与许可记录在锁定文件里，随本地包携带；手动更新后的版本、摘要与签名核对结果另记在数据目录的工具记录里。对外分发前的许可核对见 [USER-ACTIONS Q-009](../../USER-ACTIONS.md#q-009)。

<a id="credentials"></a>
## 11. 站点登录

- 沿用现有凭证存储：在账号页为某个站点粘贴 Cookie 请求头值，存入系统凭证存储，只用于该站点声明的域名。
- 每个站点提供登录探测（站点“当前用户”接口），区分“已登录”“访客/未登录”“失效”“未知”；登录成功不代表某类列表或某个清晰度可得。
- 探测的判据必须用真实的已登录与未登录页面核对过。2026-10-18 的核对结果：微博分两步。先读桌面端配置接口，`-100` 为访客；已登录时它答 `ok: 1`，但回答里没有用户，不能单独证明登录。再读首页，已登录时首页的 `window.$CONFIG` 写出当前用户（`user.idstr`，与 `uid` 相同）才算已登录；访客的首页被转到 `passport.weibo.com` 的访客登录；其余为未知。两步都和不带 Cookie 的同一请求对照过。分组列表对访客也答 `ok: 1` 并给出分组，移动站是另一个 Cookie 域名，两者都不用（[研究 §13](../research/social-sites-current.md#weibo-recheck-2026-10-18)）。每个判据都要有“不带 Cookie”的对照。Instagram 读页面 `CurrentUserInitialData` 里的 Instagram 账号 ID（`NON_FACEBOOK_USER_ID`，其次 `IG_USER_EIMU`），`USER_ID` 是关联的 Facebook 账号，已登录时也常为 0。
- 签名字段（[DEC-041](../decisions/confirmed-decisions.md#dec-041)）：小红书的列表续页要按网页端的算法签名，签名要用 Cookie 里的设备标识 `a1`。站点注册表为小红书声明这一个字段；Core 只把该凭证里 `a1` 的值随请求上下文交给适配器，`web_session` 等登录 Cookie 与其他字段一律不给，`a1` 不落盘、不进日志与回执。适配器在进程内计算签名请求头，Core 照常附加 Cookie 并检查域名。有了签名，订阅（第一次检查回填完整历史）与作者主页预览都按续页一直取到列表结束，或订阅范围的边界。签名算法改写自开源实现，用固定向量测试；站点拒绝签名（例如 406、461）时按站点拒绝处理并停止，不换着花样重试，历史标为“未取完”。
- Instagram、X 等站点对自动请求有封号风险：设置页提示建议使用不常用的账号，并保持请求节奏与预算。
- 真实测试使用的本机 Cookie 文件与授权范围只在 [USER-ACTIONS](../../USER-ACTIONS.md#act-007) 维护。
- 一次“已登录”的探测结果在 Core 内保留 2 分钟（按站点与凭证代次，撤销或换代即作废）：同一批的多个下载任务和连续预览只问站点一次，获取记录里的验证时间是探测实际发生的时间，不是任务开始的时间。
- 排查站点改版时可以用 `TRACE_ADAPTER_FAULT_LOG=<绝对路径>` 启动后台，Core 与适配器把失败的方法、分类和适配器自己的简短描述（前 480 个字符，可含页面形态，如页面大小、有没有某个状态，不含响应正文与凭证）写成一行 JSON，文件超过 256 KiB 时只留较新的一半；没有这个变量不写任何文件，控制接口和档案仍然只带失败分类。

## 12. 兼容与迁移

- 订阅新增“自动下载视频”字段，已有订阅迁移为开启。
- 新增：规则目录快照、统一元数据列/子表、下载位置与外部副本记录、代理设置；预览结果只在内存与有限期缓存中，不进入档案。
- 插件协议保持 0.x，新增字段可选：旧适配器没有规则声明时，Core 按其已有能力生成 `partial` 规则并标“未声明”。
- 备份包含新增表；从旧备份恢复后新增字段取迁移默认值。
- 迁移中断、旧程序遇到新库、恢复到新目录都有反例测试。
