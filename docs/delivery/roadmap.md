# TRACE 路线与验收

本页回答“先做什么、做到什么程度算基本可用、怎样判定完成”。需求的正本是[需求](../requirements.md)，实际做到哪、验证到什么程度只在[交付状态](status.md)维护；不能从本页的范围或预期判断功能已经通过。

<a id="principles"></a>
## 1. 交付原则

- **先贯通全部基本功能的 MVP，再按反馈 loop 迭代**（DEC-004；用户 2026-11-07 重申）。每项基本能力先做出第 3 节“MVP 必须”的完整流程，再处理“可由 loop 深化”的部分；不等一个功能的全部打磨项清零才推进下一个基本功能。
- **MVP 不放宽底线**：数据正确、凭证隔离、真实状态（风控、限流、未登录、网络、不可得、格式变化、存储失败分别说明）、只删登记过的文件、规则请求的频率上限，都不因 MVP 放宽。
- **以完整可用的流程为交付单位**：一个阶段的计划覆盖整个阶段（[开发流程 §2](../dev-rules/workflow.md#agent-handoff)），按第 3 节列出该阶段要贯通的流程；不以内部测试轮次或单个示例为交接单位。
- 不影响基本使用、没有数据或真实状态风险的问题记为[交付状态的 LOOP](status.md#loop)；产品取舍进 USER-ACTIONS 的 Q 项。MVP 达成、阶段合并、产品验收（人工检查）与对外发布是不同的事实。

<a id="mvp-loop"></a>
## 3. MVP 基线与反馈循环

“全部基本功能”按需求主线解释如下。下表每一行的“MVP 必须”都存在且可验证，才称 MVP 完整；单个功能的演示不等于 MVP 完成。

| 基本能力 | MVP 必须能完成的流程 | 可由后续 loop 深化 |
| --- | --- | --- |
| 登录与凭证 | 扫码与粘贴 Cookie 登录；未登录不发请求；失效时暂停任务、回到登录页、重新登录后回到原处；扫码登录在应用运行时自动续期，失败不丢旧凭证 | 多个登录账号；续期提醒的界面细节（粘贴 Cookie 的登录不续期，DEC-031） |
| 解析与浏览 | 视频、用户、动态、投稿、直播间链接都能打开；滚动加载、风控停在原处可重试；看原图 | 专栏全文、合集与系列、搜索；更多链接类型 |
| 缓存与下载 | 手动缓存动态与视频，最高画质与音质、多 P；断连续传；升级探测与升级；弹幕与字幕随视频保存；任务详情逐文件进度 | 弹幕 ASS 导出、弹幕更新、按条件筛选缓存内容、下载限速 |
| 主页、媒体库与播放 | 信息流（从新到旧、按最后查看时间戳记忆位置、有更新的头像行与单订阅视图、更新提示、无底部文字按钮）、媒体库（筛选含订阅、每格简洁展示与“⋯”菜单、删除只删登记文件）、播放层可开关弹幕、调透明度与密度、选择字幕（DEC-037） | 弹幕屏蔽词、播放列表、画中画、更多播放器快捷键 |
| 订阅 | 新建、改名、删除订阅；关联与解除账号（一个账号只属于一个订阅）；用户页加入订阅；从关注列表导入；订阅页圆形头像网格与订阅详情的更新、已缓存、直播、账号、规则五个标签（DEC-033） | 订阅分组与标签、排序与搜索、批量编辑、订阅导出导入 |
| 检查更新与规则 | 手动检查（第一次检查只建立起点、起点之前的动态不进入更新、风控停止整轮；不做已看标记，DEC-033）；定时检查（退避、每小时额度、每轮上限）；按订阅规则自动缓存（只缓存规则开启后发布的，每轮上限） | 每个订阅单独的检查间隔、关键词与时长等规则条件、通知提醒 |
| 直播 | 开播状态显示；手动开始与停止录制（fMP4 流与 HTTP-FLV 后备）；开播自动录制；断流重连与换段；录像条目可播放、删除 | HLS-TS 后备（LOOP-008）、直播弹幕录制（FR-LIVE-003）、边录边看、录像合并 |
| 后台运行 | 关闭窗口到托盘并释放界面内存，后台继续缓存、定时检查、自动缓存、录制与续期；托盘重新打开、退出确认；单实例 | 开机自动启动、托盘里的更多快捷操作 |
| 安装、数据与打包 | 按用户安装到 `%LOCALAPPDATA%\Programs\trace`（开发版 `trace-dev`），数据在 `%LOCALAPPDATA%\trace`、缓存在“文档\trace”，两个通道隔离；接入旧的缓存文件夹；一条命令打包开发版安装包、只留最新产物；门禁一条命令；开发版打包后本机自动更新，正式版一条命令发布并联网更新 | Windows 代码签名、winget 与 Microsoft Store、测试版通道、差分包体积优化 |
| 抖音（DEC-043） | 粘贴 Cookie 登录、按站点登录互不影响；分享文本与各类链接解析；作品详情（视频、图文、实况、配乐）与用户作品列表；缓存视频（最高档、无水印、单文件 MP4）与图文；订阅关联抖音账号、检查更新（置顶不打断）、自动缓存；开播状态与 FLV 录制（原画优先、断流重连、换段、收尾）；站点小字标记与按站点筛选；抖音与哔哩哔哩的额度、退避与熔断互不影响 | 扫码登录、关注导入、合集与喜欢收藏、直播弹幕、HLS-TS 后备（LOOP-008）、画质升级提醒、评论 |

每个阶段按“A 制定覆盖整个阶段的计划 → B 连续实现与自测 → A 集中复核 → 用户授权后 push/PR/合并”推进；用户的人工检查、反馈与决定记在 USER-ACTIONS，任何时候处理，不阻塞这条流水线，反馈带来的修复进入当时正在进行的阶段。
