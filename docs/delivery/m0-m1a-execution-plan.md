# M0 → M1a 首轮连续实施计划

计划 ID：TRACE-M0-M1A-01；修订 r1；2026-09-26；Agent A。状态：**ready-for-review（计划已形成，可交 B 执行；产品尚未实现）**。这是本轮唯一实施计划；[准备入口](m0-m1a-preparation.md)只作导航，[路线](roadmap-and-acceptance.md)定义里程碑。工作包是依赖顺序与检查位置，不是每包一次审批/交接。

## 1. 要交付的用户结果

Windows 上，用户可创建创作者、关联哔哩哔哩 UP 主、选择新增或有界近期历史范围，在必要时安全配置登录账号，订阅保存普通投稿视频（含必要分 P/音轨），浏览来源与内容、搜索中文、处理可解释失败；关闭界面后后台继续，再打开可重连；能导出与在空目录恢复，停用适配器后仍离线读取已保存档案。

一次执行覆盖 **P0～P9 全部可执行内容 → B 自检修复循环 → 文档及证据同步 → 本地交付提交 → 给用户的 B→A 审查 prompt**。不以 Hello World、骨架、模拟源通过或一条视频下载完成提前交接。A 后续做集中审核、局部修复及整批返工，双方使用[沟通机制](../dev-rules/development-workflow.md#handoff-protocol)。

范围外：抖音生产接入（M1b）、直播/自动质量升级和回收（M1c）、完整账号与历史管理、身份合并拆分和本地导入（按需求映射）、Linux 产品支持、远程/网盘同步、第三方不受信任插件市场、自动发布。为这些能力保留已有身份/代次/版本边界，不建设空实现或显示假可用入口。

## 2. 基点、权限与既有事实

用户要求先建立本地 Git：首提交 `b208ad6` 仅一个空 README；第二提交保存文档、研究、契约与本计划。B 的基点为**包含本文件 r1 的第二提交**，开工自行读取完整 SHA 并记入报告，不因本文件没有自引用 SHA 阻塞。保护两次初始化提交，不把产品代码 amend 到第二提交。

仓库目前无产品代码、Cargo/npm 工程、应用锁文件、CI、打包产物或站点接入。已有可运行命令仅 `python scripts/check_docs.py`。A 在仓库外跑过 Vue 最小兼容试验，见[选型](../research/2026-09-26-technology-stack.md)，该试验不等于产品测试。远端尚未建立，不从本地初始化推导推送/PR/发布授权。

B 默认新建或复用 `feat/m1a-video-archive`，基于上述文档提交，不自动 stash/reset 用户文件。按[Git 规则](../dev-rules/repo-and-environment.md#git-delivery)保存本轮一个可审查交付；同一未推送交付修复归原交付，M0 风险验证证据保存在同批报告，不要求工作包逐次 commit。必要恢复检查点有理由才建。不开子 Agent/新任务，不自动发送跨任务消息；用户使用双方提供的 prompt 转交。

## 6. 必须落实的细节

1. 身份/版本：改昵称不换来源 ID；短摘要不覆盖完整 Revision；统计不制造内容新版；DB 唯一键防重复。历史清单不依赖网站插件解释。
2. 文件提交：逐个 RECEIVING→COMMITTED 边界故障注入。文件与 DB 不是单事务；已有对象先校验再复用；Outbox 重放不重下；未知完整性明确 partial/unknown。
3. 调度：持久化范围/游标/复查/退避与最近成功时间。从现在开始不偷偷回填；预算耗尽安排下一批且显示部分。暂停、取消、停订阅不同；休眠离线不假装正常监测，空间不足不删原件。
4. 登录：来源账号与登录主体分开。安全 Cookie 输入是最小入口；登录有效但质量不足显示能力受限；撤销只影响关联计划，不毁历史。
5. 媒体：cid/分段/音轨组成必要资源集合，无声须有证据；过期重解析、续传校验不足重下；部分成功保留但整稿不误完整；记录平台规格与实际 probe。
6. 界面：主要入口有空/加载/失败/部分/恢复状态与可操作原因；不执行不可信内容；UI 不传任意 shell/SQL/路径；受控播放失败可外部打开。
7. 备份：完成的 SQLite 快照决定对象集合；最后才发布完成清单；元数据备份明示缺媒体；恢复仅空隔离目标，验证 schema/路径/摘要/关系；迁移失败保留原档案及备份。
8. 文档：真实依赖、命令、结构/schema、故障/恢复、实际支持能力与证据写回正本；接口变更同步使用方/固定样例；A 研究不冒充实际安装。

## 9. B 自主处理与升级边界

## 10. 交付、审核与双方 prompt

B 建立 `docs/evidence/m0-m1a-delivery.md`，持续维护本轮唯一交付报告：P/C 覆盖、版本/文件、兼容/恢复、原失败/复验、包/摘要、事项和阶段结论。可从 in-progress 开始，不能预填通过。A 在报告审查部分或同轮 `m0-m1a-review.md` 用 F-001 起记录真实发现，区分缺陷与非阻塞建议；登记文件并更新证据索引。

双方最终回复都必须有 **“交给对方的 prompt”完整可复制文本块**：角色/行动、计划 ID/修订/路径、分支/基点/交付 SHA、报告/证据、F/事项编号、必须保留的修复、验证及交付范围。仅给链接、说“交给 A 审查”或依赖隐藏聊天不算完成。[工作流](../dev-rules/development-workflow.md#handoff-protocol)与[交接模板](../templates/agent-handoff.md)维护通用机制。

A→B 首轮文本在[B 接手入口](m0-m1a-agent-b-prompt.md)。B 完成后生成 B→A 审查 prompt；A 需返工时提供集中 A→B prompt。A 审查通过后，下一轮已规划且授权则给新计划 prompt；尚无下一计划时给“保持已审查基点、等新计划，不扩建”的明确入口，不虚构后续授权或实现。

A 先核对基点/锁/证据真实性，再复核用户流程、提交窗口、凭证/IPC、站点完整性、恢复、原生生命周期和遗漏。明确局部问题直接修复/定向复验，较大问题一批给 B。技术审查、产品验收与发布分开；无具体外部授权不 push、建 PR、合并、发布。
