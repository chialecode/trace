M 表示 Milestone（里程碑）。本文只写三件事：已实现什么、当前阶段要完成什么、以后还要做什么。需求定义与 AC 在[需求正本](../requirements.md)，逐项排期在[需求映射](requirements-map.json)。

<a id="mvp-loop"></a>
## 已实现能力

已实现能力、验证状态与限制只在[交付状态](status.md)维护。概括：抖音与哔哩哔哩两站的动态、图文、专栏/长图文、视频与直播的订阅、下载、录制和离线阅读；视频链接选清晰度下载与直播链接录制；每次获取的认证历史与两条时间线、登录后质量补全的统一确认；质量保留与安全回收；中文搜索与筛选；后台生命周期；导出、备份与恢复；Windows 便携包。2026-10-15 经 PR squash 合并进 main（`c1552e0`）。

<a id="current-stage"></a>
## 当前阶段：M2 多站订阅与下载

唯一计划：[TRACE-M2-01](stage-plan.md)。依据 [DEC-031～034](../decisions/confirmed-decisions.md#dec-031) 与 [DEC-039～041](../decisions/confirmed-decisions.md#dec-039)，设计约束见[多站契约](../design/multi-site-contracts.md)，站点资料见[社交站点研究](../research/social-sites-current.md)。

范围：

1. 行为不变的[代码结构整理](../design/code-structure-refactor.md)与工作区清理（先做）。
2. 订阅规则目录与“支持的网站”页面。
3. 微博、小红书、Instagram、X、YouTube、抖音、TikTok、哔哩哔哩八站的文字、图片、视频及混合内容更新订阅，单链接下载，作者内容先预览再勾选的批量下载，尽可能多的统一元数据。
4. 资源库位置与下载位置、可读命名、每个站点账号单独的“自动下载视频”开关、手动同步与补查。
5. 资源管理器页面、多站账号关联与统一时间线、网络代理设置。
6. 原顺延的管理与插件能力：创作者合并/拆分/重新关联与资料历史、录制与回放关联、本地导入、重复与相似比较、质量筛选、跨平台作品聚合、插件独立安装升级与能力契约（DEC-040）；yt-dlp 手动更新（DEC-039）；小红书完整历史（DEC-041）。

技术退出条件：

- 代码整理完成且行为不变：原有测试与断言全部保留，重命名有映射对账，全部门禁通过。
- 本阶段需求（[需求映射](requirements-map.json)中状态为 `current` 的条目）全部适用行为有生产接线与自动证据，A 集中复核收敛。
- 每条标为“已实现”的规则都有当前生产包的真实验证（按 [USER-ACTIONS ACT-007](../../USER-ACTIONS.md#act-007) 的对象与预算）。目标是八站每站至少“用户发布内容”订阅与单链接两条规则达到“已实现”；站点侧阻断（验证码、封禁、签名无法实现）导致做不到的，规则如实标“部分”或“未实现”并写明原因，由 A 在复核时交用户决定是否接受，不能把未验证的规则写成支持。
- 重构与新功能之后，按原规模与阈值重跑正式资源测量并通过。
- 阶段证据工具已与文档解耦（文档修改不再让包证据过期），阶段聚合通过。

B 自检、A 技术审查、用户产品验收分别判断；人工体验检查不是远端授权的前提。一个阶段一个分支、一个提交、一个 PR；用户明确授权后才 push、创建 PR、合并，main 只经受保护的 PR squash 集成。

## 待实现的后继范围

以下尚未排期，先后由用户决定：

- **远程模式**：VPS 无界面核心、网页管理、同步与远端清理（FR-SYNC），Linux 无界面验证；RSS/Atom 输出作为远程模式的候选功能（DEC-034）。
- **站点能力扩展**：新站点的直播录制、评论与互动数据、Instagram 快拍与精选、X 回复与点赞列表、会员/年龄限制/付费内容，以及更多网站。

非阻塞优化有负责人、可用替代和复测入口才进入状态页的 LOOP；新产品取舍、人工检查与外部授权只在 USER-ACTIONS 维护。发布需另有范围、许可、支持矩阵和授权；技术通过或源码合并不等于公开发行。
