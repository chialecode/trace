## 1. 产品定位

TRACE 是 Windows 桌面应用，以“订阅”（被追踪的人）为入口，用社交网络式的界面浏览并缓存站点内容（DEC-026、DEC-032）。当前只支持哔哩哔哩（DEC-018）：登录后粘贴一个链接，就能看到视频详情，或者某位 UP 主的资料、动态和全部投稿；把关心的人建成订阅、关联他的一个或多个账号，随时检查谁有新动态、谁在直播；可以把一条动态（文字、图片、视频及其弹幕字幕）以最高画质和音质缓存到本机（DEC-024），也可以让订阅按规则自动缓存新动态、开播自动录制（DEC-027）；主页像社交网站的信息流一样汇总所有已缓存的内容（DEC-023），媒体库按图片、视频和直播录像浏览。

原则：

- **必须登录。** 未登录时不发任何解析请求，也没有访客模式（DEC-018）。
- **状态真实。** 风控、限流、未登录、网络失败、内容不存在要分别说明，不显示成空列表或“没有更多”；缓存只有文件完整落盘并通过校验后才标为“已缓存”。
- **凭证隔离。** 登录凭证只在后端使用，加密保存，不进日志、历史记录、缓存文件和界面数据；手动添加的凭证只从输入框单向交给后端一次。
- **克制请求。** 只在用户操作或用户明确开启的规则（定时检查更新、自动缓存、开播自动录制、登录续期）下请求，不预取；规则触发的请求有频率上限，只在应用运行且已登录时进行（NFR-NET-002）。API 请求不自动重试，风控和限流一律停下，规则触发的请求还要退避。媒体文件传输中断时在任务内有限次自动续传（FR-CACHE-005），直播断流时在录制内有限次重连（FR-LIVE-002）。
- **不碰用户的文件。** TRACE 只删除自己登记过的文件；保存位置里用户自己放的文件一律保留。
- **开发者优先与边界清晰。** 全项目采用 Go 语言开发（DEC-032），界面层（`internal/ui`）与服务层（`internal/service`）通过清晰的 Go 接口解耦，让改一处站点规则不牵动界面，也为未来提取远程服务器无头录制模式预留干净边界。

### 2.2 缓存

| 编号 | 需求 | 状态 |
| --- | --- | --- |
| FR-CACHE-001 | 手动缓存：动态条目和投稿条目的“⋯”菜单里有“缓存”，视频详情页有“缓存视频”按钮（DEC-038）。缓存一条动态保存它的正文、发布信息、全部原图，以及其中的视频；转发同时保存原动态。视频按 `bvid` 只存一份，动态和投稿共用 | 已实现 |
| FR-CACHE-002 | 最高画质与音质（DEC-024）：视频默认缓存这次能拿到的最高清晰度（同档内按编码偏好），音频默认缓存能拿到的最高音质（Hi-Res 无损 > 杜比全景声 > 192K > 132K > 64K）；多 P 默认缓存全部分 P。清单记录每个分 P 实际缓存的清晰度、编码、分辨率、帧率和音质，以及缓存时站点列出的全部档位。设置页可以改成设定上限（以后需要时） | 已实现 |
| FR-CACHE-003 | 缓存任务：图标栏“任务”入口（DEC-022）列出每个任务的对象、进度、速度和状态；可以暂停、继续、取消、重试；应用重启后未完成的任务恢复为“已暂停”，用户点继续后从断点续传；每个任务有“详情”，列出出错的分段、节点域名、错误类别与时间（不含签名地址） | 已实现 |
| FR-CACHE-004 | 状态圆点（DEC-024）：动态、投稿、视频详情、主页信息流和媒体库条目上用小圆点表示缓存状态：绿 = 已完整缓存且是能拿到的最高档；黄 = 部分缓存、已暂停或有更高档可升级；红 = 失败、文件缺失或清单损坏；缓存中显示进度圆环；未缓存不显示。圆点带图形符号、悬停说明和无障碍名称，不只靠颜色。重启后保持，删除后同步消失 | 已实现 |
| FR-CACHE-005 | 下载稳定性：媒体文件分段下载；某段提前断开、超时、连接重置或服务器 5xx 时，在任务内自动重试并从断点续传，在主地址和备用地址之间轮换；地址过期时每个分 P 最多重新取一次播放地址；重试用完后任务“已暂停（网络）”并写明原因。遇到风控立即暂停，不重试（[媒体与存储选型 §5](research/2026-11-05-media.md#download)） | 已实现 |
| FR-CACHE-006 | 画质升级提醒（DEC-024）：打开已缓存视频的详情页时（同一视频 24 小时内最多一次），以及在任务页手动“检查画质更新”时，探测当前能拿到的最高档；比已缓存的高时，圆点变黄并提示“可升级到 4K”等，点“升级缓存”只重新下载档位较低的分 P，新文件校验通过后才替换旧文件 | 已实现 |
| FR-CACHE-007 | 自动缓存（DEC-027、DEC-040）：自动缓存是共用“缓存规则”的一项（FR-SUBS-004），规则里选择动态类型（视频、图文、文字、转发，默认视频和图文）；检查更新（手动或定时，FR-SUB-001/002）发现的、在规则开启之后发布的新动态，自动建立普通缓存任务（任务标“自动”，用当前画质与音质设置）。一轮检查最多自动建立 20 个任务，多出的留到下一轮并在订阅里写明；风控、限流、未登录时不建任务。关闭规则不影响已建立的任务 | 已实现 |
| FR-CACHE-008 | 弹幕与字幕（DEC-027）：缓存视频时，每个分 P 同时保存弹幕（缓存那一刻站点给出的全部弹幕，存成通用的 XML 弹幕格式）和全部 CC 字幕（每种语言一份 WebVTT 与 SRT，AI 生成的字幕标明“AI”）。设置可以分别关闭；没有字幕不算缺失；弹幕或字幕取不到时记为缺失项（黄点，可“补全”）。在本功能之前缓存的视频保持原圆点，详情页提供“补存弹幕和字幕” | 已实现 |
| FR-CACHE-009 | 任务详情逐文件进度：任务“详情”列出每个文件（每张图片、每个分 P 的视频流与音频流、弹幕、字幕、合并后的文件）的状态、已下载 / 总大小与速度 | 已实现 |
