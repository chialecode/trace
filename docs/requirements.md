## 1. 产品定义

**TRACE = trace + record + archive + collect + explorer。**

TRACE 是以创作者为中心的个人内容档案应用。用户关联一个创作者在不同社交平台上的账号，持续发现、下载、录制其发布的内容，在统一档案中浏览、查找、对比和维护这些内容的轨迹。

产品的核心价值包括：

1. 跨平台关联同一创作者，保留每个平台上的发布语境与来源。
2. 自动收录授权范围内可获取的内容，保留修改历史与收录状态。
3. 在后台持续检查订阅和录制直播，并明确显示中断与缺失。
4. 统一管理文件、质量、重复关系和存储位置。
5. 让历史档案独立于当前网站、平台插件和网络状态保持可读。

### 1.1 成功标准

- 用户能回答“这个创作者有哪些已关联账号、保存过什么、哪些内容还没有保存好”。
- 重试、重启、插件更新不会造成重复档案或无提示的数据丢失。
- 关闭 GUI 后采集继续，界面占用的 WebView、播放器及媒体资源得到释放。
- 平台插件停用或移除后，已有档案仍可浏览、搜索和导出。
- 每次画质替换、文件回收和远程同步都能解释原因与结果。
- 新平台通过适配器接入；平台特例由明确的能力与扩展字段表达。

### 1.2 产品原则

- 创作者、平台账号、发布记录、内容版本、媒体版本、文件实体分别管理。
- 保留来源信息与时间语境，身份关联可修正。
- “完整”必须声明相对范围与证据，未知状态不能显示为成功。
- 优先保证档案可恢复，再优化速度、空间和界面体验。
- 外部依赖通过可启停、可替换的模块连接。
- 设计出现根本问题时修正模型，同时维护历史档案的迁移、恢复与可读性。
- 前端、组件、数据库访问、媒体、测试等通用能力优先整合经验证的活跃开源方案，各网站下载规则独立处理。
- 先交付基本功能 MVP，再依据反馈持续迭代，数据正确性与恢复要求贯穿每轮。

## 2. 范围与边界

### 2.1 内容范围

| 范围 | 基线 |
|---|---|
| 跟踪对象 | 用户明确添加并关联的平台账号；跨平台身份默认人工确认 |
| 默认内容 | 创作者发布的正文、图片、视频、音频及附件；具备能力的平台支持直播 |
| 历史范围 | 从现在开始、最近一段时间、指定起止时间、尽可能回溯历史 |
| 获取范围 | 当前登录身份有权访问、适配器支持且来源仍可提供的内容 |
| 可选扩展 | 评论、转发详情、他人提及、头像及简介历史、弹幕、字幕、OCR、语音转写 |
| 已消失内容 | 保留已归档版本；没有历史副本的内容记录缺失或不可获取原因 |
| 未知格式 | 保存原始文件及基础元数据，提供下载或使用外部程序打开的入口 |

未开启的扩展不纳入该订阅的完整性计算。评论与转发引用中出现的人，不自动加入创作者订阅。

### 2.2 关键用语的可验收定义

| 用语 | 定义 |
|---|---|
| 全部内容 | 在已关联账号、已选内容类型、历史范围、授权范围与已验证扫描覆盖内的内容集合 |
| 已发现 | 内容身份和基础来源信息已经可靠保存，后续任务可以恢复 |
| 本次内容完整 | 本次已发现版本中，已选且可枚举的必需资源全部保存并通过对应校验；不代表整个网站历史完整 |
| 历史扫描完成 | 适配器报告扫描边界，且范围内已发现内容均有处理结果；若平台无法证明覆盖，显示“已扫描，覆盖未知” |
| 及时发现 | 从来源通过所用接口可观察，到发现结果持久化之间的延迟；实际网站无法提供起点时展示检查周期与最近成功检查时间 |
| 最佳版本 | 在相同内容语义和可比较条件下，由订阅质量偏好选择的版本 |
| 降级收录 | 实际保存质量或资源范围低于期望，已有内容仍可用，同时保留告警和补全任务 |
| 轻量模式 | 没有交互式 GUI 资源，后台保留订阅检查、下载、录制及必要通知 |
| 删除 | 必须明确作用范围：删除缓存、移除本地副本、删除档案、停订阅、删除远端副本各自独立 |

### 2.3 本期边界

本期建设本地单用户档案、后台服务和可插拔平台接入能力。跨操作系统、远程采集、第三方插件分发逐阶段验证。

以下内容不作为本地首版交付要求：公共分享社区、多租户服务、推荐算法、自动推断全网身份、自动转写所有媒体、分布式任务选举、插件商城、对所有站点的通用浏览器抓取。

已实现：抖音、哔哩哔哩两站的内容归档、直播录制、质量与认证历史，以及视频链接选清晰度下载、直播链接至少720P录制（DEC-020/028）。本阶段（DEC-031～034）：把文字、图片、视频及混合内容的更新订阅、单链接与作者内容批量下载扩展到微博、小红书、Instagram、X（Twitter）、YouTube、抖音、TikTok、哔哩哔哩八站，并提供订阅规则目录、支持的网站页面、下载位置、资源管理器页面和多站统一时间线；新站点的直播录制、评论与互动数据不在本阶段。必要登录与凭证保护随首次使用交付。Windows桌面优先，之后Linux无界面，其他桌面系统按需验证。

站点下载、登录和直播获取方案在具体适配器开发时单独调研，不预选现成站点下载器，也不将某个网站的当前接口固化为核心模型。工具支持某站点或能够下载单个视频，不代表满足本项目的完整收录需求。

## 3. 概念与使用场景

### 3.1 参与对象

| 对象 | 说明 |
|---|---|
| 应用用户 | 使用 TRACE 的本地档案所有者；远程首版仍服务同一所有者 |
| 创作者 | TRACE 内的统一身份，可以关联多个平台账号 |
| 来源账号 | 被跟踪的平台账号，以平台稳定 ID 识别 |
| 登录账号 | 用于访问来源内容的凭证主体，可以服务多个订阅 |
| 采集节点 | 执行检查、下载、录制的本地或远程服务 |
| 平台适配器 | 理解特定平台身份、内容、媒体访问方式和认证状态的模块 |

### 3.2 主要流程

**建立档案：** 添加创作者 → 添加平台主页或稳定 ID → 解析并确认账号 → 关联登录账号 → 选择范围、质量与检查策略 → 开始检查和历史回填 → 在时间线查看。

**持续收录：** 后台检查 → 保存发现结果 → 排队获取元数据和媒体 → 校验归档 → 更新搜索与时间线 → 根据需要通知。单项失败不应阻止其他已发现内容归档。

**直播录制：** 检查开播状态 → 创建或恢复直播场次 → 获取当前允许的流 → 按片段保存 → 断线重连或刷新访问凭证 → 结束并记录覆盖范围。

**链接收录：** 粘贴两站视频或直播链接 → 解析真实来源和当前身份可得质量 → 选择清晰度及必要音轨/分段 → 确认下载或开始录制 → 在任务和档案中查看实际保存结果。无需先创建全历史订阅；后续订阅是独立选择。已有档案的升级仍进入统一确认页，不因粘贴链接自动覆盖旧选择。

**凭证失效：** 检测到能力变化 → 标记受影响任务与订阅 → 发出可操作告警 → 按订阅策略临时保存或等待 → 用户重新登录 → 再验证 → 恢复并补全。

**已有文件整理：** 选择目录或文件 → 选择托管复制或原地索引 → 提取媒体信息及哈希 → 查看重复候选 → 关联创作者与来源 → 在资源库管理。

**远程接力：** 发布订阅配置 → 指定节点采集 → 上传文件与清单 → 本地接收并校验 → 确认保存 → 按策略保留或清理远端副本。

## 4. 功能需求

“状态”列只有三种：**已实现**（现在的产品已有，验证状态与限制见[交付状态](delivery/status.md)）、**本阶段**（当前[唯一计划](delivery/stage-plan.md)要完成）、**待实现**（以后再排）。排期以[需求映射](delivery/requirements-map.json)为准；当前必须行为与自动证据按唯一计划整体收敛，真实站点与人工验收分别记录。

### 4.1 创作者与账号关系

| 编号 | 状态 | 需求 | 验收要点 |

| FR-ID-003 | 已实现 | 支持创作者合并、拆分及账号重新关联，保留操作记录 | 发布来源 ID 与文件身份保持不变；可检查并修正关联结果 |

| FR-ID-005 | 已实现 | 保存账号基本资料的已观察历史，并支持待确认身份关联 | 相似昵称仅作为候选；合并必须由用户明确操作 |
| FR-ID-006 | 本阶段 | 在创作者页粘贴八站中任一站点的主页或用户链接即可识别站点与稳定 ID 并关联；同一创作者可关联多站、同站多个账号 | 识别结果先预览再确认；同一来源账号不能重复关联；关联、移除不移动或丢失已存内容 |

默认一个来源账号关联一个创作者。共同创作、账号换人等情形通过显式关系或人工归属修正处理，不能因当前昵称自动改写历史作者事实。

<a id="fr-subscription"></a>
### 4.2 内容订阅与历史扫描

| 编号 | 状态 | 需求 | 验收要点 |
|---|---|---|---|
| FR-SUB-001 | 已实现 | 为来源账号配置内容类型、时间范围、质量、登录身份和检查策略 | 配置可保存、暂停、恢复；有效配置可查看 |
| FR-SUB-002 | 已实现 | 增量检查与历史回填独立推进 | 回填不能长期占用直播与更新检查额度；重启后能恢复进度 |
| FR-SUB-003 | 已实现 | 保存来源 ID、扫描游标、发现结果及持久化任务 | 重复页面、重复通知、重试不会重复创建同一逻辑归档工作 |
| FR-SUB-004 | 已实现 | 重扫近期窗口并支持周期补查，识别已存在内容的编辑 | 旧帖编辑、延迟出现、置顶和乱序发布均有验证场景 |
| FR-SUB-005 | 已实现 | 每项内容展示发现、资源保存、质量达标和访问状态 | 下载部分成功不能把整条内容标成完整；失败保留原因与操作入口 |
| FR-SUB-006 | 已实现 | 内容删除或变为不可见时保留已归档版本及来源状态历史 | 超时、限流、登录失败不得直接判断为来源删除 |
| FR-SUB-007 | 本阶段 | 支持手动补查单条内容、指定时间段和失败项目 | 补查复用去重规则；订阅游标不因局部补查错误前移 |
| FR-SUB-008 | 本阶段 | 每个创作者的每个站点账号订阅单独配置“自动下载视频”：开启时更新中发现的视频自动下载当前身份可得的最高清晰度；关闭时视频只保存封面/缩略图、标题、简介与元数据。正文和图片照常保存 | 开关只影响之后的发现与显式同步，不删除已下载视频；关闭状态下视频条目显示“未下载”而不是缺失或失败；已有订阅升级后保持原自动下载行为 |
| FR-SUB-009 | 本阶段 | 手动同步：在未下载视频的条目中勾选一部分（可跨账号、按筛选结果批量），下载到资源库 | 同步使用订阅的质量偏好（默认最高清晰度）；重复勾选不重复下载；部分失败逐条可见可重试 |

订阅配置变更只影响后续执行和显式补全操作。缩小历史范围、停止订阅或取消某内容类型，不自动删除已有档案。

### 4.3 直播订阅与录制

| 编号 | 状态 | 需求 | 验收要点 |
|---|---|---|---|
| FR-LIVE-001 | 已实现 | 独立开启直播检测，支持开播自动录制与手动开始、停止 | 同一节点不重复录制同一已识别场次；停止理由可查看 |
| FR-LIVE-002 | 已实现 | 记录直播场次、开始结束时间、实际录制区间和媒体规格 | 检测到的开播时间与实际开始保存时间分别展示 |
| FR-LIVE-003 | 已实现 | 分片保存，支持断线重连、访问地址刷新和进程恢复 | 已封口片段可独立恢复；未封口片段标记为待修复或损坏 |
| FR-LIVE-004 | 已实现 | 显示录制缺口、质量变化、异常中断及恢复结果 | 重连不能掩盖未录到的时间；低清片段的独有覆盖不能被误删 |
| FR-LIVE-005 | 已实现 | 处理磁盘不足、凭证失效、插件停用和完全退出 | 安全封口已有片段；保留可恢复状态；清楚说明终止原因 |
| FR-LIVE-006 | 已实现 | 将录制与随后出现的回放关联，按覆盖及质量策略整理 | 回放剪辑或缺少区间时保留录制中的独有内容 |
| FR-LIVE-007 | 已实现 | 按录制分片保留获取时登录状态、实际分辨率/码率及质量变化，在场次和资源详情展示 | 登录前后分片不相互重标；未知规格不填成原画；历史直播不进入登录后重新获取或覆盖队列 |
| FR-LIVE-008 | 已实现 | 输入两站真实直播链接即可识别房间、查看可得流并录制至少720P视频 | 实测短边至少720像素；原画/清晰度标签不替代宽高、帧率、码率和音轨。来源不足或中途降级明确显示，不能静默当达标；同场、后台、封片、缺口、重开及导出沿用既有契约 |

录制范围、字幕、弹幕和其他附加流由能力声明与用户选择决定。平台无法恢复的历史直播缺口保持可见，不承诺事后补齐。

### 4.4 登录账号、凭证与告警

| 编号 | 状态 | 需求 | 验收要点 |
|---|---|---|---|
| FR-AUTH-001 | 已实现 | 管理多个登录账号，通过适配器支持的登录或浏览器辅助方式获取凭证 | 登录账号与来源账号分开显示；不假定任意浏览器会话均可导入 |
| FR-AUTH-002 | 已实现 | 对登录账号记录能力检查结果、时间和失效原因 | 登录有效、原画访问、会员访问、直播访问分别判断 |
| FR-AUTH-003 | 已实现 | GUI 关闭时仍能发现凭证问题并通知 | 同一持续故障合并告警，告警能定位受影响订阅和任务 |
| FR-AUTH-004 | 已实现 | 支持“先保存并待升级”和“只接受达标版本”两种策略 | 保存期望与实际质量；严格策略导致的未收录区间明确可见 |
| FR-AUTH-005 | 已实现 | 凭证更新后重新验证、恢复等待任务、安排质量补全 | 暂时失败有退避；不持续触发登录或重复下载同一版本 |
| FR-AUTH-006 | 已实现 | 凭证与普通档案、日志、导出、同步数据隔离 | 常规诊断和备份不包含明文凭证；删除登录账号可解除后续使用 |
| FR-AUTH-007 | 已实现 | 为每次获取保存不可变认证观察，按登录/未登录查看独立时间线并保留未知与失效标识 | 同一内容身份及共享文件不复制；筛选、分页、统计和资源详情一致，当前登录/退出不改写旧资源标签 |

默认启用“先保存当前允许取得的内容并告警”，低于目标的内容标记为待升级。账号失效只在有证据时确认；网络故障和未知能力状态分别展示。


<a id="fr-archive"></a>
### 4.5 统一归档与本地资源

| 编号 | 状态 | 需求 | 验收要点 |
|---|---|---|---|
| FR-ARC-001 | 已实现 | 统一保存正文、图片、视频、音频、附件和来源元数据 | 同类文件采用同一管理流程，存储位置不依赖网站或创作者名称 |

<a id="nonfunctional"></a>
## 5. 非功能需求与工程目标

### 5.1 可靠性、安全与可维护性

| 编号 | 要求 | 验收依据 |
|---|---|---|
| NFR-REL-001 | 执行允许重试，发现、归档和同步提交必须幂等 | 在关键边界注入进程终止、重复消息和超时，验证唯一身份与引用 |
| NFR-REL-002 | 文件系统与数据库不一致时必须能恢复或显式标记异常 | 不依赖跨文件和数据库的虚构单一事务；逐个恢复窗口验证 |
| NFR-REL-003 | 保留已观察到的来源事实和操作原因 | 未知、暂时失败、来源删除分别表达；重要状态变更可追踪 |
| NFR-PERF-001 | GUI 关闭后释放本应用的交互式 WebView 与媒体资源 | 对比进程、内存与资源对象，排除其他应用的共享运行时 |
| NFR-PERF-002 | 后台资源与活动任务数量相关，缓存和并发有上限 | 长期运行、突发更新和大批回填均有固定工作负载测试 |
| NFR-PERF-003 | 搜索与时间线分页，扫描、校验和预览按需执行 | 十万级发布记录下验证首屏；不一次把全部档案放入内存 |
| NFR-SEC-001 | 凭证使用系统级安全存储或经验证的加密存储边界 | 日志、错误、导出、同步、崩溃诊断均用敏感样本检查 |
| NFR-SEC-002 | 归档内容按不可信输入处理，插件只获得所需能力 | HTML、路径穿越、异常协议消息和越权资源访问有测试用例 |
| NFR-SEC-003 | 远程控制接口和本机服务接口验证调用方 | 不允许网页任意控制本地后台；远端身份与档案权限绑定 |
| NFR-COMPAT-001 | 无 GUI 核心保持可移植；实际支持矩阵逐阶段验证 | 已确认 Windows 桌面优先，工程基线暂用 Windows 11 x64；Linux 无界面能力在远程模式之前验证，其他桌面系统按需验证 |
| NFR-DATA-001 | 档案格式、核心 API、插件协议、配置格式分别版本化 | 不兼容输入明确失败；迁移和恢复路径可重现 |
| NFR-OBS-001 | 暴露最近成功检查、队列、重试、限流、磁盘和录制状态 | 故障可关联到节点、插件、账号、任务与内容，并清除敏感信息 |
| NFR-TEST-001 | 关键规则通过模拟适配器和故障注入验证 | 测试可以不依赖实时网站；实际适配器另有受控集成验证 |

### 5.2 初始性能目标

以下为待测的工程目标，不能作为已达到的性能承诺。基线建立后如需调整，应记录工作负载、原因和新目标。

统一基线：Windows 11 x64、至少 4 核 8 线程 CPU、16 GiB 内存、SSD；本地十万条发布记录，正文中位长度约 500 字符，五十万条媒体元数据。模拟两种平台适配器，网络响应延迟固定为 100 ms。CPU 指全部 TRACE 相关进程占整机可用 CPU 时间的比例，内存使用私有工作集之和。

| 场景 | 工作负载 | 初始目标 |
|---|---|---|
| 空闲订阅后台 | 100 个普通检查目标，周期 300 秒；20 个直播检查目标，周期 30 秒；无新增媒体；含适配器和必要通知壳 | 预热 2 分钟后采样 15 分钟；平均 CPU ≤ 1%，内存 P95 ≤ 150 MiB |
| GUI 转轻量模式 | 保持相同订阅工作负载 | 10 秒内关闭本应用交互式 WebView、播放器和登录辅助窗口；后台任务连续 |
| 搜索首屏 | 每页 50 条，覆盖中文一字、二字、长词和组合筛选 | 热缓存 P95 ≤ 500 ms，冷启动查询 P95 ≤ 1500 ms；不含原图和视频加载 |
| 资源管理器 | 同一十万条记录；资源库首屏（最新在前）、末页（名称倒序、作者倒序、发布时间正序）和站点文件夹，每页 100 条；按大小排序要汇总每条已存字节，不在此目标内 | 热缓存 P95 ≤ 500 ms，冷启动查询 P95 ≤ 1500 ms；不含原图和视频加载 |
| 多路录制 | 4 路、每路约 8 Mbit/s 的兼容流拷贝录制，无预览转码 | 稳定阶段平均 CPU ≤ 5%，内存 P95 ≤ 300 MiB；没有由队列设计造成的丢片 |
| 更新检测 | 模拟来源可观察时间已知，调度未被限流或暂停 | 配置周期为 T 时，持久化发现延迟 P95 ≤ 1.2T + 10 秒 |
| 开始录制 | 已确认直播，流可访问且有资源预算 | 从确认直播到开始写入 P95 ≤ 10 秒 |
| 异常重启 | 100 个未结束普通任务，已有大文件与分片 | 30 秒内恢复服务可访问并开始恢复扫描；大文件校验不阻塞其他任务 |

真实站点的额外请求、限流、验证挑战、来源延迟、设备休眠和网络不可用会影响检测目标。界面必须展示实际检查周期、受限原因与最近成功时间，不能维持虚假的“正常实时监测”状态。

## 6. 默认策略提案

| 项目 | 初始默认 | 可调整边界 |
|---|---|---|
| 新订阅范围 | 从现在开始，用户可选择历史回填 | 保存范围变化不删除已有档案 |

| 直播检查 | 30 秒周期，加入抖动 | 来源支持的推送可优先使用；受限时显示有效周期 |
| 近期复查 | 最近 7 天；另安排周期性深度补查 | 具体策略由来源分页与历史能力验证，不保证覆盖全部旧编辑 |

| 关闭主窗口 | 继续后台运行，首次操作清楚说明结果 | 完全退出为独立动作 |
| 平台停用 | 停止新调度，下载到可恢复边界暂停，录制封口 | 强制终止需呈现恢复状态；不删档案 |
| 原件保留 | 持续保留；可比较低质量副本按替换策略回收 | 不根据来源删除、停订阅或磁盘压力自动删原件 |

| 手动删除档案 | 进入等待回收，建议 7 天后物理清理 | 记录删除版本；立即清理仍遵守共享引用与副本保护 |
| 磁盘安全余量 | 至少 1 GiB，且不低于所有录制约 60 秒的估算写入量 | 同时预留下载与质量替换峰值空间；估算策略需实测验证 |
| 凭证检查 | 使用时验证、根据可用信息安排低频探测 | 不依赖单一到期时间，不常驻完整浏览器 |
| 远程执行 | 每订阅一个明确采集节点和一个配置权威 | 切换需要交接或明确强制接管，分区时不自动双写 |

## 7. 信息架构与交互要求

| 入口 | 核心内容 |
|---|---|
| 创作者 | 平台账号、时间线、筛选、资料、订阅与档案健康 |
| 资源库 | 文件类型、规格、来源、重复关系、保存状态及批量管理 |
| 任务 | 检查、回填、下载、录制、校验、补全及可操作失败 |
| 账号 | 登录身份、能力状态、受影响订阅、重新登录入口 |
| 模块 | 已安装能力、启停状态、协议兼容、健康和更新 |
| 存储 | 使用量、缓存、目录、离线位置、备份、回收与修复 |
| 链接收录/录制 | 八站作品/帖子链接与两站直播地址、作者主页的预览与勾选、当前登录身份、实际可得清晰度、下载位置、明确下载/录制动作、任务进度及保存结果；入口复用现有导航风格 |
| 资源管理器 | 资源库与下载目录的文件夹树和文件列表，列排序、筛选、预览、打开、定位与同步入库 |
| 支持的网站 | 由订阅规则目录生成：支持的网站、每站可订阅内容、所需条件、状态与最近验证日期 |
| 设置 | 文字大小、资源库位置、默认下载位置、下载文件命名、网络代理、各站点登录 |
| 节点（远程模式，待实现） | 执行分配、配置版本、同步、保存确认与连接状态 |

界面应同时保留“内容是否已保存”和“后台任务是否结束”的区别。任务成功只说明该任务完成，不代表创作者历史完整。

本阶段新增的桌面交互要求（[DEC-042](decisions/confirmed-decisions.md#dec-042)）：标题栏融入应用蓝白外壳，保留真实的拖动、最小化、最大化/还原、关闭和调整窗口大小；关闭仍只关闭 GUI，不终止后台。设置提供 100%、110%、125%、150% 四档文字大小，默认 100%，即时应用并在重开后保留。字号改变时导航、表单、按钮、卡片、详情和弹窗随内容重排，不裁切文字、不隐藏关键操作；表格可在自身区域横向滚动，不让整个页面横向溢出。此设置与 Windows 系统缩放独立，不以放大后裁切的固定画布代替响应式布局。

删除、身份合并、目录迁移、强制终止等操作需要显示真实影响范围。普通查看、重试、检查、暂停不应增加不必要的确认步骤。

<a id="authentication-acquisition"></a>
### 登录状态与获取历史（DEC-024/025）

认证观察属于某次获取及资源引用，而不是共享 blob、创作者或当前账号状态；同字节也能有不同获取历史。时间线按实际保存的认证观察筛选，认证未知单独可见，不能猜为已登录。验证登录后只安排普通资源补全；直播保留当时状态，不承诺重取。详细字段、确认事务、迁移和失败语义以[归档契约](site-archive-contracts.md#authentication-acquisition)为准。

本地测试凭证不属于普通档案功能：安全准备入口和缺输入停止规则见[数据与安全](dev-rules/data-and-security.md#local-site-credentials)，用户实际配置及授权只在 [ACT-002](../USER-ACTIONS.md#act-002) 维护。

## 9. 交付阶段

实施顺序与阶段门槛统一维护于[路线与验收](delivery/roadmap-and-acceptance.md)，FR/NFR 的逐项分批见[需求映射](delivery/requirements-map.json)，不在本文复制第二套路标。

已实现能力见[交付状态](delivery/status.md)；本阶段为八站更新订阅与下载（见第 2.3 节）；待实现包括远程模式、管理与插件演进等，顺序见路线。每轮由 A 计划与最终集中审查、B 连续实现与自检，A 通过后直接向用户收尾，见[开发工作流](dev-rules/development-workflow.md)。

平台差异与未知必须明确，抖音长文不能只保存简介。局部通过不代替本阶段完整门禁；真实账号请求仍按具体授权。

### 9.1 实施时需要确认或验证的事项

开发及上游事项唯一入口为[集中总表](decisions/open-questions.md)，用户规模、许可、真实站点与实机检查只在[USER-ACTIONS](../USER-ACTIONS.md)维护。蓝白视觉方向已确认。已确认方向见[有效决定](decisions/confirmed-decisions.md)，不重复待批。更远期问题在对应阶段进入计划时登记，不提前阻塞本地开发。

## 抖音与哔哩哔哩的完整内容要求（DEC-020，已实现）

两站覆盖Bilibili/抖音空间与创作者动态、图文、专栏/长图文、视频、直播的订阅、下载、录制和离线读取。类型差异按证据表达；抖音长图文不能按普通视频简介处理。API提供的安全元数据应尽可能保留，包括原生身份/来源、作者、全文/结构、顺序附件、音轨/字幕/章节、计数观察、配乐与合集、录制场次/片段/缺口和质量证据。细化定义见[归档契约](site-archive-contracts.md)，来源与未证实范围见[解析资料](research/site-parsing-current.md)。该增量细化FR-ARC、FR-SUB、FR-LIVE、FR-BROWSE、FR-PLUGIN等既有要求，不使历史子集测试自动覆盖新增类型。
